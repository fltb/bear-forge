# 通用卡牌设计与训练系统

**当前边界：以玩家决策为环境步，只在支持的决策等待边界保存与分叉。优先复用现成执行器，具体后端尚未确定。** 见 [当前执行与实验契约](spec/runtime-contract.md)。不再要求任意指令级可恢复抢占，也不默认选择 JS-Interpreter。

把卡牌游戏定义为可执行程序，在完整可分叉的演算机上运行脚本、搜索器和学习策略，再用带证据的关系图分析构筑、卡牌和策略生态。项目当前处于实施规划阶段，尚未实现演算机、策略服务或训练器。

## 已确定的设计

- TS＋toolkit 为作者方向，语法与依赖白名单由所选后端的能力明确约束；不默认自研控制流编译器。
- 游戏的一步是一个完整决策动作到下一真实决策或终局；规则内部调用与模型参数 token 不是环境步。
- 支持的决策边界快照必须保存完整后续执行现场，后端可以管理续延；宿主隐藏状态不可遗漏。
- 分叉要求隔离、恢复不依赖完整历史重放；结构共享/COW 是优化选项，不是首版硬条件。
- ExperimentInstance 调度多局独立 GameInstance；代码/冻结权重可共享，游戏状态与各参与者记忆隔离。
- 内核是执行器与记录 toolkit，没有生命值、回合、胜负等语义。游戏自行实现主循环和结算循环，并提供游戏运行、训练与分析三份契约。
- 真人前端与训练共用规则与动作协议。时间是显式输入，实战使用真实时钟、训练使用明确配置的虚拟时钟；动画完全由前端处理，不推动或阻塞规则。
- 上层可以提供模板与组合库，但必须保留完整计算与交互表达能力；特殊规则不靠不断增加配置开关实现。
- 模型默认使用成熟实现的标准因果 Transformer。动作允许自回归表示，不预设自研混合网络。
- 当前先用编程 Agent 在局外生成脚本种群，建立设计评估闭环；Transformer 后续接入同一环境。已有 4070、本地优先，增量预算上限 $500，包含策略生成调用与计算开销。
- 策略独立于规则与 core；玩家搜索通过 PlanningService 与游戏 PlanningAdapter 建立假设世界，复用同一规则和执行器。全状态设计干预采用独立权限。
- 模型学玩家策略；构筑探索、对手调度、独立评测与关系分析是独立模块。
- 输出是有上下文、证据和未知区域的关系图，不是单一“卡牌强度分”。

## 下一步工作

从 [当前执行与实验契约](spec/runtime-contract.md) 出发，选择支持决策点快照的现成后端并实现薄适配，贯通起步策略与批量对局；旧九节点机器不作为交付前置。

完成顺序是：可验证演算机 → 游戏规则包 → 脚本种群、干预与初版关系图 → 受限搜索及小模型扩展。训练设计保留，但训练不是关系图的前置条件；规则正确性与设计评价分别验收。详见实施计划的依赖分支。

## 规划与实现的边界

本文档中已确定的设计来自当前讨论；标记为“默认提案”的细节是可执行的起点，不代表已验证。当前目录包含规格与模型层面的人工证明，没有声称完成机械化证明、引擎实现、游戏复刻、性能测试或模型训练。

不在本阶段引入新的 DSL 语法解析器、任意 TS 编译器、专用 Transformer 架构、视觉客户端控制或独立世界模型。网络规模、部署硬件和性能阈值在确定预算后落定，不编造耗时承诺。
