# 实施计划

实施量与复用优先级见 [全系统评估](system-reuse.md)：先固定脚本的设计分析闭环，训练/规划/自动演化为独立增量。下文旧自研编译器任务不作为交付前置。

最新计划以 [当前契约](../spec/runtime-contract.md) 为准。R101 改为按决策点快照选择并固定现成后端；R102 为该后端的 TS/SDK profile；R103–R105 交付桥接、决策点恢复分叉和成本记录。不要求任意指令级可恢复抢占。增加实验实例调度多局与冻结策略版本的联调；具体后端未定。

按验收门槛推进，不凭“能跑起来”跨越语义、规则或训练验证。每项工作留下程序、测试或实验记录；本清单中的工作目前均未完成。

## 里程碑与依赖

| 阶段 | 依赖 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| P0 核心规格 | 无 | 演算语义、context、证明结构、构造器契约 | 所有运行期状态与转移显式，关键语义无悬空约定 |
| P1 作者工具与运行时 | P0 | SDK、受控编译、强制检查、参考执行器、直接分叉 | 自然 TS 规则贯通，编译结果与参考语义一致，无隐藏续延 |
| P2 规则贯通 | P1 | 完整小型扑克、跨机制规则案例 | 独立预期/参考实现对照，观察隔离与分叉一致 |
| P2S 策略与模拟服务 | P2 中至少一个合格游戏包 | 脚本协议、种群候选、受限模拟适配 | 信息权限隔离、行为可复现、资源可计量；未支持搜索明确报告 |
| P3 训练闭环（增量分支） | P2S 的决策/轨迹接口 | 小 Transformer、采样与评测管线 | 已知答案环境校准，固定基准评测，样本来源可追溯 |
| P4 生态与干预 | P2S；不要求 P3 | 脚本/混合策略种群、构筑探索、实验协议 | 交叉评测与三类适应实验可复现，无不公平预算比较 |
| P5 关系图 | P4 | 有证据的图、覆盖状态、回放定位 | 任意边可追溯，冷区与已排除区分，循环不被强排成总榜 |

P0 同时固定训练与实验数据契约，避免直到 P3 才发现轨迹缺少必要信息。硬件、模型规模和吞吐阈值按可用预算设置；不在预算未知时承诺工期或性能。

当前硬件与费用约束已明确：已有 4070、本地优先、增量 $500 上限，包含 Agent 策略生成与运行开销。P2S → P4 → P5 的脚本评估路径先行，P3 后续接入。规划模拟是可选策略能力，其游戏适配未完成不阻塞无搜索脚本闭环；多游戏范围按预算分批交付，不暗示 $500 包含引擎开发人工。总架构与目录命名以 [架构文档](architecture.md) 为准。

## P0 固定核心语义与程序契约

已有 [执行规格 v0.1](../spec/execution.md) 与 [人工构造性证明](../spec/proofs.md)，按后续讨论统一为 TS + toolkit。九种节点及 context 转移已列出；原子准入、校验器与实现映射仍需落实，因此工作包不直接标成已完成。

- [ ] T001 将九种节点、值/schema、流程定义和原子注册契约落实为可校验的数据接口。
- [ ] T002 定义严格求值顺序、单步转移、尾调用处理和错误状态。
- [ ] T003 落实 Await/恢复、响应路由、重复输入与取消契约；第一版不引入深/浅 handler。
- [ ] T004 定义存储、对象身份、context 完整性、快照版本与分叉隔离。
- [ ] T005 审核现有模型证明，将确定性、暂停、分叉与构造性完备论证映射到实现检查。
- [ ] T006 固定 TS 构造期与 DSL 运行期边界，以及符号作用域检查。
- [ ] T007 按 [训练与分析接口](../spec/ports.md) 落实决策包、动作协议、玩家收益区间、事实和关系证据契约。
- [ ] T008 按 [分层契约](../spec/layers.md) 固定核心扩展清单、程序定义表和包校验规则，并将拒绝条件落实为校验用例。

默认提案：单线程确定性机器；数学语义采用无界有限数据，实际执行受资源预算限制；无隐式时钟和宿主随机。数值溢出、浮点/精确数值与集合遍历规则必须在这一阶段明确，不留给宿主偶然决定。

执行/效果/context 已合并在 `spec/execution.md`，模型证明在 `spec/proofs.md`；训练记录协议另行落实。形式证明不能用“我们用的是函数式语言”替代；若仍是证明草案，应明确状态。

## P1 受控编译、参考机器与开发体验

实现路线见 [作者与编译方案](../spec/authoring.md)。原来的显式构造器保留为内部工具，不要求作者手写 Bind。

- [ ] T101 建立 TS 项目、defineRule/状态/请求 SDK 类型与作者样例；内部构造器返回不透明句柄。
- [ ] T102 实现符号绑定、作用域、类型、函数与操作引用的程序校验。
- [ ] T103 实现九种节点、显式控制循环、闭包环境、Bind 帧及注册计算边界。
- [ ] T104 实现 context 直接分叉、分支隔离和快照恢复；不得从头重建。
- [ ] T105 实现执行预算、错误定位和分支资源释放。
- [ ] T106 保存节点定义位置、函数名称、调用链和状态差异。
- [ ] T107 建立源码准入与产物校验反例，包括隐藏状态、未识别 await、数据逃逸和非法闭包。
- [ ] T108 用 TS Compiler API 构建规则调用图、CFG 与跨暂停点变量分析。
- [ ] T109 生成显式帧、调用与恢复代码，覆盖分支、循环、规则递归；附源码映射。
- [ ] T110 实现 typed ESLint 插件与构建强制校验共享的诊断规则。
- [ ] T111 将受控源码的参考执行、IR 执行器和生成后端做行为对照，补充编译保持性论证。
- [ ] T112 落实 [公共会话契约](../spec/session.md)：人类/模型共用动作、真实/虚拟时间、动画与规则独立，并验证回放与超时边界。

验收至少覆盖：递归与闭包、嵌套流程、选择后继续循环、处理中再次选择、分叉后修改捕获引用所指存储、程序版本不匹配、预算暂停后恢复，以及执行追踪不改变结果。记录分叉时间和内存增量用于工程优化，但不以重做已有技术可行性实验阻塞实现。

## P2 多游戏规则验证

第一组是完整小型游戏；后两组是明确列出的真实机制子集，不能声称已经复刻整个商业游戏。实施前按 [复杂用例审查](stress-cases.md) 核对 SDK 时机、延迟任务、事件批次、对象身份和玩家投影；这些用例目前只完成架构推演。

| 包 | 范围 | 关键验收 |
| --- | --- | --- |
| Kuhn Poker | 完整发牌、下注、观察和收益 | 穷举历史，对照 OpenSpiel 的合法动作、信息与收益 |
| 万智牌子集 | 优先权、堆叠、目标失效、区域身份、替换、触发、持续效果案例 | 固定规则版本，逐决策边界与裁定案例/Forge 对照 |
| 杀戮尖塔子集 | 固定角色和内容集合的战斗、抽弃牌、状态、选牌成长 | 固定客户端与内容版本，对照可获取的状态和结算证据 |

- [ ] T201 为每个包先写规则范围、来源、缺失项和独立预期。
- [ ] T202 完成 Kuhn Poker 端到端接口和穷举检查。
- [ ] T203 将万智牌困难交互实现为 DSL 程序；发现公共内核缺口时登记，而非添加游戏特例。
- [ ] T204 实现杀戮尖塔式跨战斗成长闭环，并明确哪些是原创缩小环境、哪些已与真实规则对照。
- [ ] T205 为每个游戏建立信息隔离、参考分歧与最小反例归档。

斗地主、三国杀、小丑牌、花火作为下一批兼容目标，分别检查组合动作、嵌套技能、多阶段计分和合作信息。新增包主要修改游戏与适配层；是否需要修改内核应成为架构审查项。

## 实施纪律

- 每次工作围绕一个编号交付，并记录完成证据；不将规划勾选为实现。
- 不使用进程分叉或从头重放管理游戏分支；允许显式标记规则区域的受控编译，不以它声称支持任意 TS。
- 不以增加 DSL 游戏原语替代游戏库编程，不以配置开关替代完整的流程组合能力。
- 不要求先做全量万智牌才能验证闭环；完整表现力证明与实际规则覆盖是两件事。
- 模型胜率上升不能豁免规则检查；图谱饱满不能证明探索完备。
