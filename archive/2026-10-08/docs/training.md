# 训练与实验

训练对象是在规定规则、信息约束、初始局面、对手分布和预算下的玩家策略。关系图是独立实验的测量产物，不是网络直接输出的“设计分”。

具体集成协议见 [训练与分析接口](../spec/ports.md)：统一 start/advance/submit，保留每游戏的观察、动作、收益与领域分析契约。

## 模型与决策

当前实施顺序是脚本种群先建立评估闭环，再接小模型，详见 [策略层](../spec/policies.md)。Agent 在局外生成脚本，其调用费用也计入预算。脚本、搜索器、模型共享环境与决策协议；以下 Transformer 设计适用于采用学习策略时，不要求所有探索都先训练模型。

默认基底为标准因果 Transformer，先每游戏独立权重，共用结构和训练管线。输入是玩家可见历史、当前观察和决策请求；输出是受规则约束的动作序列。

动作内部可自回归生成操作、对象、目标、数量等参数。只有规则允许一次提交牌列时，连续出牌才是一个宏动作。若出牌后会获得新信息或产生响应，则提交当前动作、执行环境、再决策。参数 token 不自动获得独立奖励，也不自动消耗游戏时间。

固定观察历史下，一个完整动作的行为对数概率等于其条件 token 概率对数之和，合法掩码/前缀约束也必须可复现。搜索策略替换模型采样时，必须记录实际行为来源，不能继续假称动作来自原策略。

## 三种记录

| 记录 | 内容 | 可见范围 |
| --- | --- | --- |
| 执行记录 | 节点、调用、效果、状态变化 | 调试与审计 |
| 决策记录 | 玩家观察、合法空间、动作、行为策略、收益区间 | 按玩家投影 |
| 实验记录 | 游戏版本、分支来源、对手、预算、协议、结果 | 研究与图谱 |

同一玩家的相邻决策之间可能经过多个对手动作。训练连接时保留全部可见更新，正确归集奖励。终局、预算截断、规则错误分别编码；环境失败不得默认为负奖励。

```typescript
type DecisionRecord = {
  episode: EpisodeId;
  player: PlayerId;
  request: RequestId;
  observation: ObservationRef;
  visibleHistory: HistoryRef;
  legalSpace: ActionSpaceRef;
  action: Action;
  behaviorPolicy: PolicyVersion; // 脚本、搜索配置或模型检查点
  behaviorLogProb?: number;
  source: "policy" | "search" | "script" | "human";
  nextPlayerDecision?: DecisionId;
  rewardSpan: RewardSpan;
  ending: "continue" | "terminal" | "truncated" | "fault";
};
```

分叉形成证据树；一次经历仍是一条路径。不同分支不能拼接为真实轨迹，后验挑选高收益分支不能当作无偏在线样本。环境 context 与模型记忆分别隔离；换模型版本后，需要用可见历史重建该模型的记忆，不能跨版本复用不兼容缓存。

## 训练任务的含义

- 固定构筑训练：学习给定牌组怎样打。
- 在构筑分布中训练：学习多种牌组怎样打，不自动等于会发现新构筑。
- 构筑搜索与打法联合适应：探索有效的牌组和打法组合。
- 对手混合下训练：得到针对该分布的策略，不等于全局最优。

构筑探索器提出候选，玩家学习器负责适应，实验调度器负责减少关系不确定性。三者目标分开；构筑探索器不必是同一个 Transformer。

## 策略种群

成员由规则版本、构筑或构筑策略、策略版本、适应对手、预算和种子共同标识。策略版本覆盖脚本代码、搜索配置和模型检查点。维护当前策略、历史版本、固定基准、独立探索策略与已知威胁。单人游戏比较场景分布，对抗游戏比较对局矩阵。

对抗游戏采用 PSRO 风格循环：交叉评测 → 选择对手混合 → 生成新响应 → 加入种群 → 更新收益矩阵。新响应可以是 Agent 修改的脚本、搜索策略或训练模型。不要只保留平均胜率最高的成员；克制关系可循环。响应生成器的盲区不会因使用 PSRO 自动消失。

对抗趋同的独立挑战包括：针对主流策略、稀有组合专项训练、资源循环与行动压制搜索、人类反例、不同搜索方法。人工提供优势条件时，分开记录“条件成立时的效果”和“从正常开局到达的成本”。

## 隐藏信息

可执行接口见 [受限模拟](../spec/planning.md)：PlanningService 从合法信息经游戏 PlanningAdapter 建立假设起点，复用原游戏规则和 core；真实全状态干预另走 ExperimentService。

完整 context 只提供准确执行，不自动提供合法决策搜索。审计可以研究真实局面的动作后果；玩家策略不得读取真实隐藏数据。

策略搜索必须定义信息状态与相容局面处理。不能把每个抽样隐藏局面当明牌求最优后简单合并，便宣称没有信息问题。第一版训练可先不用此类搜索；后续以 ReBeL 等工作为方法参考，明确双人零和等适用边界。

## 设计空间与干预

```typescript
type DesignSpace = {
  baseline: GameVersion;
  editable: EditableRegion[];
  constraints: Constraint[];
  frozenContracts: ContractRef[];
};

type AdaptationScope = {
  play: "frozen" | "train";
  construction: "notApplicable" | "frozen" | "optimize";
};

type ExperimentSpec = {
  baseline: GameVersion;
  variant: GameVersion;
  focal: AdaptationScope;
  opponents: AdaptationScope;
  initialization: CheckpointSet;
  baselineBudget: Budget;
  variantBudget: Budget;
  evaluation: EvaluationProtocol;
};
```

三类干预分别测短期冲击、固定构筑的战术适应和构筑/打法的生态适应。基线也获得匹配的继续训练预算。冻结权重不等于行为不变：输入新规则数值、搜索配置和规则访问权限均须固定或记录。

设计 Agent 不得同时修改自己的收益定义、分析解释和评价门槛来获得更好结果。修改这些契约应生成新的研究任务。更换规则导致动作或观察模式变化时，要验证模型兼容性，不能把接口失败算成设计弱化。

## 关系与冷区

关系单位为 `(节点或组合, 关系类型, 上下文)`。节点可表示卡牌、组合、构筑、策略、角色和规则版本。原始统计必须记录机会分母；携带、抽到、可用、实际使用不能混为同一个频次。

每条边保存协议、效应估计、不确定性、有效样本覆盖、策略适应预算、观察/干预来源和回放。α-Rank 可用于策略收益表的生态分析；不能直接把单张卡当策略输入并声称得到了卡牌因果强度。

状态包括：不适用、未覆盖、未充分适应、已排除、有关系、有分歧。“未发现差异”不等于“已证明等价”。

冷区比例必须声明查询域与权重；权重不能只来自当前策略采用频次。分别展示卡池均匀、合法机会、自然到达概率和重点机制的覆盖。两两关系覆盖不等于高阶组合覆盖；假热区由独立挑战与方法分歧检查。

## 评测输出

每次评测输出规则和模型版本、训练预算、对手/角色/座次分布、独立种子、收益矩阵、样本及区间、失败与截断计数。训练曲线或对称自博弈平均胜率不能单独作为进步证据。

“稳定”仅指指定评测条件下的稳定；完整计算表现力不支持对所有游戏做有限预算探索完备性承诺。图谱必须保留未知区域。
