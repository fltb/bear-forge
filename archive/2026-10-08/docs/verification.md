# 语义与验证

规则正确性、训练管线正确性和策略实力是不同命题。它们需要独立的预期与证据；模型学会利用错误不能视为验证通过。

## 演算机的证明义务

| 性质 | 证明或论证方式 | 实现对应检查 |
| --- | --- | --- |
| 通用计算能力 | 固定保底原子加流程递归编码图灵机 | 符号比较、列表/pair、分支、递归与尾调用符合规格 |
| 交互表达能力 | 将可计算交互系统编码为 Continue/Request/Done，并模拟转移 | 中途选择、嵌套效果、调度均可表达 |
| Context 完整性 | 每条转移仅依赖程序、context 和显式输入；归纳得到恢复等价 | 无宿主状态残留，包含控制帧、引用与外部等待状态 |
| 分支隔离 | 不可变共享或写入隔离保持各分支逻辑存储独立 | 交叉修改、引用别名和捕获环境测试 |
| 类型与作用域安全 | 根据实际类型系统给出对应保持性等论证 | 校验器拒绝越域符号、错误签名和不合法引用 |

模型层面的人工证明已写入 [证明规格](../spec/proofs.md)，包括完整 context、隔离、预算分段、图灵机编码与交互模拟。它们以合格 TS 原子和持久化存储为前提，不是机械化证明或实现验收。图灵完备性不证明所有程序终止，也不证明所有游戏策略可被发现。预算耗尽在流程步骤之间可恢复；同步原子内部不承诺可恢复暂停。

若以后引入字节码，新增语义保持证明和与参考解释器的差分验证。宿主原语必须有明确语义与资源计量边界，不能成为藏有状态或无限工作量的黑盒。

## 受控编译验证

参见 [编译方案](../spec/authoring.md)。执行模型正确不推出编译器正确；需要建立源码局部值、控制位置和请求顺序与生成帧/代码的模拟关系。对照普通 JS 参考执行、IR 解释与生成后端；拒绝未支持语法，不允许降级为原生异步现场。

## 规则包验证

每个机制交付前置条件、读取时点、更新范围、原子边界、事件、选择与取消/失败行为，并配套具体裁定用例。预期来自规则规格或独立参考，不由实现反推。

验证组合：

1. 具体局面与动作的逐决策边界预期。
2. 适用的不变量，例如区域唯一性、非法输入不改变状态、引用生命周期。
3. 随机生成合法场景的性质检查。
4. 与参考实现的差分；分歧仍需按固定规则版本裁定。
5. 注入错误，检查测试是否能发现重复提交、颠倒时序或信息泄漏。

交互覆盖按身份变化、替换/触发顺序、嵌套选择、同时变化、来源失效和信息变化管理。单卡测试通过不等于组合正确，规则子集通过不等于完整游戏复刻。

## 策略与训练管线验证

- 相同信息历史对应相同模型输入；修改不可见状态不得直接改变输入。
- 动作编码与执行一一对应，合法前缀与最终动作验证一致。
- 角色奖励、终局、截断和错误明确区分。
- 记忆按玩家、对局和分支隔离，无跨局泄漏。
- 行为概率与真正使用的策略/搜索过程匹配，离线与在线样本不混用。
- 使用已知答案环境校准立即收益、延迟收益、记忆、随机化和合作。
- 小型双人零和游戏可精确检查最佳响应或可利用程度；大游戏只报告基准内表现。

## 反例与发布门槛

万智牌专门的表示关系、嵌套施放构造、语义撤销及证明缺口见 [万智牌适配](../spec/mtg-conformance.md)。支持复杂规则的可计算性与正确复刻该规则是两项独立交付。

反例包包括程序/规则版本、必要 context、输入与随机结果、首个分歧、状态差异和因果链。尽量缩减为最小复现，纳入回归。模型记忆与编码版本也属于学习反例的必要材料。

| 门槛 | 通过后允许作出的结论 |
| --- | --- |
| 核心语义与恢复/隔离检查 | 机器在已验证范围正确执行 |
| 游戏规则与信息隔离检查 | 指定规则子集可用于正式训练 |
| 训练管线与小环境校准 | 学习结果可作为策略实验数据 |
| 独立评测与预算协议 | 指定范围内的策略关系有证据支持 |

探索运行可以提前发现缺陷，但必须标为未验证。独立挑战被用于训练后，不再作为独立验收集。正式图谱不得自动把执行错误、未覆盖或训练不足解释为设计缺陷。
