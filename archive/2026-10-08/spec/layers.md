# 内核、共享库与游戏 DSL 的分层契约

当前规范以 [执行规格](execution.md) 为准。此版替代 Scheme、动态深/浅 handler 和禁止所有运行期 TS 计算的旧提案。

## 已确认边界

内核只是执行器与方便记录数据的 toolkit：执行受控程序、保存现场、记录执行事实；不定义游戏循环、回合、胜负或统计意义。游戏根据 SDK 编写自己的主循环、结算循环、调度和领域记录。

游戏决定循环条件与顺序，编译器转换循环回边和跨步骤局部值，内核负责逐步推进及预算。受控规则即使循环内没有 await，也要保留回边预算检查；白名单原子内部循环受原子契约约束。预算暂停不触发游戏规则。

训练与分析通过游戏提供的版本化契约接入，见 [训练与分析接口](ports.md)。context 是执行必需数据，调试 trace 是可选记录，游戏领域事实由游戏声明，三者不混同。

动画属于前端展示层。游戏输出带版本的状态变化和领域事件，前端决定动画的顺序、时长、倍速与跳过；动画结束回调不得推进规则、修改权威状态或触发结算。内核不等待动画，也不包含动画队列。训练客户端可直接消费同一决策协议，无需播放动画。

前端可以维护独立的展示版本及待播放队列，按玩家权限投影后的记录展示；其播放顺序不能改变游戏的同时事件或规则时序。决策到达时允许压缩/跳过动画以对齐决策状态。限时决策由会话协议与显式时间输入裁定，不以客户端动画完成时间为依据。

## 所有权

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 执行内核 | 九种流程节点、显式控制帧、引用存储、外部等待、预算、快照和分叉 | 卡牌、生命、区域、回合、胜负 |
| 共享 toolkit | TS 构造器、纯算法、循环与容器组合、显式随机流、调度工具 | 强制所有游戏遵循一种规则顺序 |
| 游戏规则库 | 状态 schema、领域流程、可审计计算、合法性、观察、结算、终局收益 | 隐藏宿主状态或自定义机器求值分支 |
| 内容 | 卡牌、技能、角色、关卡；组合上述能力 | 宿主 I/O 特权 |
| 运行器 | 活跃分支、响应路由、模型或人类输入、实验资源 | 私自改变游戏规则 |
| 分析适配器 | 将版本化领域事实解释成统计与关系 | 把生命、伤害等反向加入内核 |

## 扩展规则

游戏可增加流程定义、数据 schema、内容及满足准入契约的同步 TS 纯计算；不可增加九种节点之外的机器规则。Compute 通过固定 ID 调用注册函数，程序版本冻结其实现；普通 TS 计算不能直接取得可变 world 或 I/O。

作者使用受控 TS 规则函数，由 [编译器](authoring.md) 生成流程表示；内部仍可用构造器和领域数据调度器组合。源码回调和局部值跨暂停边界时必须完成受支持的转换，不能保留原生 JS 闭包。

核心提供 Call/Bind/Await；领域所谓 damage、trigger、resolve 都是流程函数。动态处理器是 Closure 参数或游戏状态中的显式表，不是语言级续延捕获。替换顺序、重复触发、优先权由游戏程序决定。

## 必须区分的概念

| 机器机制 | 游戏语义 |
| --- | --- |
| Bind 的返回帧 | 游戏的咒语堆叠、待结算任务 |
| Call 调用 | 技能触发顺序 |
| Read/Write 的通用单元 | 区域、卡牌实体身份、生命 |
| Await 等待 | 玩家合法选择、同时行动及公开时机 |
| 纯 PRNG 运算加状态读写 | 洗牌、发牌与随机目标分布 |
| 运行器 fork | 玩家在合法信息下进行搜索 |
| 机器追踪 | 规则承认的伤害、离场等事实 |

上下两种机制可以组合，但不能把一个机器返回点自动当作一次游戏结算完成。领域接口需说明返回意味着“已入队”还是“已结算”。

## 准入条件

1. 构造产物只有九种流程节点、合法操作数、代码定义和引用。
2. TS 计算只依赖参数和版本化不可变定义，满足确定、同步、终止与资源契约。
3. 所有跨步骤的对局状态、局部数据和剩余流程都在 context 内。
4. 程序包与快照绑定；不能在同一版本中热替换计算实现。
5. 外部请求与响应全部走显式边界；禁止普通 Promise 或 generator 保存对局现场。
6. 规则不变量、观察保密、语义合法性由游戏验证，内核不自动担保。

直接拒绝：Damage 特制 opcode、可变全局技能队列、依赖时钟的纯函数、捕获对局状态的运行期 JS 续延、规则计算任意网络访问、原地修改共享快照。

“多款游戏通用”是进入共享库的理由，不是进入内核的充分条件。完整计算与交互表达能力见 [证明](proofs.md)，不等于具体游戏已被正确实现。
