# 万智牌适配：构造方案与尚未完成的证明

状态：架构审查，不是实现验收。当前没有万智牌规则包、编译器实现或机械化正确性证明。表达能力证明不能替代下面的规则精化证明。

## 1. 要证明的命题

固定规则版本、Oracle 卡牌文本快照、赛制与外部裁定协议。当前核查来源为 [2026-09-25 综合规则](https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.pdf)。不得把固定子集的验证结果写成全卡池正确。

令 S 为独立规则规格的状态，C 为执行 context，R(S,C) 为表示关系。输入 i 包含合法选择、随机结果和约定的外部事件。在适当的规则边界上要求：

```text
R(S,C) 且 S --i/o--> S'
    => 存在有限执行 C --i/内部步骤*--> C'
       R(S',C') 且各观察者获得的输出等于 o
```

还需要反方向：引擎提交的每个领域转换都被规则允许。前者防止漏掉合法行为，后者防止制造非法行为。内部步骤允许停顿，但不能在规则应能继续时无限空转。合法无限游戏不要求被强行终止。

证明链分为独立的四项：规则文本到规格的审查、游戏程序到规格的精化、受控 TS 到显式帧的语义保持、执行器到机器规格的正确性。现有 proofs.md 只涉及最后一项的数学模型及一般表达能力，没有完成这条链。

测试、第三方引擎差分与裁定案例提供证据，不能冒充全称证明。独立规格也可能误解自然语言规则，需要可追溯规则条款和独立审阅。

## 2. 游戏包必须保存的状态

以下全部是万智牌程序的数据，不是新增内核指令：

| 游戏数据/服务 | 必须表达的区别 |
| --- | --- |
| objectId、zoneGeneration、历史属性快照 | 物理卡、当前规则对象、历史对象；与内核 Ref 分开 |
| 领域 stack | 咒语/异能堆叠；与机器调用帧 K 分开 |
| procedure、permission | 当前正在做什么、为什么此时允许作选择；不能仅用 currentPlayer |
| pendingEvent、replacementHistory | 提议事件、修改后的事件、正式提交；保留应用谱系 |
| pendingTriggers、placementProcedure | 触发发生、进入等待集合、入堆叠、结算是不同阶段 |
| continuousEffects | 来源、作用域、层、时间戳、依赖；派生属性缓存只是优化 |
| actionJournal | 施放/起动过程及支付依赖；语义撤销不能直接恢复整个 context |
| decisionAuthority | 决策主体、代为选择者、合法信息、资源归属与收益归属 |
| turnSchedule、taskTable | 普通推进、插入、跳过、延迟规则和任务失效 |
| sessionLineage | 子游戏、重开、继承数据及历史归属 |

对应核查入口：综合规则 400.7、601–616、704、723–724、727、729、732–733。此表是实现设计，不是宣称条款已被逐一实现。

## 3. 可直接审查的复杂控制流构造

### 搜寻过程中施放 Panglacial Wurm

采用当前版本允许的普通产费手段，并假设其余施放条件满足。预期程序结构：

```text
resolveSearch
  -> searchWindow
      -> 玩家选择施放 Wurm
      -> castSpell（授权来自搜寻窗口，不来自优先权）
          -> 选择/费用/支付子流程
          -> 完成施放，将 Wurm 留在领域堆叠
      -> 返回原搜寻流程
  -> 完成搜寻的剩余指示
  -> 返回游戏调度器
```

这是架构构造：每个缩进对应普通 Call/返回；等待选择用 Await，局部状态与返回位置放在显式帧。Wurm 留在领域堆叠不意味着机器应立即 Call 它的结算流程。

局部证明义务：支付期间暂停/分叉后，恢复的仍是同一个搜寻实例；只施放一次；没有提前结算 Wurm；没有把搜寻窗口误开放成任意瞬间咒语窗口。程序计数器、实例 ID、权限与领域堆叠四者共同决定行为。

版本反例：[官方 2026 年 8 月更新公告](https://www.magic.wizards.com/en/news/announcements/the-hobbit-update-bulletin) 修改了产费能力判定；Chromatic Sphere 和 Selvala, Explorer Returned 等不再符合条件。因此旧版“搜寻中为 Wurm 使用这些能力”的测试不能原样作为当前规则正例。需要正例和禁止例成对验收，且冻结规则/Oracle 版本。

### 非局部流程改变

“结束回合”不能实现成设置 turnEnded=true 后继续执行当前规则余下语句。建议万智牌 SDK 用显式领域结果：

```typescript
type ResolutionResult<T> =
  | { kind: "normal"; value: T }
  | { kind: "redirect"; procedure: ProcedureRef; payload: Value };
```

所有可传播该结果的游戏组合器必须检查并返回 redirect，由游戏调度器运行对应程序。底层仍然只用返回、分支、调用与数据写入；内核不需要 EndTurn 指令，也不允许游戏任意篡改机器帧。

必须证明：redirect 后旧流程不再产生领域事件；调度器接手一次；遗留任务按规则处理。不是每种特殊流程都能丢弃原续延：重开游戏和子游戏等必须分别定义返回/延续策略，不能共用“清空全部状态”。

### 规则撤销与训练分叉

综合规则 733 的撤销有保留限制，不能用 restore(snapshot) 一概实现。游戏层记录细粒度 actionJournal：操作、因果依赖、是否可撤销及规则依据，再计算撤销程序。此算法尚待给出与证明。

三个操作必须分开：协议拒绝无状态改变；游戏语义撤销产生按规则调整后的状态；训练分叉保留一个假设世界。已经交给玩家的知识不能靠恢复堆消除，观察历史与撤销记录必须单独核对。

## 4. 压力机制的验收义务

| 机制 | 必须检查的架构性质 |
| --- | --- |
| 替代链与同时事件 | 应用谱系不重复；相关选择顺序与实际提交边界可区分 |
| 持续效果层与依赖 | 未缓存的语义解释器与缓存版一致；循环依赖有规则处理；不能直接依赖 signal 拓扑 |
| 触发与状态动作 | 不能把每次 Write、每次 Await 或返回都当检查窗口 |
| 换区、历史信息与关联能力 | 不把同一张物理卡的新对象误连到旧效果；历史读取时点准确 |
| 控制另一位玩家 | 选择者与行动主体分离；观察、费用和收益分别归属 |
| 结束流程、重开、子游戏 | 旧续延终止/保留条件明确，且没有重复效果或悬空等待 |
| 规则循环与捷径 | 预算耗尽仅为暂停；有限测试没有发现出口不等于强制循环平局 |

游戏 SDK 可将前述数据编码成已有 Value/Ref，将算法写成受控 TS 流程。由现有表达能力结论，可以承载一个已给出的可计算规则算法；这不能证明该算法就是正确的万智牌算法。

## 5. 哪些仍然缺失

- [ ] 固定完整支持范围，逐条规则列出实现位置；不支持项显式拒绝，不能降级成近似效果。
- [ ] 给出领域状态和转换的独立规格，尤其是撤销、依赖算法、特殊控制流。
- [ ] 实现规则包与编译器，并完成上述表示关系的局部保持证明。
- [ ] 组合定理：模块证明的前置条件被调用方保持；仅各自单测通过不够。
- [ ] 建立带规则版本、初态、选择、每方观察、预期轨迹的独立裁定集。
- [ ] 任意受控边界快照恢复/分叉与不中断运行一致；记录、权限与语义历史一同验证。
- [ ] 边界与故障分类：资源中断、不支持规则、引擎错误不得计成游戏平局或卡牌弱势。

一般程序的无限循环不能由通用算法完整判定；内核不得承诺自动解决所有万智牌循环。游戏可用已证明的规则特例、玩家提出并验证的捷径，或显式外部裁定协议；未解决状态须标记未解决。若要求全自动且所有可能局面必然给出正确终止结论，这一要求超出当前可承诺范围。

相关理论证据见 [Churchill、Biderman、Herrick 的论文](https://arxiv.org/abs/1904.09828)：作者在其规则模型下构造了结果不可判定的强制行动局面。这不妨碍逐步执行，也不代替对当前规则版本的复核。

目前结论：已给出复杂流程的承载构造，未发现必须增加游戏专用 opcode 的理由；万智牌规则正确性仍是明确未完成的交付项。
