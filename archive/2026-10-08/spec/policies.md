# 策略层、脚本种群与游戏 AI

状态：职责设计，尚未实现。策略位于规则和 core 外部，经会话决策协议参与游戏。[架构与数据流](../docs/architecture.md) 是总入口。

## 1. 接口与状态

```typescript
interface Policy {
  decide(
    decision: DecisionPacket,
    memory: SerializableValue,
    budget: PolicyBudget
  ): Promise<PolicyReply>;
}
type PolicyReply = {
  action: Action;
  nextMemory: SerializableValue;
};
```

这是宿主概念接口，允许异步，不是规则 DSL 的 Await。会话负责校验、提交、超时和过期响应；策略无权修改真实状态。搜索使用独立 Planner 能力，不获得真实 checkpoint/fork 权限。

策略版本包括代码/权重、编码器、动作生成、搜索配置、先验、对手配置和随机算法版本。记忆按策略身份、会话和分支隔离。可序列化逻辑记忆与可重建 GPU 缓存分开；复现记录策略随机状态和必要历史。游戏 context 与策略记忆分别保存，实验检查点关联两者。

PolicyRuntime 在接受动作的边界提交对应记忆；过期/重复回复不得推进当前记忆。重试若有记忆更新，必须显式定义和记录。行为来源与概率遵循训练契约，脚本/搜索动作不能冒充模型原分布采样。

## 2. 实现共存

- 脚本：CPU worker 中的启发式、有限搜索和历史记忆。
- Transformer：GPU 批量推理，记录实际检查点，完整动作参数尽量一次解码。
- 搜索器：受限模拟服务构建假设，预算包括规则执行和模型调用。
- 组合策略：明确组件分工与切换条件，作为完整策略重新评测。
- 真人：使用同一动作协议，前端不需要实现模型训练接口。

游戏专属策略库可提供估值和构筑特征，但不是规则真相。规定的怪物行动可属于游戏；可替换的玩家打法属于策略。策略是否用规则 DSL 是独立选择，当前不要求把策略脚本编译进游戏程序。

## 3. 编程 Agent 与脚本候选

Agent 是局外策略生成器：读取公开规则、观察 schema 和指定训练反馈，输出脚本候选与策略假设。经接口、权限、资源和动作检查后试跑；可运行不等于强策略。

脚本进程不挂载真实 context、审计文件、真实 seed 或任意网络能力。进程和受限能力用于隔离；linter 或 worker 本身不是完备安全沙箱，具体隔离实现待交付。

循环为：提出假设 → 写脚本 → 小预算对局 → 返回失败/覆盖反馈 → 修改 → 独立评测 → 保留。Agent 的 token/现金费用、修改轮数和模拟计算都纳入 $500 上限；局内不调用大模型不等于生成策略免费。

不同 Agent 承担不同探索任务，但多样性按行为、构筑、克制和场景优势衡量，不按 Agent 数量宣称。相邻 checkpoint 不作为独立发现。保留固定基线、历史威胁和未用于适应的挑战集。

## 4. 训练、设计、产品用途

脚本、模型、搜索器可混合对战。学习器仅更新指定模型，对手无需同时学习；保留循环克制。单人游戏比较共同场景分布，不做虚假对战矩阵。

脚本轨迹可用于模仿初始化；其动作没有模型采样 logprob，不能直接混作 PPO 在线样本。加入训练的挑战移出独立验收集；比较记录座次、构筑、规则、推理预算。

固定策略实验冻结脚本、权重及相关配置；战术适应限制可修改模块；生态适应开放构筑与打法。不可分离的策略不能口头宣称只适应战术，必须有可执行限制。脚本改写和权重更新成本分别计量，避免把不同工作量当作公平适应预算。

产品 AI 另验收难度稳定、风格和延迟。默认合法信息权限；未来若增加产品作弊设置，必须独立声明，不能混入公平设计评测。

## 5. 当前交付顺序

先统一协议、脚本基线、Agent 候选管理、对局与关系证据，再按 PlanningAdapter 支持范围加入搜索。小 Transformer 接同一环境，仍遵守 4070、本地优先、$500 上限。设计探索成功标准是发现并验证有条件的卡牌/策略关系，不是规则测试通过。

## 6. 内置起步策略

首批接入 RandomLegal、FirstLegal、LastLegal，均经普通 Policy 接口参与，不进入 core。它们用于初始轨迹、基准和粗略覆盖，不充当卡牌价值裁判。

游戏动作协议提供稳定且不泄露信息的排序。复杂动作通过结构化前缀选择，要求可完成性或明确回退，不枚举无限/极大动作空间。随机前缀采样与完整动作均匀分布不同，采样算法和 seed 必须记录。First/Last 受顺序影响，若末项是结束回合则如实标注其行为。重复行动导致预算耗尽按截断记录，不自动判平局。
