# 执行规格 v0.1：构造性证明与实现责任

范围更新：以下仅证明旧演算机的数学模型性质，不证明现成后端，也不把任意指令级暂停规定为现行需求。当前边界见 [执行与实验契约](runtime-contract.md)。

对应 [执行规格](execution.md)。以下是数学模型上的人工证明，不是机器检查的形式化证明，也不是已有代码通过测试的报告。

## 0. 假设与观察范围

A1：程序包冻结且引用、作用域、schema 有效；操作数及 context 只含规格允许的数据。

A2：每个注册 Compute 是输入到 Ok(value)/Error 的确定、终止、可计算函数；不修改输入或外部状态，没有隐藏对局状态。成本契约有效。

A3：H、rho、K 和值具有不可变语义；实际共享实现遵守写时隔离。初始化引用和闭包均合法。

A4：比较两次执行时，使用同一程序版本及对应的外部响应序列。数学内存无固定上限，允许任意大的有限配置。

可观察行为为按序出现的外部请求及响应、已提交存储和完成/错误结果。另行说明时可忽略本地请求 ID、地址重命名、内部步骤数、预算让出及调试轨迹。这里不把时间或运行器分支路由 ID 当作游戏输入。

## 1. 单步确定性与 context 完整性

命题：对任何良构的非边界 C，step(P,C) 有且只有一个下一结果，且不需要 context 以外的可变游戏状态。

证明：按 mode 分类。Eval 的九种节点互斥；Return、Bind 及三个存储节点均由 C 中字段唯一决定；If 的 Bool 决定唯一分支；Call 从冻结 D 和显式闭包产生唯一环境；Compute 由 A2 唯一确定；Await 使用 authority 和 nextRequest 唯一产生请求。Value 的 K 非 Halt 即 Frame，各有唯一规则。错误检查次序固定。Waiting/Done/Fault 是显式边界。所有规则只读 P、C，因此没有第二个隐含状态来源。证毕。

推论：若 snapshot 编解码保持所有上述值、引用与程序版本，则恢复前后的单步结果相同。对执行长度归纳，给定相同后续输入，所有有限执行前缀相同。快照保存的 K 和捕获值包含剩余流程，无需重放之前的输入。

注意：定理不证明任意 JS 满足 A2。一个 Date.now、可变全局变量或不可见缓存反例就足以让前提失效。

## 2. 纯转换语义、单步原子性与分支隔离

命题：step/resume 不改变输入快照；它们产生新 context 或拒绝。只要 C1、C2 最初来自同一快照，C1 的后续执行不会改变 C2。

证明：检查转移，非存储步骤只产生新的控制/环境/请求数据；Alloc/Write 采用 H 的函数式更新，旧 H 不变；Read 只读；Compute 按 A2 不修改数据。resume 只替换新 context 的 mode。以执行步数归纳，任意分支的更新均保持其他根可达数据不变。独立响应仅影响被路由的分支。证毕。

这要求实现的结构共享不暴露可变对象别名；仅复制顶层对象不能满足 A3。这个定理也不提供分支合并语义。

单步原子性：每步先完成参数与结果检查，再发布一个新根；失败时该步不发布部分写入。此前其他步骤的写入不自动回滚，因而没有错误地推出“整张卡是事务”。

## 3. 暂停、恢复与预算分段等价

命题：在任意已完成步骤之后暂停，再用同一 C 继续，得到的规则轨迹与连续执行相同。

证明：由定理 1，下一步仅取决于 P、C。run 的预算不足分支不执行转移、不修改 C；补足预算后下一步仍相同。对后续步数归纳即可。Waiting 保留 K；合法 resume 只将响应设为 Value，由普通返回规则送入后续流程，其他数据不丢失。证毕。

命题有条件：后续必须最终提供足以执行各步骤的预算；每次都给小于某原子成本的预算会一直让出。真实超时或内存耗尽不属于上述正常暂停。

## 4. 计算完备性：直接编码任意确定性图灵机

无需使用任意用户 JS，也无需 mutable store 或 Await。仅使用 Return、Bind、If、Call、保底 Compute 和基础有限数据。

给定任意确定性单带图灵机 M，有限状态 Q、有限带符号 Γ（含 blank）、有限转移表 δ，以及停机状态集合 F。状态和符号用 Symbol 表示。配置编码为：

```text
c = Pair(q, Pair(L, Pair(h,R)))
```

h 是当前格，L/R 分别是左/右侧从近到远的 List<Symbol>；没有显式表示的格为空白。任意有限计算前缀只访问有限纸带，所以配置始终可由有限值表达。

以下伪代码是九种节点的组合缩写，不是依赖 JS 执行的算法：每个赋值展开为 Bind，每个纯操作展开为 Compute，每个分支展开为 If，流程应用展开为 Call。

```text
pop(xs):
  if list.isNil(xs): return Pair(blank, Nil)
  else: return Pair(list.head(xs), list.tail(xs))
```

pop 的分支有限，并且只在非空分支投影，永不访问空表 head/tail。δ 是有限表，因此可生成有限的 symbol.eq 与 If 树，不需要反射或动态编译。设 δ(q,h)=(q',w,d)：

```text
若 d=右：
  (h',R')=pop(R)
  返回 Pair(q', Pair(cons(w,L), Pair(h',R')))

若 d=左：
  (h',L')=pop(L)
  返回 Pair(q', Pair(L', Pair(h',cons(w,R))))

若 d=不动：
  返回 Pair(q', Pair(L, Pair(w,R)))
```

这定义一个有限流程 stepM。保底原子均终止，分支有限，所以每次 stepM 在合法非停机配置上有限步终止，并精确完成一次写符号及移动。

生成有限递归定义：

```text
runM(c):
  if isHalting(c.q): return c
  else:
    c' = stepM(c)
    return runM(c')
```

isHalting 是有限比较树；runM 的递归引用为固定定义 ID，不进行 TS 无限展开。各配置的类型固定，所以不依赖动态类型绕过。

模拟证明：初始有限输入可编码成上述配置；按左右不动三种情况，stepM 保持配置对应关系。对 M 的步数归纳，每个 M 步对应有限个引擎步。M 停机当且仅当 runM 返回编码终态：若 M 永不停机，每个 stepM 虽然结束，但 runM 持续递归，不会自行返回。按终态纸带读取输出即可计算 M 计算的函数。

因此，在 A4 的数学资源模型下，固定保底原子加流程组合具有图灵完备性。每个原子都终止与整体完备性不冲突，无界计算发生在流程的重复调用中。反过来，有限数据上的每条规则都可计算，A2 也禁止不可计算 oracle，因此闭合引擎没有超出通常可计算能力。

这不是“因为 TS 完备，所以系统完备”的循环论证。证明只使用列明的列表、pair、符号比较原子和明确的流程控制。

## 5. 可计算交互规则的表达能力

对象范围：一个顺序运行、每次推进可在有限时间内决定 Continue/Request/Done 的可计算规则系统；状态和消息均有有限编码。发散规则可以表达，但不能保证其到达下一个决策点。

把系统状态编码为 s，定义其推进函数：

```text
advance(s) = Continue(s') | Request(q,p,s') | Done(r)
accept(s',response) = s''
```

两函数可通过定理 4 的编码表达，也可由合格 TS 计算加速。驱动流程对标签分支：Continue 递归；Request 执行 Await(q,p)，Bind 响应后计算 accept 再递归；Done 返回结果。对交互次数归纳，请求顺序、响应后的状态和终局结果都与原系统对应。

并发/同时行动的离散游戏规则可由显式消息集合与调度状态描述；同时保密、公开时点和合法性不由本定理自动保证，需游戏编码满足其规则。有限 capability 类型可用通用消息封套编码，动态内容不需要新增机器指令。

因此，嵌套选择、反应窗口、任务队列与任意可计算游戏调度不要求增加伤害、死亡或牌型等专属 opcode。可表达性不是已经正确复刻某个商业游戏的证明。

## 6. 函数组合律与尾调用

在无限预算的可观察语义下，忽略内部步骤、调试位置等管理细节，Bind 满足：

```text
Bind(Return(a),x,p) ≈ p[a/x]
Bind(p,x,Return(x)) ≈ p
Bind(Bind(p,x,q),y,r) ≈ Bind(p,x,Bind(q,y,r))
```

代换必须避免捕获，且第一式 a 在当前环境可求值；结合律要求 x 不自由出现在 r，必要时重命名。第一式按 Bind、Return、Value 的三条规则得到绑定后的 p；第二式仅在 p 返回后增加一个返回帧，不改变 p 的效果或发散行为；第三式在两边都按 p、q、r 的顺序执行，参数环境相同，仅帧布局不同。对各段内部执行及外部请求按步对应，得到相同存储、请求和结果。

这些不是有限预算下逐步轨迹相等定律；改写可能改变指令费用和调试轨迹。不能按代数律优化后还声称逐步预算完全相同。

尾调用：Call 规则沿用 K，不新增返回帧；调用前用于计算参数的 Bind 帧已经在进入后续流程时弹出。一个只做尾递归的循环不会因循环次数增加未返回控制帧。它仍可能主动累积列表或游戏状态，不承诺总内存恒定。

## 7. 尚需实现验证的责任

类型保持与无未定义执行：按 execution.md 第 10 节的判断，对正常单步分类检查。Bind 压入匹配输入类型的帧；Value 弹帧时按参数类型扩展 rho；If 保持分支结果类型；Call 以已检查的捕获和实参建立函数体环境；Compute 的成功结果须通过声明 schema 检查；Read/Write 保持 Σ，Alloc 用新地址扩展 Σ；Await 保存结果类型一致的 K，resume 只接收该类型值。Return/Halt 同样保持结果类型。因此正常转移保持 context 良构；发生规定错误则进入 Fault，不产生类型不明的可运行现场。

在 A1–A3 和足够数学资源下，任一非边界良构 context 要么有唯一正常转移，要么进入明确 Fault：九种节点与两种 K 已穷尽，操作数有限，原子按 A2 终止。这里不声称良类型程序绝不会 Fault，空表投影、无授权 capability 等仍是规定错误。持久化编解码和宿主实现是否满足这些条件需以下验收。

| 数学前提/规则 | 实现验收 |
| --- | --- |
| 有限纯值与稳定代码引用 | 快照编码、Ref/Closure 校验；不允许 JS 函数、getter 或可变别名进入 |
| 作用域与签名合法 | 构造回调只运行一次；符号越域、未声明捕获、递归引用及结果类型检查 |
| Compute 合格 | 输入不变、重复执行一致、错误契约、资源计量、外部访问准入；测试不等于证明任意 JS 纯净 |
| 单步规则对应 | 每种节点及故障路径的实现测试，参考模型对照 |
| context 完整与隔离 | 嵌套选择、递归选择、读写别名、父/兄弟快照互不污染、恢复后对应 |
| 响应一次性路由 | 同分支重复、过期请求、兄弟分支串入及活跃版本竞争 |
| 预算与尾调用 | 不同预算分段结果一致；长尾循环控制帧不增长；大原子成本不足不偷跑 |

本文给出上述模型的人工构造性证明，未给出 TS 程序的机械化类型安全证明，也未声称实现已经满足 A1–A4。游戏规则正确性和学习覆盖度仍由各自的验证协议负责。
