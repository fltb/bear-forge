# 共用游戏会话、时间与前端展示

状态：已讨论确定的设计边界，接口仍是待实现规格。补充 [训练与分析接口](ports.md)，将公共游戏交互从训练专属协议中分离。

## 1. 一份规则程序，多种客户端

前端、人类、模型和脚本使用同一份游戏程序、同一动作协议和同一规则校验。游戏不判断参与者是在训练还是在真人对局；席位控制器由会话运行器绑定。

三份契约：

- GameContract：初始化、玩家视图、决策、动作、游戏结果。
- TrainingContract：观察/动作编码、学习奖励、行为概率、轨迹与截断。
- AnalysisContract：领域事实、机会分母、统计与实验关系。

游戏调用 game.requestDecision；不采用 training.choose 作为通用规则接口名称。图像、布局和动画资源独立于规则程序，通过定义 ID 关联。

```typescript
createSession(game: GameRef, setup: Value): SessionId;
getView(session: SessionId, viewer: ViewerId): GameView;
submitAction(session: SessionId, input: {
  decisionId: DecisionId;
  expectedRevision: Revision;
  action: Value;
}): Accepted | Rejected;
subscribe(session: SessionId, viewer: ViewerId): Stream<GameUpdate>;
```

这些是会话服务接口，不是内核业务指令。训练可通过进程内适配器调用相同语义，不必走网络；前端通过网络接入。单机可以把运行器放在 Worker，多人隐藏信息对局推荐由服务器持有权威 context。

玩家视图由游戏进行权限投影；模型编码与前端呈现都在合法视图上工作。浏览器不能获得完整牌序、种子或其他玩家私有数据。断线重连获取当前合法视图、版本与待决策；不依赖恢复一个原生 Promise。

## 2. 限时决策是显式协议

```typescript
const result = await game.requestDecision({
  actor: player,
  actionSpec,
  timeout: { afterMs: 30_000 },
});

if (result.kind === "expired") {
  await applyTimeoutRule(game, player);
} else {
  await executeAction(game, player, result.action);
}
```

超时是正常协议结果，不是机器 Fault。跳过、托管、判负、扣剩余时间等由游戏/会话契约规定。内核不读取 Date.now，也不自行启动真实定时器。

会话适配器将时间转成显式记录：DecisionOpened、ActionReceived、DeadlineReached。保存逻辑时间、决策 ID、opensAt、deadline、时间策略及已接纳事件；真实时钟与虚拟时钟只是两种输入来源。底层 Await 仍只是通用请求与响应。

默认建议政策：由服务端权威接入点为动作加时间戳；有效动作必须严格早于期限，恰好截止算超时；非法动作不重置期限；活跃决策最多完成一次。裁定按该接入点的有序事件与固定规则完成，不能依赖业务工作线程与定时器回调偶然执行先后。具体政策必须版本化，不能在运行中变更。

客户端倒计时仅作展示。重启后是否将离线期间计入期限，由会话政策明确：若继续计时，需持久化可恢复的到期依据并在恢复后补发到期事件，不能只保存进程内单调时钟数值或定时器句柄。

## 3. 训练的时间驱动

训练不真实等待期限，也不把模型推理耗时自动计入游戏时间。

| 时间作用 | 训练协议 |
| --- | --- |
| 单纯防挂机 | 正常训练可默认及时响应；超时分支单独覆盖 |
| 每局总时间、思考预算 | 使用显式虚拟时钟和模拟耗时 |
| 等待会影响收益或行动顺序 | 将时间纳入动作/环境转移，不得删掉该规则 |

“不受训练机器速度影响”不等于“不训练时间策略”。时间模型、耗时分布、是否注入超时均属于实验版本。真实部署的推理延迟另行评测，不能由即时响应训练结果推断部署时没有超时。

模拟快照保存逻辑时间与期限；分支实际算得更慢不会自行过期。回放使用记录的时间事件。人类对局仍按该会话真实时钟政策推进，不能因研究分支暂停而冻结正式比赛时间。

## 4. 动画完全在前端

游戏提交带版本的状态变化与领域事件；先按玩家权限投影，再给前端。前端将这些数据转成移动、命中、数字变化和离场等表现。

禁止 await playAnimation，禁止动画完成回调推进规则、修改权威状态或触发后续结算。只有真实决策或游戏定义的外部输入使规则等待。训练直接消费同一协议，不加载或播放动画。

前端独立保存：已接收权威版本、当前展示版本、待播放事件与相应状态变化。它在播放时推进展示版本，不重算游戏结果、不重新扣血，也不读取已经改变的最新世界来解释旧事件。

游戏同时事件可被前端同时或分段表现，但视觉顺序不能变成规则顺序。隐藏牌面使用该玩家在相应版本合法可见的数据。播放器可以暂停、快放或跳过；重连/积压时可丢弃剩余动画并对齐最新合法视图。

## 5. 动画与限时决策的连接

默认在决策到达时允许压缩/跳过未播动画，及时展示决策状态；倒计时按服务器公布期限计算。设备掉帧、关闭动画或后台标签页不改变裁定。

若产品要求先展示一段过程再开放决策，由会话服务声明固定 opensAt/deadline，而不是无限等待客户端动画完成确认。训练推进虚拟时间即可，不真实等待展示窗口。此政策不进入卡牌代码。

## 6. 验收不变量

1. 同一游戏版本、初始状态、动作和时间输入，在动画开启/关闭/跳过/卡顿时，规则结果相同。
2. 前端与模型提交相同规范动作，得到相同权威状态转换。
3. 重复、迟到、过期和越权动作不绕过会话与游戏校验。
4. 实时时钟输入记录后，虚拟时钟回放得到相同超时裁定及游戏结果。
5. 训练协议明确说明时间策略覆盖范围；动画事件不成为学习奖励或环境时间步。
