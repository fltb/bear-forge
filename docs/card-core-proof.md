## 43. 整体优化的条件等价性与实现义务（2026-10-21）

本节对应 card-core-spec.md 的三层整体优化设计。编号43承接原第42节；为便于阅读放在文首，既有第1–42节仍在后文。条件证明针对有效规则程序，不把任意使用 any 伪造类型、隐藏可变状态或违背只读约定的程序纳入新增保证。

### 43.1 关系与观察

设既有语义的逻辑配置为 C，优化后的物理配置为 C′，Program 静态定义分别为 P、P′。定义投影 π(P′,C′)=C：恢复组件的逻辑世界、登记序列、outbox和任务、控制帧/游标、待决调用、RNG、预算和记录。索引、槽位和COW布局属于表示，不增加第二个逻辑世界。

观察 O 包括外部call/reply/done/fault、完整玩家可见交付、合法动作顺序、全部未来相关状态、记录、规定的对象别名/可变隔离与拒绝位置。对给定同一Card声明，逻辑trace和预算也在O内。内容源码重排带来的Program身份变化不承诺跨版本内部位置号相等，但每个冻结Program自身必须稳定。

需要证明 R(C,C′) ⇒ 对每个合法输入，存在有限优化步骤使 R(C₁,C′₁) 且 O一致；拒绝输入两侧都不推进。随后对输入前缀归纳得到完整轨迹等价。以下引理给出这一模拟关系的条件，源码落实及有限差分是后续义务。

### 43.2 校验前移与删除

装配检查 V(P) 只依赖不可变Program，故对所有运行Context相同。装配成功后反复计算V不会增加判别信息，可以替换为已绑定描述；含运行值的检查不满足这个条件，不可前移。静态配置的转换在装配完成，动态setup或由seed生成的地图不属于静态P。

内部结构谓词 T(x) 若由受信任模块的实际类型、已验证链接关系及构造操作保持，则在每条可达内部边上 T(x)=true。删除一个纯判别、恒为true、无转换/副作用的检查保持后继。对类型化函数应用和受约束构造归纳可证明T的保持；需要消费动态数值范围的边不能由TS number直接推出T。

这是用户选择的可信类型边界：以实现遵守类型声明为前提，不继续运行冗余结构校验，也不把TypeScript本身声称为全称机器证明器。未知外部输入先验证建立前提；转换、默认值、自定义refinement或会保留/修改值的parser不是恒等谓词，不能用此引理删除。若已有边界规定拒绝变换结果，仍须得到相同拒绝。

实现义务：每个删除点归属装配事实或明确类型；真实动态谓词与parser顺序保留；不得用any/双重断言补洞。旧内部类型伪造负例改为类型/装配反例，外部和动态反例保留。

借用与纯schema结果复用：令 B 为已隔离、递归只读的版本，S 为装配固定且不含作者回调的schema计划。S(B)只依赖(B,S)，同一版本重复检查可以复用成功结果；仍保留数值范围、字段顺序、strip/strict等规范化结果。未拥有输入先取得自身所有权，再冻结私有结果；已拥有子版本继续共享。任意refinement/transform/default/opaque parser不使用这个纯计划证明，输入与保留的输出仍隔离，回调顺序与次数不改变。纯计划的缓存不依赖Context状态，也不缓存Query业务结果。

组件/Query/Atom/read回调的读接口统一为递归Borrowed<T>。owner更新C为C′，保留的C引用不变；未改动的只读子版本可属于二者。登记R安装时不可变，事件捕获R后，卸载只从当前登记表删除R的索引，不改变捕获值；故借用R与复制其字段在允许观察内等价。任务参数与显式snapshot同样捕获稳定版本，不是指向以后可变的对象。

### 43.3 索引等价

令 Reg 为登记表，目标t的语义候选为 sort(filter(Reg,target=t),既有偏序/优先级/sequence)。初始化空表满足桶I[t]与该序列相等；每次合法安装按同一顺序插入，每次撤销删除同一ID，其余目标桶不变。对登记变更次数归纳，I[t]始终给出原序列。

条件/资格仍在原时点判断，事件仍捕获当时快照，故折叠、派发和重选输入序列不变。entity/component/source/scope/task索引以同样的增删保持证明。索引和主状态在同一提交点改变，失败前不动两者；fork/restore保持这个不变量，而非依赖全局可变缓存。

### 43.4 字面量和表达式

静态字面量中的定义引用和参数位置由链接函数L固定；运行时只对动态叶求值。若构造器保持叶的求值顺序、每次构造的身份、内部别名、字段顺序与捕获时间，则预绑定构造与原递归evaluate值同构。静态只读数据只能在O允许共享的位置共享。

b.read中的任意函数不能由此推出可在装配运行；动态query构造必须保留参数捕获时机。Query结果复用若不能证明当前版本、依赖登记和身份观察不变，不采用。第三层把动态构造重写为装配表达式时，逐调用点确认运行输入和依赖不变。

### 43.5 原子提交与拆组件

设原单体状态s与新组件组(s₁,…,sₙ)通过可恢复映射F对应，逻辑完整投影恢复s。每个原子只更新相关组件且F(update′(s₁,…,sₙ))=update(s)，故拆分保持逻辑状态。地图/池/历史不误归静态；不保留旧s作为第二权威副本。

必要运行约束、动态写权限/实体资格和捕获查询先在overlay上完成；提交之前无可见写入，提交将写集、索引、事件和ID一并应用。失败保持R，成功保持R并产生同序事件。类型形状检查的删除按43.2，不影响这些动态义务。

### 43.6 物理块与逻辑步骤

块B关联有序逻辑步骤(τ₁,…,τₘ)及每步位置/预算/trace。逐步保持同一副作用和观察；物理分发、查表和可恢复状态的冗余写入可以消除。预算仅允许前j步时，执行恰好该前缀并在原位置fault；作者异常产生相同已提交前缀。不能先执行整个块再扣预算。

request前把所有未来相关控制值写入Context；回复后从相同逻辑位置续接。空派发可以不创建物理帧，但若原逻辑步骤对预算/trace可见，其描述仍按顺序处理。外部trace回调时机不推迟到块尾。由块内归纳及块间模拟，循环/递归/动态调用等价。

### 43.7 COW、别名和回收

投影把每个逻辑对象映到本分支当前的行/页或不可变块。共享页/块没有分支可写别名；写时只分离触及部分并保留逻辑身份/别名，因此父子分别满足同一初始R，后续写入独立。不可变仅证明内容稳定，不自动证明改变===或返回可变性合法；需新身份/独立副本的边继续物化。

增量回收只有在对象对当前分支及其有效共享根不可达时才能删除。开始根、推进期间写屏障、帧/待决队列及fork回收元数据必须保持这一条件；颜色或缓存不能跨分支误用。只移动回收时机不能证明成本消失，回收总工作及债务仍计入性能。

decode(encode(C′))≅C′，并恢复相同Program绑定，即由模拟关系推出同一输入后缀。fork不运行initialize，restore不重放前缀；静态函数和宿主绑定不进入存档。布局身份不匹配明确拒绝，不求助旧执行器。

### 43.8 发布与记录

私有发布值与活动世界和外部可写副本分离，且发布后不再修改，故内部纯只读转发可以共享；真实消费者仍拿到约定的独立副本。保留独立parser行为与隐藏信息投影后，减少内部物化不改变O。

记录块编码E与解码D满足D(E(trace))=trace，并保持追加次序、sequence和逻辑线性化点。fork共享前缀、尾部写时分离；读取/保存得到原DTO和独立输出。没有实际记录消费者的原生模式不构造记录，默认受控仍完整保留。

### 43.9 结论边界

在43.2–43.8前提落实时，对合法外部输入前缀归纳得到三层优化前后的观察等价、恢复后缀等价和分支隔离。证明允许直接替换实现，不要求保留旧生产路径运行自比。具体游戏数值/时序由固定C++、独立机制期望及三方difftest验收。

复杂度改善来自删除全表/全状态/逐层重复处理，不能由上述语义定理推出2.77–6.93ms。50×目标必须最终实测；未知parser、真实完整输出和逻辑trace的必要工作均计入，不能借未证明优化删掉。

## 1. 定义与前提

固定规则包 D（静态定义和函数），世界 W，调用栈 K，待决调用 Q，停止状态 Z，确定随机状态 R 和剩余预算 B。配置 C=(W,K,Q,Z,R,B)。局部值、参数、返回地址及待处理规则队列均包含在 W/K，不存在隐藏续接。静态函数不在 C 中。

操作/查询为同输入给出同结果的有界同步函数，不读写宿主或跨实例状态；所有可变值经实例所属数据图访问，移交原生数据后不再通过外部别名修改它。schema 校验拒绝变换输入的 parser，非法回复不进入机器。操作异常终止为 fault，无自动事务回滚。随机是 R 上的确定状态转移。

这些前提是规则包义务，不可能在没有源码分析或隔离的情况下对任意 JS 函数自动证明。卡牌后端提供已满足这些义务的领域操作；任意程序仍由并列通用后端处理。隐藏信息由 GameContract 的观察/投影证明，不能由状态可复制推出。

## 2. 小步语义

内部步骤标为 τ，对外边界标为 call(p,x)、reply(p,y)、done(v)、fault(e)。预算先于每条执行步骤递减；有限 B 保证至多 B 条内部步骤后等待、结束或预算故障，不保证任意回调内可以抢占。

operation：以当前 W、输入和局部环境调用操作，写回其结果槽，推进当前步骤。branch：只计算一次条件并选择一个子块。sequence：仅在当前子步骤完成后推进。repeat：子块完成后回到条件；forEach：进入时捕获有限成员序列 L，按原身份依次调用，每次具有独立局部环境。invoke：验证目标定义存在，压入新调用环境与返回目标。return：弹出该调用及其未完成结构块，结果写回父目标；顶层则 done。

request：先保存下一执行位置和接收槽，形成 Q=(port,input,target)，发出 call 并禁止内部推进。合法回复原子地消费 Q、写接收槽并续接；重复或不合法回复无对应 reply 转移。事件经原 event 端口采用同一规则。异常进入吸收状态 fault，done 亦为吸收态。

## 3. 栈与组合不变量

I1：每个结构块归属唯一调用环境；每个调用环境至多一个父返回目标。局部槽是字符串到值的有限映射，实现使用无原型字典，__proto__/constructor/toString 同样是普通槽名，不能触发原生原型 setter 或读取继承值。I2：帧的块身份及位置引用固定 D，位置属于块合法范围。I3：等待 Q 指向仍存活的唯一接收环境，等待时无运行中的规则操作。I4：所有未来可观察的值都可从 C 到达。I5：每个动态对象身份解析到本实例一个节点，别名相同身份不分叉。

初态压入入口调用，I1–I5 成立。对每种小步逐项归纳：operation 不改帧归属；结构块沿原调用环境扩展；invoke 增加唯一父边；return 删除该调用所辖块，不能误弹出兄弟环境；request 在存活环境保存 target 并停止；reply 消费后才续接。故所有可达非故障配置保持不变量。未知定义、悬空 target 或非法位置必须拒绝或 fault，不能静默跳过。

由此，sequence 不重复执行已完成子项；branch 不执行另一分支；repeat 在正确时刻重查状态；forEach 保持进入时成员/顺序但可看到同一对象后续规则修改；invoke 保留跨选择的局部值和返回值。对效果结构与调用步数归纳，执行器轨迹等于上述声明语义。递归不假设结构有限，有限前缀归纳仍成立；终止性由规则或有限预算另行处理。

## 4. 确定性与运行模式一致

固定 D、初始 C 和合法回复序列。每种可执行指令及函数结果唯一，request 后只能由下一个明确回复推进。对步数归纳得内部轨迹及外部 trace 唯一，忽略宿主生成凭证。

设 E 将原生对象图映射为受控图的节点/引用表示，保持原始值、属性顺序、空洞、对象身份/别名和循环。若每次读取/写入满足 read(E(W),k)=E(read(W,k)) 和 write 对应关系，且模式不改变规则和步骤，则原生与受控机器以 E 构成逐步模拟；预算充足时外部轨迹相同。只有受控模式拥有额外保存/分支/记录能力，不把能力差异当游戏差异。

## 5. 分支非干扰

持久索引每个可写节点/页带所有权 token。fork 共享只读根并给双方新 token。读不写共享页；首次写仅在 token 不同处复制索引路径和目标节点/页。按写次数归纳，A 的修改不能改变 B 可达数据，反之亦然；共享定义 D 和不可变记录前缀不破坏结论。别名由本分支统一身份表解析，故写一处别名在同分支可见，在另一分支不可见。

普通对象只使用字符串字段容器，数组整数索引才使用分页容器；普通对象的空分页容器可表示为空值。对象读写、枚举、导出及回收从不访问数组分页，因此两种表示的可观察状态和可达边相同。fork 仅对存在的分页容器执行原分离操作，不改变对象字段的 COW 或数组分页边界。

属性读取可合并存在性和取值查找：字段容器无原型，分页也仅保存实际自有字段；读到非 undefined 编码值即蕴含字段存在，直接解码即可。仅在值为 undefined 时查询存在性，以区分“自有 undefined 屏蔽原型”与“缺失字段回退原型”。不改变数组 length、原型回退或分支中的对象身份。

推论：同回复的分支与原地继续等价，异回复的分支分别与各自独立执行等价。父关闭只释放自己的根，子分支无父链依赖。fork 不调用初始化/重放/序列化。根操作 O(1)，首次写成本为索引路径加目标对象字段/固定数组页；整个 Instance fork 若复制待决载荷或历史则不满足本结论，外层适配必须同时避免这一复制。

## 6. 保存恢复

仅等待或终局的完整边界允许保存。编码对从 C 可达的图给每个节点一个编号；解码先建立节点再连接引用，故保持身份、循环和别名。D 不编码，以明确规则身份及兼容格式绑定。若 decode(encode(C)) ≅ C，则由第 4 节，对任意相同后续回复有相同后缀 trace。无需重做 initialize，也不重放已完成外部作用。规则/格式不兼容、截断数据或未知快照拒绝；fault 不可保存。恢复时的停止态比较必须检查别名双射；Node 的 isDeepStrictEqual 仅有相同字段时可能接受不同别名图，不能承担该义务。实现复用边界 sameData，并有篡改别名的拒绝测试。

快照必须覆盖随机流、局部值、遍历游标、待决请求、发布游标，而不只是世界 JSON。这是在推导恢复定理时补入方案的必要条件。保存的宿主绑定不属于 C，恢复时为空。

## 7. Instance 协议细化

定义适配 A(C) 为现有 call/done/fault；Controller 为 call 分配凭证，并校验端口输入/回复。只有合法且属于当前调用的回复产生机器 reply；回调失败、取消、无绑定和非法回复保持当前等待，不计入成功返回。驱动租约保证一个实例至多一位活动驱动，transfer 撤销旧句柄，关闭后不可推进。

将 Controller 内部重试/绑定/检查步骤隐藏为 τ，则 Controller trace 投影为机器外部 trace。证明对每种协议操作分类：inspect 是隔离观察；bind 只改宿主绑定；run 要么保持等待/终局，要么接受一次回复并执行机器至下一边界；fork 用第 5 节，save/restore 用第 6 节。快照恢复分配新 InstanceId、保留待决 CallId及记录前缀，fork 分配新实例身份，跨分支 BaseGame 凭证必须拒绝。宿主生成身份只能做保持等值/引用关系的双射，不能规范化业务 ID。

停止态/记录的所有权引理：read(schema,x) 返回已隔离、校验且值保持的数据 y；后端没有 y 的别名，Controller 以后只替换停止态，不修改 y。公开 inspect/run 返回、宿主 handler 参数及 capture.read 均再次隔离复制。因此当前停止态与新 called/completed 记录可共享 y：任何协议观察都无法获得共同可写引用，对后续步骤归纳保持记录不可变。returned 同样保留验证后的私有回复，Execution.advance 则收到一份无凭证的独立副本；任意执行器修改回复也不能影响记录或沿用旧所有权凭证。started、fault 保留原隔离策略。该引理同样适用于旧后端，不改变其执行/语言语义。

## 8. 记录与重放

令 L=(setup,call₁,reply₁,…,done/fault)。记录器在 Controller 成功状态转移的同一线性化点追加记录，sequence 连续。拒绝/重试不伪造 returned，fork/restore 继承不可变前缀并在下一序号续写；记录前缀不是重新执行的活动。

重放在同规则身份 D 上从 setup 创建新实例，核对每个调用并注入 recorded reply，再核对终态。对 accepted reply 数归纳，第 4 节保证每次当前配置同构，所以重放得到原轨迹。相反，任意调用/回复/结果不匹配必须报告差异，不能只核对最终 winner；调用和结果用 sameData 检查值及别名关系，不能只用字段深相等。内部步骤记录是此确定轨迹的另一个投影，可附带检查；它不代替完整外部记录。

## 9. BaseGame 与两游戏等价

固定原 GameContract G，定义外层观察函数 O_G，合法性函数 V_G，事件投影 P_G。若新旧 Program 的每个端口载荷、顺序、回复及终局相同，且 G 相同，则 O_G/V_G/P_G 输入相同，确定输出亦相同。对 Instance 到 BaseGame 的绑定转移归纳，得到玩家请求、合法动作顺序、事件、接受/暂停、会话控制及终局同轨迹。非法或过期回复须在接受前拒绝。

Forge 的语义对应：主循环→repeat，发布→原 event，action→校验/开始/分支/收尾，attack→伤害/反击/死亡，卡牌→原定义步骤。斗地主对应：显式随机流发牌→同 LCG/Fisher–Yates，阶段循环→原 frame/事件/decision 顺序，input→校验/消费/动作或 clock。每个原语保持原实现的状态关系，再由组合定理及上述外层定理得到新旧轨迹等价。具体原语前提必须由独立旧参考差分及定向规则测试落实，本文不凭接口形式证明游戏规则正确。

斗地主 Frame 的局部复制可消除：旧机在事件前复制世界为 output.state；新机让 output.state 指向唯一世界。关系要求二者世界值相同，旧 output.state 的值等于新世界，output.events 为独立的成员数组。事件等待到下一决策期间，唯一修改是世界外的 published 游标和将 output.events 替换为空数组，不修改世界；故关系保持。每个宿主出口由 export 隔离数据，FrameSchema 仍在公开端口/终局校验。接受决策后，旧 output 不再被流程读取，下一轮先重建 output，故世界修改不会改变任何过去的宿主载荷或记录。按轮数归纳得到相同外部 trace。该优化依赖此具体阶段顺序；若后来在两请求之间插入世界修改，必须重新证明或恢复局部快照，不能推广为任意效果中的通用借用。

此关系还需要别名规范化，而不只是字段值相等：世界的 last.play 与审计事件、result 与终局事件可能共享对象；旧 FrameSchema.parse 会将它们变成分别拥有的树节点，外部 boundary 的值保持检查包含别名关系。故新定义必须在隔离导出之后，使用同一 FrameSchema.parse 形成规范 Frame；该纯投影不作用于活世界、不把投影副本重新登记到执行图，且对 decision/done 采用相同旧表示。令观察标签为 P_D(export(C))，P_D 是此静态纯投影，则外部图关系与旧实现一致。事件载荷采用原表示。没有这一步，直接借用世界的候选会被外层拒绝，不能视为正确优化；该缺口已在方案与实现中补齐。

还必须保持异常发生位置：不能把可能失败的 Frame 校验从 event 之前移到 decision。合法 setup/clock/timeout 允许 MAX_SAFE_INTEGER，stage 的 now+25000 可能越界；直接延迟校验会多发一批事件，因而不等价。实现采用可达状态不变式和保守回退：初始化经过原 StateSchema；发牌保持 54 张牌及各手最多 20 张；合法动作只移除已拥有的牌，play/pass 的形状、排序及阶段由原校验保证；每手牌至少移除一张，每次出牌至多两个 pass，故单副牌中每位玩家 playCounts≤20、bombs≤13、rockets≤1、评分指数≤17，评分均在安全整数域；阶段切换保证 ended 恰有 result 且 stage=null，其余出口恰有非空且 slot 唯一的 stage；events 始终由原 schema 合法的事件追加，当前批次按 published 截取。对这些原语归纳，唯一可能离开 Frame 数值域的是跨局 deal/stageSequence/boundarySequence 及 deadline 的累加。每轮在 event 之前检查这些值是否为安全整数；若否，调用原 frame helper 在原位置产生完全相同的异常；若是，上述不变式蕴含原 FrameSchema 必成功，才可借用世界并延迟规范化。now 由合法输入给定且 advanceClock 保持非负安全整数；第一次计数越界即故障，不存在越界后重新进入快速分支的执行。该证明仅覆盖由本规则初始化和合法回复产生的状态，不把任意伪造世界当作合法规则执行。定向差分覆盖初始极大时钟、clock 后 timeout、timeout 跳跃和 deadline 恰等于 MAX_SAFE_INTEGER，核对故障前完整调用和错误消息。

## 10. 证明审查产生的实现义务

实现必须落实：同一图保存世界与局部别名；forEach 捕获成员但保留身份；返回不能遗留子块；不兼容快照拒绝；不可变规则不被实例写入；记录线性化；外部 inspect 不暴露内部可变图；fork 包括 Controller 等待态/记录的隔离；异常现场不可保存；规则回调不使用隐式随机/宿主状态。上述义务已回填 card-core-spec.md。测试与结构检查需覆盖每项，未完成项只在 plan.md 保持未勾选。

入口迁移与薄封装的新增证明见第 11 节；代码检查与指标完成状态仍以 plan.md 为准。不能由 ReadView 类型推出直接共享冻结对象与原隔离副本等价，反射和保留引用的反例已进入正式测试。

## 11. 薄封装的细化义务

以下引理是实现的前置条件；证明完成与代码检查、性能达标分别验收。

用户后续明确选择 GameContract 纯只读借用，见第 13 节。本节中每次作者适配函数取独立可变副本的额外保证据此替换；schema、玩家和公开交付的隔离义务继续有效。

用户后续纠正了性能基准，见第 12 节。以下隔离与等价义务继续有效，但任何具体复制策略、Controller 记录实现或逐层调用形式都不是理论最优结构的证明；不能从这些引理推出原生必须默认维护记录，或为每个接口另持有完整世界。

**私有数据所有权。** 设 A 为活动世界及所有作者可保留的引用，H 为宿主公开交付的引用，Q 为框架私有规范图。准入复制建立 Q，故可写节点集合满足 Q∩A=Q∩H=∅。框架只替换 Q 根，不修改已发布 Q 的节点；内部停止态、记录及派生元数据可以引用同一 Q。每次作者回调和公开交付用保持对象图同构的复制器 E 建立新图 H'，于是 Q∩H'=∅；按交付和推进次数归纳，不变式保持。内部凭证只标记经隔离建立的根或由已拥有分量组装的根，不从 frozen/类型推断所有权。未知输入仍先拒绝 Proxy、访问器和资源，再归一化；凭证不附加到 DTO。若 project/parser 返回并保留对象，仍必须隔离其返回值。此处的同构包括别名、循环、空洞、特殊键及 Object.is 原始值相等。

**停止态复用。** Instance.run 的线性化点是接受回复并推进到稳定边界；其返回 state 与该点随后的 inspect 状态相同。BaseGame 独占已 transfer 的实例，refresh 期间不能有其他推进，故以 run.state 替换紧随其后的 inspect 是 τ 步消除。无接受、取消、非法回复的分支保留既有状态机；初次 bind 仍 inspect。由每次 run 的接受/非接受分类归纳，外部请求凭证、故障和终局不变。不允许通过忽略 run.pause 或绕过公共 run 来获得此结论。

**校验及回调隔离。** 每次逻辑校验保留同一 parser 的一次调用，传入与原基线同构的独立普通图，返回结果仍准入、隔离并与基线检查值保持。减少的是基线的框架副本和已准入数据的再次描述符扫描，不能删除自定义 parser/refinement。回调入参不能改为冻结的 Q：反例是 Object.isFrozen 和属性描述符读取，或保留入参后尝试修改。每次 receive/describe/observe/respond/projectEvent 仍在原逻辑位置调用，异常先后及可见事件顺序不变；同次校验内部的私有基线不交付作者。由各回调前后的图同构与相同异常转移，可逐回调组合推出完整外部 trace 相等。游戏内部冗余解析的删除另需可达状态不变式，不能由本引理自动推出。

**派生结果分支。** 设派生缓存 K=(view,requests,events,output,stop)，其数据分量都满足上述 Q 不变式。fork 共享这些只读分量，同时创建独立驱动标志、绑定表与会话 handler。请求身份中的 InstanceId 替换为子实例身份，CallId/key 保留；仅重建请求外壳。K 不包含活动规则世界，故其共享与 Core COW 非干扰可组合。若缓存只在真正产生新 view 的停止态更新，事件期间继续持有旧 view 与原适配行为相同；拒绝/取消不能更新有效期。复杂度是 O(请求数量)，与世界/历史大小无关。该等价要求契约投影为确定的只读函数；对带外部可变副作用的契约不得省去原有回调执行。restore 从快照重建派生值仍允许，但不得初始化或重放规则。关闭和替换清除私有缓存根，不能通过缓存建立历史版本链。


实现细化：私有 readOwned 在一次遍历中准入整个 parser 返回图并校对值、别名和键顺序；发现值不等仍继续准入余下字段，故不能让值不等掩盖非法 getter/Proxy。值及键序均等时返回未交付可写消费者的私有基线；键序不同则隔离复制返回图，保持既有表示。不能把作者可能保留的 parser 返回图直接当作私有值。DTO 快速复制只读取已准入的自有数据字段；输出写入按第 12 节对实际字段检查继承键，命中 setter/只读字段等风险时用 defineProperty，数组原型基底异常时全部使用 defineProperty，不再枚举或缓存整套原型键。因此不存在构造输出触发宿主 setter 的新增效果，且保持普通可变输出、空洞、循环及别名。

属性描述符的“数据字段”也必须检查为自有字段：原生 getOwnPropertyDescriptor 返回的描述符继承 Object.prototype，用 `'value' in descriptor` 会把原型上新增的 value 误认为数据属性。访问器可能因此被准入，甚至在随后读取时执行。所有准入及图存储检查须使用 hasOwn(descriptor,'value')，不能依赖宿主原型恰好没有该名字；这一修补保持正常数据输入的语义，拒绝原本就禁止的访问器。正式反例分别覆盖公开复制、私有准入、parser 结果及卡牌状态/导出。

未知输入的双份隔离可以合并遍历：准入每个源节点时同时分配私有基线 A 与 parser 入参 B，身份表存储源节点到 (A节点,B节点) 的映射；每条边分别写入 A/B 对应端点。由节点和边归纳，两图各自与准入复制同构，且彼此、与源图均无可写别名，原语值、键序、空洞和循环保持。自有描述符及非法值检查仍按原顺序完成，再读取并调用 parser；parser 只能接触 B。已拥有的基线仍只克隆一次。已知会自行隔离的 parser 可跳过备用 B；这一提示只减少分配，真实调用仍核对当前 parse 函数，提示过期时回退普通克隆，不能成为校验或隔离豁免。

跨层私有停止态可以直接转发。框架在调用既有 inspect/run 前核对句柄与实际方法均为 Controller 登记的原身份，仅对此次调用建立不可伪造的私有 receiver；原方法仍执行全部可用性、绑定、取消、校验、推进及记录逻辑，仅在交付停止态时识别此 receiver，转发不可变 Q。交接函数直接返回原方法的同一个 Promise，不增加 await/then 或微任务，保持取消检查的调度顺序。receiver 不传给执行器、parser 或 handler，普通调用及重入调用均不能取得它，故普通公开调用不能取得 Q；成功交付即消费，提前拒绝时只剩不可保活的弱键。BaseGame 的纯 GameContract 适配按第 13 节借用，玩家回调与公开返回继续复制。包装/代理方法不能取得 receiver；即使在返回前恢复原方法，也走普通公开复制及完整准入路径。公开 Instance 的字段、方法、可变返回语义和执行状态机不变，不增加公共推进接口。

BaseGame 向 Instance 绑定的内部回复函数只闭包读取已准备的 output，不使用调用输入或 context，也不调用作者代码。由框架专用构造器产生并以函数身份登记后，Controller 可省去其未读取的输入副本及调用参数；任意包装函数均不继承该性质。callback 的异步排队、取消、回复复制、输出 parser、记录及推进仍按原路径执行，因此外部接受/暂停顺序与回复隔离保持。该结论只针对这一具体框架函数，不从函数形参个数、类型、冻结或端口名称推断作者 handler 的行为。

树结构凭证只在完整准入或解析结果比较时产生：重复遇到任何对象就撤销树判定；外部交付的副本不带凭证，调用方增加别名或循环后再次提交会重新准入。已隔离且不再修改的树可以不用身份表复制，有共享节点或循环的图保留身份表。Controller 的小停止态只增加标量及新容器；BaseGame 每个请求的数据、观察和选项分别隔离，身份外壳全新，故在各分量均为树时可组合该凭证。exact 选项的成员属于私有规范图，只能复用为校验基线；每个 action parser 仍在独立副本上执行，不能从选项合法推断动作已检查。树已蕴含无环，框架 requireAcyclic 可复用该结构结论。

密集数组的后续复制优化以前置条件为界：对非 Proxy 的标准数组，所有自有键总数为 length+1，且 ownKeys[length] 恰为不可配置的 length 键，则整数索引已覆盖 0..length−1，且没有额外字符串/Symbol 字段。若此条件覆盖私有树中的每个数组，索引循环与按键复制等价；稀疏或附加属性的数组必须保留按键路径。宿主原型存在整数索引键或数组基底异常时，输出索引仍用 defineProperty，不能触发继承 setter。输入图不交给作者，凭证有效期与不可变私有根一致；外部提交必须重新判断，不能继承旧凭证。

该条件也可用于比较：私有基线的每个数组已证明密集，结果数组重新检查原型、自有键和每个索引的数据描述符后，可按索引比较；长度不等仍继续准入结果的全部成员，超过基线长度时不读取继承索引。数组键序由标准 ownKeys 的整数索引顺序确定，不需第二次枚举基线。普通对象仍枚举并核对全部自有键；只有本节点的键序及数量完全相同，才可复用已证明的字段存在性，省去随后逐字段的重复 hasOwn。任一条件不符均走原图比较，不省略 parser、自有描述符、别名或非法结果检查。

恢复必须同时检查位置、图一致性和声明 schema。一致的两份非法载荷不蕴含有效端口值；实现对恢复中的等待载荷/终局结果重新做静态边界校验，并检查 CallId 及停止态字段，不重新执行初始化或历史 IO。该修补覆盖原先“根与外部状态同时被破坏仍可能通过比较”的反例。本文保存恢复定理以合法存档为前提，不声称能鉴别任意伪造的、内部自洽的历史记录。

解析结果比较无需第二张反向 Map：维护源节点→结果节点的映射 F 与结果准入的 visited 集合。源节点已在 F 中时必须再次匹配同一结果；源节点第一次出现时，其结果节点不能已在 visited 中，否则发生合并别名。有效匹配下 visited 正是 F 的像集，因而二者一起保证双射；遇到形状/值差异时拒绝标志保持，仍遍历未准入的结果节点以保留错误优先级。该论证不要求两个图彼此不相交，同一对象可分别出现在输入与输出图中。这样复用了原本需要的准入集合，去掉反向 Map 的分配，不放松别名约束。

若私有基线已证明为树，F 也可省略：源图的每个节点只有一个到达路径，按字段对应的遍历不可能再次合法到达同一源节点。结果图出现重复节点必然引入原图没有的别名或循环，直接置不等标志；结果准入已有的 visited 集合足以检测它。结果的字段、原始值、键序和完整准入仍按原遍历检查，不因不等提前返回未检查的分支。非树基线继续保留 F。该条件只来自不可变私有根的树证明，外部提交和 parser 返回对象不继承凭证，故不能用过期树证明忽略新增别名。

斗地主生产适配器另有可消除的静态重复解析：决策端口的实际输入已经由同一 FrameSchema 在 Instance 边界规范化，BaseGame 又按 FrameSchema 建立私有 view；该 view 在下次发布前不变，作者拿到独立副本。于是其 state 已满足 StateSchema。生产 receive 可以借用自己的回调输入，随后仍由 BaseGame 的 view 校验隔离；describe 与 respond 可直接读取此已验证 state。legalActions、validateInput 等查询只读取 state，动作和控制的 InputSchema 校验、请求/期限及规则检查仍执行。此前内部 Frame/State 重解析对这些规范输入只作确定的复制并必然成功，不产生新的拒绝或 IO，故去掉它们不改变请求、合法动作、接受/暂停、事件或终局。GameContract 外部可替换的 schema/parser 仍在原逻辑边界调用；导出的独立 prepareAction/prepareControl 工具仍保留原有 StateSchema 校验。此证明只为原规则与匹配的生产契约成立，不给任意自定义 schema 或规则回调颁发豁免。

Forge 的 receive/finish 同理：匹配的 Core 已以 StateSchema 校验当前调用或结果，适配器借用自己的隔离回调副本即可，BaseGame 仍分别校验/隔离 view 和 result。保留正常终局必须有 result 的检查。旧适配器对同一已规范化 State 再解析只产生等值副本；新旧外部观察在 BaseGame 的再次隔离后相同。该消除位于已证明匹配的游戏生产适配器，没有改变通用边界对未知值及任意自定义 parser 的处理。

同一证明可用于生产观察、事件批次及合法动作描述的重复解析。BaseGame 在调用观察前已校验并隔离完整 view；两游戏的观察构造器只选择已验证字段、计算合法计数并按固定受众过滤事件。Forge 的手牌只出现在 hand，英雄摘要不再携带手牌；斗地主 Frame 已把 last.play/result/doubles 与历史中的对应对象拆成独立节点。因而每份观察中的节点不会因借用而产生原先不存在的别名，字段顺序与原观察 schema 一致。BaseGame 仍执行 observation/playerEvent/options 及逐 action 校验，并隔离返回值；可以省略生产回调内部必然成功的同一静态解析。斗地主的独立导出 observe/projectEvent 保留原解析，以维护直接调用工具的验证行为；当时生产构造器借用的是各次回调各自的独立 view 副本，第 13 节已将适配入参替换为稳定发布值的纯只读借用。原事件批次已经经过端口 schema，生产 receive 可以只读借用；终局同理仍检查 phase/result。合法动作由原 legalActions/plays 生成，槽匹配检查保留，最终 schema 与动作检查仍由框架执行。该消除不推广到可替换的自定义回调或任意未知状态。

固定游戏数据校验器可以使用当前锁定 Zod 版本的 compile 快路径，仍由同一边界执行完整 parse 及隔离/值保持比较，不替换卡牌执行器或编译卡牌流程。仅对本游戏已审查为纯、同步、无外部可写引用的 State/Observation/Options/Event 校验组合启用；成功结果与原 parser 的值、键序及别名相同，失败回到原 parser。该编译器在失败时可能先后执行快路径及原检查，因此不得自动用于任意作者提供的 refinement；默认游戏现有 Deck/Stage/Play 检查仅计算输入谓词或追加 issue，多次计算没有外部效果，且需比较最终错误消息。斗地主保留原 Frame 的一致性检查，只给其 state 子树使用等价快路径，维持 JSON 检查及出口别名规范化。原 schema 导出与通用测试入口保持原实现；优化只在专用卡牌及生产模块装配中选择，静态校验函数不进入实例根、快照或分支。无法支持的固定结构由库返回原校验器，不缩减协议范围。

回复交付修补：Controller 将验证后的私有回复保留在 returned 记录，给 Execution.advance 一份无凭证的独立副本，替代原先在记录端执行的复制。因此执行器可修改并再次发布回复，重新发布时必须走未知值准入；不会带着旧树/密集数组凭证绕过 getter 或循环检查。BaseGame 的控制转换器也只收到已验证控制值的副本，不能修改 accepted 中保存的原值。投影批次按自有索引的数据描述符读取，Proxy 或访问器不作为迭代代码执行；准备结果也先检查数据字段再读 valid。

受控存储的私有导出另可在构造时建立准入证明。仅当根为本图管理的节点、没有作者 project、且标准数组原型条件保持时启用；所有边都是已准入 Value 或已管理节点身份，导出器按数据字段构造普通对象，故无须随后再扫描整个结果来证明这一相同事实。导出时的身份表仍维护别名/循环，数组成员数及额外键决定密集性；父根为树/密集树时，其实际子图继承该结构结论，否则只继承所有权。公开 CardGraph 导出、外部回复和带 project 的导出不取得该凭证，仍走完整准入和隔离；schema 和结果保持比较不省略。

私有导出可以跨停止态共享只含原始值的叶节点。缓存键是实际存储行；每次赋值、删除及数组长度写入均在修改前删除该行的缓存。无子引用的叶节点不存在“只改后代而未失效”的反例；非叶不缓存，旧导出不再修改。fork 写入先取得分支独立的行，新行没有旧行缓存，父子不共享可写行或旧导出的可写引用；共享叶只在框架私有图内使用，schema/公开交付仍取得各自副本。不同节点行不会被合并，单次导出的身份表保持重复引用；空洞、额外数组字段、null 原型和特殊数值仍按原导出语义处理。失效不依赖有限精度的修订计数。缓存最初使用弱键映射，当前由第 14 节的非枚举行内派生属性替代；未被私有导出的行不添加此属性。缓存不链接父实例，不给 fork 或首次局部写入增加全图扫描；关闭解除行根后，缓存不能独自保留其行。

该共享还必须在批量记录出口隐藏：原卡牌导出为每个停止边界建立独立图，不能把多个记录一次图复制而暴露新跨记录别名。卡牌提供者因此按记录分别复制，单条记录内仍保持原有别名和循环；通用提供者保留既有整批复制行为。记录区间和游标不变，保存可以保留内部物理共享，恢复后公开交付仍采用同一独立边界规则。这是内部共享的必要细化条件，不能仅证明每次单独 inspect 有副本就声称完整捕捉协议等价。

原生停止态导出仍执行原来的 structuredClone，不能把原始规则对象直接当成准入数据。当调用的确为宿主原始 structuredClone、没有 project、且导出值确为当前 stop 时，可利用其新建对象的自有字段必为普通可枚举数据、无 Proxy/访问器/Symbol 键的构造保证。随后只需遍历节点检查标准对象/数组类型、别名和数组密集性，省去逐字段重复读取描述符。Date/Map/资源等非协议类型不取得凭证，交给原 Controller 准入产生原有 invalid_output；原生克隆抛错仍按原位置进入 program_failed。替换 structuredClone 时不使用构造保证；project 也仍拿无凭证的普通副本。回复复制不签发凭证，避免活动规则局部值修改后携带过期证明。该优化不改变 getter 在原生克隆中的原有执行次数、字段归一化、别名、空洞及公开可变副本语义。

已准入数据的原始值复制是恒等映射。私有复制循环可在字段读取后直接写入 null 或非对象值，仅为对象递归进入身份/数组处理；与原先调用 visit 后立即返回该原始值等价。此处不作原始输入准入，不扩展函数/Symbol 的准入集合，原始值的 -0、NaN、undefined 和 bigint 均不转换。每条对象边仍走原身份映射，保留循环、别名和稀疏键；输出仍保留继承字段写入防护。该改写只减少复制器内部函数调用，不改变静态代码与实例状态分离，也不增加跨版本缓存。

比较中的私有基线只有自有可枚举数据字段，Object.keys 的序列等于 for-in 再逐键 hasOwn 过滤的序列。可改用本次即时生成的键数组直接核对数量和顺序，省去逐键过滤；结果图仍重新准入所有描述符，基线键数组不跨次缓存。枚举函数在宿主模块装载时捕获，parser 不能通过替换 Object.keys 获得私有基线。稀疏数组只列出现有索引和附加键，不枚举 length，保持原来单独处理 length 的逻辑；继承可枚举键或 getter 不计入基线字段。

固定校验器的构造保证可用于既有 isolatedParser 能力，但不能推广到任意 schema。本次候选只覆盖两游戏已审查的有限严格数据结构：没有 any/unknown、递归 lazy、变换或资源；每个对象和数组均由锁定版本的 Zod 普通解析代码新建，原始值保持。非 assert-only 的 compileFn 先构造该节点的完整解析输出，再执行该节点的 refinement；现有 Deck/Play/Stage/Frame 检查只计算谓词或追加 issue，不改值、不保留参数。因此这些检查得到的仍是与私有输入无可写别名的普通新数据。成功输出是一棵无外部可写引用的密集树，可以在内部作为已准入数据比较，仍须校对完整值、别名和键序；不因同一 schema 身份省略这些检查。

INVALID 分支先复制私有输入，再调用原 parser 产生原错误；固定纯检查在失败时可先后执行快路径与原校验，两者没有外部效果。用户配置的错误回调不接触私有基线；若原路径成功，其返回值仍完整准入和隔离，不取得构造证明。异常、schema 替换和不支持的编译结构没有结果所有权证明。仅当输入本来是框架私有根，成功的新结果才取得私有证明；公开 schema.parse 和公开 read 的输入无证明，返回也不带证明，防止公开可变对象携带过期凭证。readOwned 仍调用当前 parse 函数，普通或替换 parser 保留原完整输入复制、结果准入及图比较。这里编译的是已有固定数据校验，不是卡牌执行流程；静态校验器不进入 Context 或快照。

结构准入还需逐层拒绝 any/unknown、lazy、coerce、变换和资源；只有明确列出的 Deck、Play、Stage、Frame 自定义检查函数可使用构造证明。新增加且未审查的自定义检查直接保留原 schema，不自动编译或授予私有结果能力。检查集合及遍历集合只用于装配，不进入运行时解析闭包。原始 schema 的 parse、safeParse、错误消息及生产 Frame 别名规范化另做差分；不支持的情况保留原路径，不拒绝作者使用它。

两份已证明私有、已准入的树可用专门循环比较：数组先比长度，只有两图全部数组都已证明密集时才按索引；其他节点比较全部自有键。键序相同即证明键存在，顺序不同仍逐键检查存在性，并保留 parser 的表示顺序。每个原始值使用 Object.is，对象继续递归；树中没有重复节点，故不需别名映射。任一图不是树时仍用完整双向图映射。此处省去的是通用反射和原始值递归，完整的值、形状、空洞、键序及别名约束仍成立。键序不同且 parser 结果已经私有时可直接保留该结果，无需再克隆一份；无该所有权证明的结果仍隔离复制。

## 12. 完整游戏成本与能力分离的新增证明义务

本节对应用户纠正后的目标，列出后续实现必须满足的命题，不宣称已证明当前代码达到它们。只改文档不构成语义、结构或性能验收。

**同等完整工作。** 定义游戏可见轨迹包含各玩家实际收到的请求身份、观察、合法选项、事件和接受结果，以及会话输入和终局。原生/受控使用同一规则包、契约和玩家/事件消费者，在相同显式输入下轨迹等价；受控记录与快照等能力按既有协议另外验证。只有端口与终局相同不足以证明计时工作量一致；预制回复带绕过玩家观察或事件消费的局部计时不能充当完整游戏下界。

**未启用能力消除。** 正常原生轨迹不得依赖未请求的调用记录、步骤轨迹、存档字节或 COW 版本元数据。去除这些维护后，玩家交互及独占驱动/取消/拒绝语义不变；不得误删游戏历史或真正参与续接的游标。已有可选 capability 未提供与提供后必须完整实现是两个条件，不能暴露 capture 后返回不完整记录。此命题的实现证据必须同时覆盖零构造/零追加和既有外部行为，而非仅断言没有读取记录。

**内部交接。** 若当前载荷满足第 11 节私有稳定值不变式，则在内部停止态、接口外壳和已启用的记录之间传递引用不改变可见轨迹，无需重建相同世界。新身份外壳只含相应请求元数据。未知作者回调与公开输出继续满足隔离；不能由这个命题推出任意 receive 返回值可直接与私有图共享。对原样投影的优化须另证回调输入/结果的所有权及校验行为。

**冗余计算消除。** 每一项被删除的原生解析、导出或历史扫描，须证明其结果已由当前同一逻辑边界的有效数据确定，且调用次序、错误、别名及自定义检查没有新增可观察效果；或者用等价增量算法完成同样工作。不能仅凭结果值碰巧相同删除有观察效果的回调。增加缓存时，其键、失效、分支隔离与释放也属于证明义务，不能另建一套长期持有完整世界的管理层。

**复杂度独立性。** 固定本次规则读写、请求数量及实际交付值，扩大不可观察且不被本次规则访问的世界部分，纯接口管理不得增加对该部分的节点访问或复制。受控存储寻址与分离成本单独按索引路径和触及的节点/页计；宽对象克隆、周期回收、首次推进的工作必须如实包含，不能把一次全图扫描平移到别的函数后声称消失。完整历史若实际交付则按输出量计费，重复历史计算仍需单独优化。上述命题约束计算的依赖范围，不把有限机器上的一次计时当成渐近复杂度证明，也不推导未经测量的 ms 下界。

**按实际字段保护输出写入。** 输出只使用新建普通对象、标准数组或无原型字典。普通对象写入前用 in 检查 Object.prototype 是否包含同名键；该对象的原型固定为 null，查询不会调用 getter 或 Proxy。标准数组基底为 Object.prototype 时同理查询 Array.prototype；若数组基底异常则全部使用 defineProperty，避免查询任意原型链。无原型字典直接写入。命中任意继承键时用 defineProperty 建立自有可变数据属性，未命中时赋值等价。因此不必预先枚举全部 Object/Array 原型键、维护键集合与失效缓存；检查仅涉及实际要写入的字段，__proto__、继承 setter/只读字段和稀疏索引继续保持。同步复制中没有作者回调，实际交付到下一回调后会重新判断基底与字段，不依赖跨调用缓存。这是待实现等价条件，不从该条件推断性能收益。

**完整可变回调快照的成本下界。** 此命题针对借用实施前附加的防御性保证，不将其冒充原始纯只读 GameContract 的必然要求。设 view 可达 n 个可变节点；若每次作者回调都可保留任意节点、任意修改，并仍须收到普通对象及自有数据属性，则不同调用与私有 view 不能共享任何可写节点。否则选择一个共享节点，令一次回调修改其字段，后续调用即可观察到改变，构成非干扰反例。因此一次完整回调快照至少要建立 n 个独立节点，时间和分配均为 Ω(n)；r 次独立交付为 Ω(rn)。未修改字段上的延迟代理、访问器或原型借用会改变普通对象/属性描述符行为，不能在这一保证下代替复制。运行世界的 COW 不消除宿主回调的这一下界。用户已确认纯只读适配语义，对应稳定发布图借用的证明见第 13 节；玩家和公开返回值的独立可变交付义务仍分别保留。该下界不再用于主张每次纯适配必须复制。

**准备输出的内部转发。** checkedPrepared 在同步检查数据字段后复制作者 output，得到作者无法保留的私有图 P。prepare 只将 P 交给私有驱动，公开 validate 不返回 P；该路径没有将 P 暴露给其他消费者。故 prepare 再复制 P 是不可观察的内部步骤，可直接转发 P。后续端口 schema、执行器入参及公开 accepted 的隔离保持，作者对原 output 的后续修改不能到达 P。

## 13. 用户确认的纯只读借用

用户已选择作者适配函数按纯只读契约借用稳定发布数据；该语义用于同一 GameContract 的原生和受控路径，不添加公共选项。令 A 为活动执行图，H 为玩家、公开读取及任意 schema 可写入的数据，Q 为已隔离、准入并发布的普通数据图。保持 A∩Q=H∩Q=∅，框架不修改已发布 Q，只在下一稳定边界替换根。GameContract 的 receive/finish/describe/observe/respond/projectEvent 及会话转换只读 Q，可返回引用 Q 的结果，不得修改借用数据或通过带外写入影响后续调用。该前提由用户确定的作者契约承担，不宣称自动沙箱证明，也不改为 Proxy 或冻结对象。

对同一纯函数 F，独立同构副本 E(Q) 与 Q 具有相同数据字段、键序、别名、空洞、原始值及普通可变属性描述符。F 不修改或用跨调用对象身份产生外部状态，故 F(E(Q)) 与 F(Q) 的值及异常转移相同。函数结果仍经过原逻辑 schema 的一次调用、完整结果准入及值保持比较；schema 只接触独立输入副本，玩家及公开输出仍取独立普通副本。因此借用不能让合法消费者修改执行图、私有记录或其他玩家数据。作者保留的只读引用在后续推进后仍指向旧 Q，不会变成活动世界引用。

已登记原 Instance 方法通过既有私有停止态交接提供 Q；未登记、包装或替换方法得到的公开值不自动取得该证明，必须先复制准入并仅在私有侧标记。卡牌私有导出把对象规范化为与公开 DTO 复制相同的普通对象，null 原型存储节点不使作者观察到此前复制不会暴露的原型差异；公开 CardGraph.export 仍保持其原有存储导出语义。私有叶缓存按行失效继续成立，不改变别名、特殊键和数组稀疏性。

按稳定边界归纳：基例由提供者隔离导出及 Controller 校验建立 Q；只读适配不修改 Q；schema、玩家及公开消费者只修改自己的图；推进只修改 A 并建立新 Q；fork 共享旧 Q 并重建身份外壳，restore 重新建立同一隔离关系，不重新初始化或重放程序。故可以组合得到记录、公开观察、玩家交互及继续执行的非干扰。只读借用本身只做根身份查询和引用转发，新增整图访问为零；既有 schema、真实观察构造和实际公开交付的成本单独核算，不能因这一证明宣称它们已经消失。

## 14. 发布缓存与原始对象索引的生命周期

叶节点缓存只依赖同一存储行的原始字段，可作为该行的私有非枚举派生属性。命中直接读行缓存；首次写在修改前删除缓存；COW 浅复制不复制非枚举缓存，父行及其旧发布值不变。快照、可达性和程序反射只读取行的 props/pages，故缓存不成为执行数据或新增可见字段，关闭和行回收也不依赖全局弱映射删除。语义与原弱键缓存相同，但下一次小量导出不再向包含无关世界叶节点的全局 WeakMap 写入。诊断观察到的高延迟发生在该写入调用内；这不是对 V8 内部扩容或回收算法的证明。

原始对象到节点身份的索引只服务一次完整导入及同一 IO 区间内的重复引用。构造根时先完成全图导入，保持全部别名和循环，随后可直接丢弃原始对象索引；已建立的身份通过实例数据引用和活动代理维持。每个稳定 IO 边界再用空弱映射替换索引，保留本分支身份分配器和持久行根。依据既有作者约定“不得保留已移交原生对象；跨步骤值通过局部槽或状态引用传递”，后续合法计算不再通过旧原始对象访问该身份，故不会丢失有效别名。回复每次先隔离，恢复只导入解码后的 Context；两者各自在本次导入中保持引用关系。替换索引是根操作，不遍历世界，不把旧表的删除/扩缩维护移到 fork 或首次写入；同一 IO 区间内新导入的 k 个节点的索引维护按实际输入工作计费。

fork 仅复制当前节点编号上界到子分支，复用子图已有的空导入索引；父子后续独立分配本图节点。继承节点的编号和持久行仍共享，新节点由各自 Context 解释，即使数值相同也不跨图混用代理。于是子分支的临时分配和关闭不会提高父分支后续寻址的编号范围或污染其原始对象索引，分支成本保持根操作，不引入重放、初始化或全图复制。

## 15. 可扩展规则的证明对象与不变量

本节至第 22 节对应 2026-10-20 的先建模后实施要求。证明对象是 card-core-spec.md 的可扩展规则模型，采用手工数学证明；没有使用证明助手验证，也没有证明尚未编写的 STS 实现。具体代码的符合性和完整原作规则等价性是独立义务。

为避免与此前 Q=待决调用混淆，重新用 C=(H,K,w,z,b) 记同一配置。D=(E,M,P) 分别为效果定义表、不可变规则元数据和端口声明；H 是有限可变图，K 是调用/结构帧，w 是待决请求，z 是运行状态，b 是预算。规则队列 J、登记表 T、RNG 状态 R 和冒险状态 A 都是 H 的子图，不是多个运行世界。外部标签沿用 call/reply/done/fault，并在协议层包含拒绝与玩家交互；内部规则事件仅在实际发布到端口时才成为外部标签。

对合法配置要求：

1. **状态闭合。** 所有影响后续规则、选择、观察和随机结果的可变值都在 H/K/w 中。D 与宿主绑定不保存可变游戏数据；派生缓存若在此之外，必须证明删除或重建它不会改变转移。
2. **位置有效。** 活跃帧、队列项、触发器和续接中的 effectId 能解析到固定 E；等待目标是存活帧。已终止的实体引用允许存在，但其读取必须按规则返回离场值、缺失结果或明确故障，不能暗中复用 ID 指向新实体。
3. **确定调度。** 每个运行配置只有一个当前步骤；同一时刻的次序由规则或显式玩家输入决定。相同输入、显式 RNG、数值语义和登记顺序产生相同选择。
4. **所有权。** 本实例内身份和别名一致；跨实例只有不可变数据或具有完整写屏障的物理共享；公开可写数据不能回写活动图。
5. **输入线性化。** 当前请求只消费一次已校验回复；过期、非法和跨分支回复不改变游戏状态、RNG 或续接。回调失败不伪造成功返回。

第 1 项约束尤其针对静态 TS 函数：冻结函数对象不等于冻结它捕获的环境。捕获可变计数、使用 Math.random、依赖外部容器迭代状态都会构成反例。当前 Card Core 对受信任同步函数不提供自动沙箱证明，必须审查规则实现。单个同步 operation 有限终止是预算有效的前提。

## 16. 表达能力：构造性编码与闭包数据化

**定理 15（有限前缀可表达）。** 一个规则程序若使用有限定义的控制流、有限可达数据、确定基本运算、动态调用及显式交互，则在基本运算可由当前同步 operation 精确实现、跨交互数据可按图编码的条件下，可用现有 CardStep 表达其每个有限执行前缀。不需要为卡牌、敌人或遗物增加指令。

**构造。** 对顺序、分支、循环、调用、交互、返回，分别使用现有步骤组合、branch、repeat、invoke、request、return；表达式结果进入 input/locals/state。任意有限控制流图的基本块可登记为效果，导入器在 locals 中保存下一块标识，用 repeat 与动态 invoke 选择下一块；块末只设置后继或返回。调用以实际 invoke 建立独立参数和返回帧，不能把所有递归共用一个 PC。这样不可归约跳转也有表示，不要求作者手工展开路径或填写 PC。

数据方面，记录/数组映射为普通图节点，指针/对象身份映射为图引用或稳定实体 ID；共享引用与循环保持。有限标签联合可用数据字段表示；整数宽度、浮点舍入及特殊值必须显式选择匹配运算。该构造不允许把“整个未知源程序执行器”当作一个已经正确的 operation，从而省略基本运算语义检查。

**证明。** 建立源状态与目标状态的关系 R：数据图对应，当前块和局部值对应，每个源调用具有对应目标调用帧，待决交互及返回目标对应。初始编码建立 R。按下一条源步骤分类：运算使用对应基本运算；分支选择同一后继；跳转更新下一块；调用建立独立帧；返回消费该帧；请求停在对应返回槽。每种情况由有限个目标内部步骤完成，并保持 R；反向除去导入器的管理步骤后只得到该源步骤。因此按源步数归纳，所有有限前缀的可见标签相同。额外管理步骤不能自行无限循环；生成的每段管理路径有限，故不会引入纯管理发散。□

这里“有限可达数据”指每个有限时刻使用有限内存，不设固定调用深度或固定机制名单。结论不证明任意程序终止，也不覆盖超出数值/数据准入范围而尚无正确编码的宿主对象。生成导入代码与现有声明作者写法分开；作者继续使用组合器，无须维护 PC。

**引理 15.1（闭包数据化）。** 对静态可枚举的闭包代码体，把活动闭包写成 `〈代码身份, 捕获环境〉`，并保留捕获的值/引用语义，可以保持调用行为及跨等待续接。

**证明。** 每次创建闭包时，为其代码体取固定身份，按源语义建立环境。按值捕获复制该值的语义表示；按引用捕获保留同一存储位置；两个闭包共享的可写捕获变量必须映射到同一位置。调用时查找代码并绑定该环境，变量读取/写入与源闭包一一对应。对闭包体的步骤使用定理 15；等待时环境仍可从 C 到达，恢复后对应关系不变。□

这适用于 sts_lightspeed 中源位置固定的 ActionFunction 和 regainControlAction，但并未证明每个实际 lambda 的捕获都已转对。C++ 的对象按值复制、内部引用、对象寿命与 `this` 捕获需逐个确定；一个通用浅拷贝不能代替这个证明。运行中生成“新牌”可生成新实体及组合数据；需要新的算法时修改/装载规则代码，不能据此声称当前装载器支持运行中任意注入新代码。

## 17. 调度、触发、替换与组合

设队列 J=[a₁,…,aₙ]，每个 a 为数据化效果。定义规则操作：

```text
front(a,J) = [a] ++ J
back(a,J)  = J ++ [a]
take([a] ++ J) = (a,J)
```

这只是队列的抽象语义，不规定用 Array.shift 或整数组复制实现。调度器取出 a 后将它放在当前调用帧中执行；直到返回，才再次选择待执行项。

**引理 16（队列与当前续接保全）。** 队列操作按上述语义实现，且当前动作经 invoke 执行，则入队顺序、嵌套调用、暂停后的剩余动作不丢失、不重复。

**证明。** 对调度次数归纳。take 仅移除头元素一次，剩余顺序保持；当前项由调用帧持有，故不会因从队列移除而消失。立即调用仅扩展 K，不读取下一队列项；入队仅按定义改变 J。request 保留 K/J，回复只恢复当前项；返回后才进入下一轮。故结论成立。□

反例说明为何不能混用：当前动作 A 先把 B 入队，再做 C；队列语义为 A 内的 C 完成后执行 B，直接 invoke B 则 B 先于 C。若 C 改变 B 读取的伤害值，两者结果不同。

触发派发可以采用捕获列表模式。令 `L=order(select(T,event,H))`，把 L、事件捕获值及游标 i 存入帧。每次执行 L[i] 前按该规则的 eligibility 决定继续或跳过，再前进游标。L 固定成员次序不意味着成员必然执行；注销、来源离场与资格重验由明确谓词决定。需要实时加入新触发者的机制改用实时选择算法，并将 processed/游标等完整保存。

**引理 17（派发可组合）。** select/order/eligibility 和捕获策略确定，且处理器满足定理 15，则派发轨迹确定；处理器内部请求、登记和注销不会使派发续接变成宿主隐藏状态。

**证明。** 捕获模式的 L 和 i 是有限数据；下一项与资格判断唯一。每个处理器正常返回后 i 只前进一次，暂停则 i 和调用帧同时保留，fault 不进入后继。实时模式同理，但以其显式选择状态而非固定 L 作为归纳不变量。新登记项是否进入本轮完全由该选择函数决定。此结论不额外保证实时模式最终结束。□

持续修正的简单情形为有序折叠：

```text
v₀ = base(H,x)
vᵢ₊₁ = modifierᵢ(H,x,vᵢ)
```

纯查询不改 H。对 i 归纳得到确定结果；次序属于规则，不能默认交换。例：基础值 5，先乘 2 再减 3 得 7，反序得 4。若修正之间存在循环依赖，需要另证求解语义：单调函数作用于有限高度格时，从底开始迭代可得到最小不动点；没有这些前提，`x=1−x` 就可能反复振荡。模型因此要求规则定义分层、合法求解法或故障，未把任意回调集合称为可求解系统。

动作替换可以表示为 `〈原动作, 当前动作, 已应用登记实例, 当前选择〉`。每次求适用集合，按规则排序或 request 选择，再 invoke 替换并更新该数据。对替换次数归纳可证明每个阶段都保留完整续接；若规则禁止重复，已应用集合保证同一登记实例不重复。动态添加无限新替换不保证终止，故有限集合去重不能被误用为普遍终止证明。

卡牌、敌人和遗物只是这些规则的不同定义与登记来源。游戏专属逻辑写在规则代码中是必要业务语义；将同样的逻辑写进 CardMachine 的牌名判断才是违反分层。以上构造也允许规则引入全新事件、查询和阶段，无须修改 VM 的指令分类。

## 18. 动态状态下的模式一致、恢复与 fork

本节把第 4–6 节的结论延伸到队列、动态登记和完整冒险，明确其前提，避免仅保存棋盘却引用旧定理。

令 `L(S)` 为某种物理存储 S 的逻辑图。要求每个准入读写都满足：

```text
L(read/write_native(S,a)) ≅ L(read/write_cow(E(S),E(a)))
decode(encode(C)) ≅ C
L(fork(S).parent) = L(S) = L(fork(S).child)
```

第一式表示对应操作及其返回值/后继图一致；≅ 保持业务身份、别名、序列、数值、帧与等待，不能只比较可见血量。静态定义相同，代理不得作为分支判据，不能依赖宿主对象地址。

**定理 18。** 若第 15 节不变量与上述存储条件成立，则资源充足时：

- 同一规则的原生与受控执行在相同输入下具有相同游戏轨迹。
- 任意允许保存边界恢复后，后续轨迹等于原地继续。
- fork 后只推进 A 不改变 B；相同输入的分支分别等价于独立继续。

**证明。** 对下一步分类。计算只读对应值并写对应位置；调用操作对应的 K；队列和登记操作只读写对应 H；随机数是对应 R 上的确定变换；请求保存对应 w，回复消费对应 w。由逐步归纳维持逻辑图同构，得到两模式一致。编解码后同构给出相同归纳起点，得到恢复。分支中读不改兄弟，写屏障先建立私有版本，包括队列、登记、计数、局部值和 RNG，故按写次数归纳兄弟图不变；再应用确定性得到各自后缀等价。□

若省略任一跨等待数据，结论可能立即失败。例如：选牌前已从队列取出一项，仅保存剩余队列，恢复后就会漏掉当前动作；只保存触发列表、不保存游标，恢复会重复已经触发的效果；登记表放在模块 Map，子分支注销会影响父分支。方案已要求这些数据归于 H/K。

保存中 effectId/块身份必须绑定同一兼容 D。新增内容后的 D' 不自动能读取旧快照；定义扩展的语义保守性不能代替现有规则身份/快照兼容校验。公开凭证仍由现有协议处理，业务实体身份不能用凭证重命名规则抹掉。

## 19. 扩展保守性、协议细化与完整 run

**定理 19（不适用扩展的保守性）。** 将 D 扩展为 D'，若旧定义及旧初态不变、新效果身份不覆盖旧定义，且在所考虑的整个旧执行上：新增规则不被调用或登记、不参与选项/生成池/查询/排序，纯索引不会改变旧次序，则资源充足时旧执行的游戏轨迹保持。

**证明。** 用同一旧逻辑配置作为关系。每个下一步查询、调度和定义查找均落在未改变部分，新增定义不会被读取；因此对应转移与后继相同。归纳覆盖整个旧执行。□

只在初态“不适用”不够，后续生成池可能抽到新牌；只是不直接调用也不够，遍历“所有牌数量”会读取新增内容。这些情况是有意改变规则，不满足定理前提。定理保证无需修改 VM 便可扩展，不保证新增遗物后仍保持旧平衡或原作结果。装载成本可随规则数量增加，不能从轨迹相同推出装载时间不变。

对 BaseGame 令 A(C) 为既有端口投影，Oₚ 为玩家观察，V 为动作校验。合法动作域定义为 `Legal(C)={a | V(A(C),a)=accept}`。exact 选项须在约定表示下与 Legal 相等；construct 必须有覆盖 Legal 的编码与校验。允许多种等价动作表示时，按明确的游戏语义等价关系比较，不得任意删选项。

**定理 20（外部细化）。** 若运行状态对应、端口标签对应，且同一纯 GameContract 的投影和校验保持该对应，则合法动作接受、玩家观察、事件顺序与结果对应；非法动作拒绝不改变运行状态。

**证明。** 在每个停止边界，A 的输入对应，确定纯投影得到对应外部状态；同动作得到相同校验结果。拒绝不调用推进器；接受只向对应等待交付一次回复。定理 18 给出下一边界对应，故按接受次数归纳。隔离复制/只读借用义务沿用第 13 节。□

动作完整性必须另核对；例如多选有 2^n 个合法子集，只返回空集仍能执行，却违反 Legal 等式。该反例已用于修正直接复用上游搜索动作枚举器的方案。

隐藏信息还需要独立的关系论证。状态有别但对玩家当前应当不可区分时，观察、请求、选项、拒绝信息等都应一致，直到规则允许披露。只删 RNG 字段不能证明这一性质；合法选项和事件时机同样可能泄漏。该义务由具体规则和投影实现承担，Core 的可复制性不授权策略读取全状态。

完整 run 表示为主效果对地图/房间/战斗等子效果的调用。战斗 return 返回冒险调用者，只有主效果 return 发布完整 run 结果；事件中的选择和房间结束续接使用同一 K。由调用组合引理，子效果正确与明确阶段转移可组合为任意有限 run 前缀正确。初始状态包括完整开局条件，目标成功谓词为该规则版本的 A20 心脏完成条件；Act 3 结束而未满足目标有独立结果，不被主效果误报成功。预算故障/外部截断不作为游戏死亡。本结论尚需实际各房间与战斗规则的局部正确性，不能用空壳阶段跳转代替它们。

## 20. 终止与复杂度能证明到哪里

任意机制允许循环与动态生成，所以不存在对所有规则程序的终止保证。有限结算段若有自然数或良基序上的秩，且每个宏步骤严格下降，可以证明该段终止；纯查询的有限折叠是一个直接例子。没有秩的触发循环只能由预算停止并报告资源失败，不能算作游戏负方。

现有预算覆盖 CardStep；有界同步 operation 结束后才检查下一步。故能证明在有限个有界操作后到达等待/结束/预算故障，不能推出毫秒硬超时，也不能阻止一个违规 operation 永久循环。多等待的整场 run 还依赖外部持续回复，不能由内部步数界推出完整游戏一定结束。

设 t 为实际执行的控制步骤数，cᵢ 为第 i 个规则运算/存储操作成本，u 为真实交付数据量；不含可选持久化，抽象执行时间为 `O(t + Σcᵢ + u)`。规则队列或派发的成本须计入 cᵢ：若按主题索引返回 k 个候选，枚举至少 Ω(k)；若要排序则另计排序成本，不能无条件称为 O(k)。不扫描不适用内容的实现可避免随全部静态牌库线性增长的每步成本，但这属于需落实的结构条件。

逻辑空间为业务活跃图、未完成动作及捕获数据、登记表、调用帧、规则要求保留的历史之和；没有因 Core/Instance/BaseGame 分层而必需的三份世界。COW 的实际寻址/首次写成本、图回收、记录和快照另计。完整快照至少读取所需状态，真实输出全部候选也有其输出下界。本文没有证明当前实现达到所有理论下界，不从这些公式推导 ms、RSS 或 GPU 利用率。

## 22. 证明反馈与当前结论

本次推导已将下列必要修正写回规格：

| 原本不充分的设想 | 反例 | 模型修正 |
| --- | --- | --- |
| 事件名＋回调即可通用 | 持续费用修正、替换后重新判断不等于事件通知 | 查询、替换、触发均可用完整规则流程定义 |
| 待执行函数换成效果 ID 即可 | 只保留 ID 丢失按值捕获或共享引用 | 明确环境、身份、捕获及离场语义 |
| 队列和调用栈可以合并处理 | 入队 B 后继续 C，与立即执行 B 次序不同 | 明确当前续接与待执行工作，两者同属 Context |
| 触发者消失就删除效果 | 已排队效果可能依赖离场前值继续执行 | 规则决定资格和最后已知信息 |
| 处理器排序一次就永远有效 | 结算中登记/注销、玩家选择排序 | 明确捕获/实时选择与游标、重验策略 |
| 有界步预算保证任何 JS 可停止 | 一个 operation 内无限循环 | 受信任有限操作前提；不声称硬抢占 |
| 完整状态可 fork 就能用于合法策略 | 状态含隐藏牌序、RNG、未来遭遇 | 观察/候选/事件独立证明信息边界 |
| 参考能跑到结局即完整原作 | 禁用内容、缺少多选、截断当输局 | 内容修正规范与完整 run 结果分离 |

设计结论：已有控制流与图状态模型足以表达上述机制；在明确前提下，组合、动态调度、模式一致、恢复、分支和外部细化有手工证明。证明没有给出自动终止、自动宿主隔离、完整 STS 内容正确或实测性能的结论。

当前尚不能把“整个 STS core 已确定无误”作为事实。下一步先确定 STS 规则与参考差异，落实各机制的局部状态关系与顺序，再编写这些已经明确的规则模块及其正式检查；最终以真实完整 A20 run 验收。阶段进度只在 plan.md，本文不建立另一份证明完成率清单。

以下只落实已迁移的正常开局、邪教徒首战与战吼待决选择，不证明其他内容或完整 run。源冒险 A、战斗 B、动作队列 Q、出牌队列 K 和输入阶段 I 对应到同一 Context 的 game/battle、具名效果队列和 Card Core 帧。长期牌与战斗副本保持源身份、随机流和退出回写关系；Core/Instance/BaseGame 不各持一个世界。

## 23. 迎战与风暴领域的构造和不变量

本节证明的是规格中明确标注的规则细则；用户已确定风暴领域只抑制敌人非力量的正面状态。混合意图与时效处理使用明确的实施默认，不视作用户逐项确认。改变这些细则需改对应规则，但以下数据/控制能力不需要新增 opcode。

**定理 21（一次机会不重复启动）。** 对每个唯一 slotId，规则只允许 `pending→running→resolved` 或 `pending→resolved(cancelled)`；只有 pending→running 可以启动意图，转换在首次调用/排队前的同一有界同步操作中完成，且没有回到 pending 的边。则在同一分支任意执行前缀中，该机会的启动次数至多为 1。

**证明。** 初态启动次数为 0。唯一增加启动次数的边同时使状态离开 pending；之后没有回到 pending 的边，所以不可能再次走该边。所有其他规则转移不增加次数。对步数归纳即得。正常且未被取消的机会，在调度最终访问且资源充足的条件下启动一次；中途 fault 不保证完成，不能将“至多一次启动”夸大为必定成功。□

迎战将这个唯一启动安排在玩家回合内；原定时点看到 running/resolved 时不再启动。在等待点保存 running 和 K 后，恢复从动作中间继续，不调用启动边；保存 pending 的分支可独立启动，不与另一分支共享消费状态。这里的唯一性是每条逻辑分支内的规则性质，不承诺跨进程外部服务的 exactly-once。

回合生命周期与意图执行分离：对指定生命周期里程碑也保存已处理位置/标识，阶段转移只前进一次。提前执行意图不自动越过这些里程碑。由相同的单调状态归纳，可排除重复扣毒、重复清格挡、重复抽取下一意图等由重复执行生命周期引起的问题；具体里程碑顺序仍由规则定义。新意图不得覆盖尚未收尾的机会记录，额外回合必须引用规则分配的正确机会。

**定理 22（领域内能力抑制）。** 设 T 是敌人状态集合，F 是存活领域登记，`enabled(s,H)` 综合状态寿命与规则抑制。按用户进一步确定的范围，风暴规则规定当 F 非空时，敌人的非力量正面状态不 enabled，负面状态不受本领域抑制；正负分类来自规则定义，不能用层数正负代替。假设所有状态产生的规则贡献均在实际使用时经过 enabled 检查，包括属性查询、能力派发、替换、已排队及暂停后继续的贡献；纯生命周期管理不作为能力贡献。则 F 持续生效的执行区间内，被抑制状态不会新增这些规则贡献。

**证明。** 对该区间每个规则转移分类。基础动作不由这些状态贡献；状态贡献必经检查，而谓词为假，转移只能返回中性/取消结果且不执行贡献；生命周期只管理寿命和登记，不绕过检查产生战斗效果。故单步不增加被抑制能力的贡献，归纳得到区间性质。进入领域之前已经提交的结果不在命题内，领域结束后也不补执行被取消的效果。□

“中性”由操作语义决定：加法修正不加，乘法修正不参与，触发不执行，替换不生效；不能一律把 amount 设为 0，因为 0 并不是任意效果的中性行为。仅在派发入口检查一次不满足前提：效果已排队或中途等待后领域开启，其余贡献仍可能漏过。规格因此补入执行时重验与来源关联。

关闭领域不需要重建状态。原始 T 一直保留，期间的正常到期/移除已作用在 T；删除对应 F 登记后，仍存活且不被其他领域抑制的状态才重新 enabled。按存活集合计算抑制，天然避免双领域只结束一个就全部解封。力量只是免受本领域抑制，仍受其自身正常生命周期约束。

**动作过滤性质。** 将意图程序的业务片段标注为攻击/非攻击等规则类别，准备、数据依赖与清理保留。在领域内，每个非攻击片段进入执行前被替换为显式 cancelled 结果，后继按该结果继续或短路；则按片段执行序列归纳，只有允许的片段能产生其业务效果。该证明要求分类覆盖所有路径、来源随延迟子效果保留，不能从伤害指令或展示图标推测语义。若整项意图过滤更符合最终卡面，使用相同构造对根片段判定即可。

组合时，机会状态决定是否还能启动，领域谓词决定启动后哪些贡献生效，两者管理不同语义。取消内容仍把机会结算完毕；领域结束不会把 resolved 改回 pending。因此“领域内迎战纯强化→提前落空→回合末不再强化”成立；混合意图按明确过滤策略处理。两个机制的全部动态数据都在 H/K，满足第 18 节前提后直接继承保存/fork 和双模式一致性。

实现反例边界：敌人 operation 直接写 HP/格挡/状态并绕过语义入口，或直接读取被抑制状态的 raw amount，会使定理 22/动作过滤性质的前提不成立。需要在规则层建立共同的行动结算和有效状态访问函数，而非在 VM 增加“如果风暴领域存在”的分支。当前结论是模型支持且有条件构造证明，尚未实现或测试这两个机制。

## 24. 类型化第二层的证明对象、链接与控制流降低

本节及第 25–27 节先于第二层实现完成，针对 card-core-spec.md 的类型化设计和模块扩展契约；不是已有代码正确性的声明。令静态定义集合 D 有限，数据图 H 含所有实例可变状态，执行配置 C=(H,K,w,z,b)。定义身份和 Local 是装配期符号，π_D 是定义到内部索引的单射，λ_f 是效果 f 中局部槽到内部键的单射。动态环境仅含可编码数据或同图实体身份，不含定义对象或函数。

作者语言 P 的构造为 literal/read、assign、sequence、when、while、forEach、call、return、choice、受权 atom 和上述构造的递归定义。read 与 atom 是确定且有限的可信计算，不能取得宿主状态。作者的语义由这些构造的小步规则定义；它不是原生 JS 栈的快照语义。choice 发出类型化请求并等待一次合法回复。依赖模块可以增加 atom/组件/时点，但不能增加未经定义的宿主调用。

**定理 23（静态链接身份与签名保持）。** 若 π_D 和每个 λ_f 单射，所有静态引用属于 D 且签名相容，链接规则只通过对应映射降低定义引用和槽，则定义比较、调用目标和槽读写保持作者语义。相同 label 不同定义不会串线。

**证明。** 单射给出 π_D(x)=π_D(y) 当且仅当 x=y；λ 同理。call(f,a) 降到 invoke(π_D(f), encode(a))，装配时输入/输出签名检查保证接收方相同。局部读写均用 λ_f，所以原先不同槽不能覆盖。帧为每次 call 创建独立 locals，递归调用不共享可变槽值。未绑定/异 Program 引用不在映射域内，应拒绝而非查 label。按结构递归，所有静态引用保持。□

TS 的签名检查与链接器的成员检查是此定理前提。任意 any/强转不能据此获得安全证明；不透明 read 回调中读取未赋值或外部槽的情况须在运行期检查，不能假装静态 TS 已证明确定赋值。

**定理 24（降低的弱轨迹模拟）。** 不计链接器内部辅助步且双方预算充足，作者 P 与降低 L(P) 的请求/合法回复/正常返回/规则故障观察轨迹一致。关联 R 将作者环境映射到 CardFrame.input/locals，将作者调用续延映射到 K，将领域数据映射到同一 H。

**证明（结构归纳及递归调用步数归纳）。** literal/read 在一次有限 operation 内求得相同值；assign 的有限计算或子调用写入对应槽。sequence 串联归纳关系。when 在同一数据上取同一布尔分支；while 降为 repeat，每轮在相同 H/环境重算条件，零轮和 k+1 轮由归纳成立。forEach 首先捕获有限项序列，并在 locals 保存序列/游标；repeat 依次执行当前项，暂停时游标不变，返回后只递增一次，保留嵌套词法环境。call 降为 invoke，独立帧持有参数和 locals，结果通过目标槽返回；return 降为 Card return，丢弃当前调用的结构块而不结束其他调用。choice 在 request 边界保留同一数据和续延，合法回复写相同槽；非法回复在外层拒绝，二者都不执行后继。atom 的模拟由定理 26 提供。任意有限递归前缀使用更短子调用前缀归纳，不需假定全局递归终止。因此每个作者可见步对应有限个机器辅助步，反向删除辅助步得到同一轨迹。□

辅助步消耗真实内核预算，因此不声称相同步数预算下任意两种降低布局在同一时刻截断。预算故障保持 fault/truncated 分类；不能据语义模拟取消预算检查。无限 while/递归不保证终止，有限硬件资源也不由数学模型消除。

## 25. 规则模块写权、提交与事件一致性

令 owner(c) 是受保护组件 c 的唯一静态所属模块；caps(f) 是由链接器赋给 atom f 的读/写/事件能力。提案 T=(W,E,r)，W 为有限写集合，E 为有限有序事件，r 为返回值。V(H,T,f) 同时检查输入/结果/值 schema、实体资格、写权、无重复目标及模块不变量。V 和 run 都不修改 H。应用 A(H,T) 在无规则观察的一个同步步骤中写 W，并登记 outbox(E,r)。

**定理 25（写权保持）。** 若 atom 执行前只有 owner(c) 的有效 capability 能写 c，V 检查每个写入且能力不可由动态数据铸造，则任意运行前缀中第三层或其他模块都不能通过合法接口写 c。

**证明。** 初态满足所有权。组合、查询、选择、登记均不产生对 c 的裸写；唯一可能写 c 的 atom 必须通过 V。若 owner 不匹配，V 拒绝且不变 H；若匹配，写入者是所属模块。公开依赖只导出效果/查询和挂接句柄，不导出 owner capability，所以 install/订阅/调用不能扩充写权。对执行步数归纳。实体私有组件以同样方式增加来源/实例归属条件。□

能力必须是链接器验证的静态身份，不能接受输入中的 moduleName 或 componentIndex 当作权限。可信 TS 故意绕过接口裸写不满足命题前提；实施必须把裸写限制在内部文件并验证真实依赖边界。

**定理 26（有效提案保持不变量与事实一致）。** 设 I(H) 成立；每个通过 V 的提案满足 I(A(H,T))，应用阶段没有作者回调、无中途交互且存储应用正确，则成功提交后 I 仍成立；验证拒绝时 H、outbox 和 RNG 均不变；不存在事实事件先发布而对应写入尚未提交的可观察状态。

**证明。** 拒绝发生于任何写入前，run/V 只读，所以状态和流不变。成功时 V 的后置条件直接给出不变量保持。W 与 outbox 在同一步产生，应用期间无观察，发布器只从已登记 outbox 读取，故每个事件都对应已提交变化。事件派发可暂停，但暂停时 W 和 outbox 已在 Context；不影响提交事实。□

V 的局部 schema 不能自动证明任意跨模块全局 I；模块必须将涉及自身组件的不变量具体化，共享结构由唯一拥有模块维护。存储应用期间 OOM/实现错误不受此定理保证，沿用 fault 锁定且不可存档，不承诺任意异常回滚。多 atom 组合只保证逐步不变量，不是全效果事务。

**定理 27（outbox 可恢复且不重发已消费项）。** 若已提交事件项有唯一逻辑身份，dispatcher 的列表/游标与当前调用帧全在 H/K，游标只在规定的消费点单调前进，恢复不重新执行 commit，则恢复后的事件/后继效果轨迹与未恢复一致。

**证明。** 暂停时列表、游标及未完成调用都被保存。恢复从相同帧继续，不重复运行已经完成的 commit，也不回到较小游标。当前项尚未完成的剩余部分依帧执行，下一项依相同游标选取。对剩余项数及每项控制步数归纳。□

此性质仅是实例内重放/恢复语义，不是远程宿主服务跨崩溃 exactly-once；外部副作用仍走已有端口协议。

## 26. 派发、替换、纯查询和扩展机制的构造

**定理 28（派发与替换可用现有指令构造）。** 有限候选列表、数据化环境、确定排序和显式资格策略的事件派发；以及携带已应用登记身份集合的动作替换，均可表达于作者语言 P，无新增 VM 指令。

**证明。** 派发用 query/atom 获得按规则排序的候选快照，写入 Local 序列；forEach 逐项检查资格并 call 对应 Effect。每次调用参数由定义索引和环境数据解码，游标与局部数据由定理 24 保留；事件中新安装项不在快照，注销是否影响已有项由资格谓词决定。替换用 while 保存动作载荷、已应用集合和当前候选；取最先适用且未应用项，先登记其实例身份，再调用其替换 Effect；keep/change 更新显式数据，cancel 返回判别结果。每次重算候选遵循检查点规则。静态候选有限且无新登记时至多 n 项；允许动态增加时不保证终止，预算保留。普通调用、集合操作和循环均在 P 中。□

**定理 29（分层查询确定）。** 查询依赖图无环、每个 base/transform 纯且有限、候选顺序稳定，则给定 H 和输入，查询结果唯一且不改变 H/RNG。

**证明。** 按拓扑层数归纳：底层纯函数结果唯一且只读；第 k 层依赖结果由归纳唯一，有序 fold 每步纯且确定，故结果唯一且只读。静态环拒绝，动态重入故障，不能用任意迭代伪造确定结果。□

**构造性表达例。** (a) 消耗触发和每回合次数上限：事件登记＋来源私有计数＋生命周期重置；先占用次数再调用效果，防嵌套事件穿透限制。(b) 黑暗球/姿态/保留：有序实体组件＋两个效果入口/离开进入程序＋查询/清理替换；实例局部值保存累计量，显式复制策略决定保留。(c) 温度扩展：唯一 heat owner、有限变化提案、受保护 changed 事件和 changing checkpoint，按定理 25–29 构成合法新模块。(d) 迎战按定理 21 占用具体机会；风暴按定理 22 抑制敌人非力量正面状态，并用意图片段 checkpoint 取消非攻击内容。每个例子都归约到 P 的构造，不以声称任意现成原子足够代替新增模块能力。

状态贡献必须在贡献时检查有效性，寿命管理独立。已锁定值与执行时查询通过 snapshot/实体身份显式区分；失效不撤销历史提交。如果模块直接读取 raw 层数产生效果，则不满足定理 22，不能宣称领域成立。

## 27. 保存、分支、保守扩展及证明完成边界

**定理 30（第二层现场闭包与恢复模拟）。** 若 H/K 包含全部跨等待所需的实体、流、登记、环境、outbox、队列、机会、局部槽及执行位置，静态代码仅在 D，编码/解码保持数据图身份，恢复校验相同 D/布局，则恢复配置与原等待配置存在保持下一步的同构，因而保持全部后继观察轨迹。

**证明。** 图同构保持数据值和别名；π_D/λ 映射匹配保证代码/槽解释相同。每种 P 构造只依赖当前配置，定理 24、26、28、29 保证同输入时选择相同步骤与结果。逐步归纳得轨迹一致。initialize 不属于等待后继规则，恢复不得调用；重装登记等价于改 H，直接破坏前提。□

**定理 31（分支非干扰与模式模拟）。** 若存储对 H/K 的每个可变节点提供父子双向隔离且复用只读 D，原生与受控对正常读写实施相同语义，则两个分支的合法推进互不改变对方，且相同输入的原生/受控观察轨迹一致。

**证明。** 静态 D 无写；所有动态写只作用当前分支所有的根及节点。模块 callback 无宿主可变捕获，所以不存在图外共享计数；运行步归纳保持互不影响。原生/受控读到相同逻辑值时纯计算相同，存储写入建立新的同构配置，故逐步模式模拟成立。□

性能结论不随该语义证明自动成立。fork 复杂度和首次推进不能补做全量复制，仍须按既有存储要求实际检查；不能复制 Program 或状态全图来替代。

**定理 32（未启用扩展的保守性）。** D 增加不被旧入口引用、未安装登记且不参与旧生命周期的新模块时，若旧定义语义不变，布局改变只做身份重编码且旧停止轨迹不暴露内部索引，则旧入口的可观察轨迹不变。

**证明。** 新定义不可达且新登记不存在，旧转移选择集合不变。π 的新编号不会改变身份/签名关系（定理 23）。每次旧调用/查询/派发仍选择旧项，数据和 RNG 操作不变，归纳得轨迹一致。若模块显式安装了能力或参与生命周期，则前提不成立，行为改变是规则扩展而非反例。□

本次手工证明完成抽象设计的表达/降低/状态义务，不是机器验证。具体链接器与模块实现必须分别通过：错引用/错类型/未赋值负例；控制流独立模型；atom 权限/坏提案/事件故障注入；中途派发/替换恢复；父子隔离/冷恢复；三方 STS 差分和真实 A20 成功 run。只实现其中一个子集不得勾选 R04–R12 全部完成。未证明 atom 自动纯度、任意规则终止、完整商业内容正确性、恶意插件安全性或任意存储实现正确性。

## 28. 实现细化：提交视图、来源栈与作用域

**定理 33（提交后捕获的只读预演）。** atom 提案 W 只修改声明组件，不修改实体集合/登记表；令 H[W] 为实际提交后的世界，overlay(H,W) 的组件读取先查 W，未触及处查 H，其他查询数据仍查 H。若查询及其修正/资格依赖只经相同只读入口，则在提交前用 overlay 计算事件候选与在 H[W] 中计算相同。

**证明。** 每个组件读到的值按 W 是否含此位置分类，恰与 H[W] 一致。未修改的实体/登记和环境相同。按查询无环依赖的拓扑归纳，base、修正及资格结果逐项相同；稳定排序和候选过滤于是相同。预演任一步失败时尚未应用 W，也未增加事件 ID 或 outbox，保持原世界；预演成功后只执行同步提交。□

这避免两个错误：在提交前用旧状态决定新事件资格，或写入后再运行可能抛错的资格回调。若新 atom 要同时修改登记/实体等其他类别，必须扩展并证明该类别的预演语义，不能私自沿用仅组件 overlay 的前提。

**定理 34（私有组件来源权限）。** 回调入口按具体来源实体 push，正常返回时匹配 pop；该栈和执行帧均属于 Context。内容私有组件只可附着于具体实体，updateLocalComponent 仅在栈顶等于目标身份时提交。则合法第三层调用不能仅凭另一实体的 ID 改其私有组件，暂停恢复也不扩大权限。

**证明。** 唯一提交入口先检查目标实体实际有此私有组件且栈顶匹配；保护组件另由 owner 权限拒绝。普通参数传递和只读查询不改来源栈。嵌套事件/替换/实体生命周期使用 push/pop，归纳保持正确的当前来源；等待时保存同一栈和帧，恢复从同一检查点继续。故通过另一个实体 ID 不会满足提交条件。故障不保证 pop，但实例 fault 后不可继续或保存，不据残余栈获得正常执行权。□

**作用域收尾。** scope 身份单调分配且不复用；只有 initializing/active 可开始 ending，ending/closed 再次关闭不执行回调。子 scope 先收尾，再执行父 scope 的结束程序，随后清理归属实体和登记，最后 closed。由阶段单调性和调用帧的恢复模拟，正常结束能力至多执行一次；等待恢复不从初始化重新开始。实体同理使用 initializing/active/removing，离场期间重复请求不会再次启动 dispose。该命题不保证用户写的无限生命周期程序终止。

**布局身份的边界。** 实现把静态定义/效果/局部槽映射、字面量、构建代码形状及生命周期关系的确定结构摘要并入既有 rule id，存档恢复先检查该身份。摘要使用 SHA-256；依赖标准的碰撞抗性假设，不以显示名称匹配代码。外部提供的原始 id 仍必须绑定冻结的实现/规则内容：JS 闭包的任意捕获值和自定义 schema 的闭包参数不能由 toString 自动完整提取，结构摘要不冒充任意 JS 的语义哈希。宿主构建/实验的源码指纹须覆盖规则源及其不可变配置。跨进程相同装配、变更字面量/局部布局拒绝旧存档均需正式测试。

## 29. 实体效果选择与任务调度的构造前提

**定理 35（有限类型化入口的动态调用）。** 实体 kind 的配置通过 schema，入口选择器是有限纯函数，链接器对本 Program 中每个该 kind 的实体定义预先计算入口，验证它是相同 Effect<I,O> 签名下的已链接定义。运行期选择只产生数据引用〈programIdentity,effectIndex,sourceEntity〉，动态 call 检查 Program、索引与来源资格并用现有 invoke 推进，则该调用等价于对当前实体定义所选静态效果的直接调用。

**证明。** 链接表为每个实体定义给出确定入口；运行期身份查询得到同一表项，不重新执行选择器或宿主代码。检查保证只访问该 Program 中的效果，索引解析对应静态调用目标。参数、独立调用帧、返回槽与静态 call 相同，因此由定理 24 的 call 情形得到模拟；来源 push/pop 由定理 34 保持私有写权限。引用作为数据进入 locals/队列，保存恢复按同一布局解析，不保存代码对象。来源离场时默认拒绝；需要离场后执行的业务使用显式捕获数据的静态任务及其资格策略，不偷用过期实体入口。□

链接须对新发现的入口/实体取可达闭包后再冻结，不能运行时补装代码。任意 JS 选择器的纯度与 TypeScript/schema 签名一致性仍为可信作者前提，运行期必须补成员/范围检查，不把 as any 当证明。

**任务和选择的构造。** 任务项仅含本 Program 的效果身份、参数数据、来源与资格、队列/时点、寿命、任务状态；调度器由 repeat/invoke 构成。取项前将 pending 改为 running，等待保留当前项与调用帧，完成后不回到 pending。前/后插入只改未来队列；数据快照与实体 ID 读取是不同捕获约定。玩家选择由完整候选描述、合法性谓词和现有 request 构成，等待期间保存这些数据，拒绝回复不得进入后继结算。实现阶段必须分别检验这些构造与已有 Instance 的回复事务语义，不能把裸请求或回放整个前缀当完成。

**选择回复的实现细化。** 类型化 choice 在自己的帧中保存候选/基数/顺序和静态适配器身份，链接器为该效果登记纯回复守卫。runtime-card 在既有 schema.parse 路径中先解析原输出 schema，再对当前等待帧的选择描述做守卫校验；守卫只接收隔离的描述与回复数据，不保存或修改规则状态。守卫失败沿现有 invalid_reply 返回，不调用 advance、不写 returned 记录，故 Context、RNG、候选与 CallId 保持。成功后 choose 在已有 request 续延中取相同合法选择继续。该构造不新增公共协议字段，不把待决选择藏在宿主闭包中；宿主仅保留共享的静态守卫代码。恢复仍从 Context 的等待帧读取描述。

## 30. 阶段偏序与动态实体定义引用

**阶段的构造细化。** 每个目标 Query/Event/Checkpoint 或 scope 声明有限阶段集合 P、边集 E（before/after）和缺省阶段。重复/未声明顶点拒绝。拓扑算法每次取声明序最先的零入度顶点，移除它的出边；若未取完而无零入度顶点则拒绝。有限无环图每个非空子图必有零入度顶点，故恰生成一次包含全部阶段的序列；每条边的起点必早于终点。以此 rank、显式阶段内优先级、登记序号作字典序，得到满足全部约束的确定全序，实例无需持有或求解偏序。生命周期退出采用初始化顺序的逆序。该算法细化定理 28–29 的“候选顺序稳定”前提，不声称不同的无约束排序语义等价。

**动态实体定义引用的构造。** 定义集合 D 在链接结束前冻结；每个实体定义有唯一索引 i 和 kind k，字面量定义进入运行现场时编码为〈Program 身份,i〉。同 kind 的定义列表、局部选择及现有实体的 definitionOf 都只传该数据引用。spawn 校验身份、i∈D、kind 匹配后，按 D[i] 的静态配置/私有组件集合与该 kind 的初始化程序创建实体。初始化输入另由 setup schema 校验，不把随机种子、HP 或牌堆实例值编进静态定义。与静态 spawn 对比，所有初始化步骤和返回身份相同，只有取得 i 的纯选择步骤不同，因此由定理 23–24 的引用/调用模拟以及定理 30 的恢复同构，得到相同后继。错 Program/索引/kind 在分配实体前拒绝；复制实例时必须显式给新的 setup，不复制宿主函数或整个定义配置。

该构造用于抽取/生成任意具体卡牌；不能要求为每个随机种子重建 Program，也不能通过牌名字符串查找执行分支。静态定义引用不授予组件写权。有限闭包、纯选择、正确 schema 与同一已冻结 Program 仍是前提。

**区域唯一归属的模块义务。** 每个参与实体具有 owner 管理的 location，每个区域具有同一 owner 管理的有序 members。初始 location=null 且区域空。move 要求旧 location=from、源中恰有一次实体、目的中无重复、插入索引合法且容量足够；同区域移动先移除再按新索引插入。提案同时更新两个列表（相同时只写一次）与 location。按 from/to 是否为空/相同分类，其他实体的成员关系不变，被移动实体在目的中恰有一次或处于 null，故归纳保持全局唯一归属。全部验证先于提交，失败不会出现“先移除、后发现目标满”的丢牌。reorder 必须是原列表的全排列，因而保持该不变量。参与实体的 dispose 必须通过该 owner 移出区域，再由通用生命周期删除；直接绕过此契约的自定义 kind 不属合法扩展。

**来源到期与实际提交目标。** 来源离场时，依赖 source-present 的未运行任务及来源实体入口任务由同一 Context 的 owner 清除；明确 captured 的静态任务保留参数数据，不因此获得已删除来源的组件。running 项仍按已保存调用帧收尾，不能回到 pending。检查点若允许改变动作目标，后续派发/死亡判断必须使用 commit 返回的实际目标与结果，不能重新取动作最初的目标；HP 资源实现因此保留 `{entity,lost}` 收据，再派发 wouldDie。恢复保留相同收据与帧，既不重复扣血，也不对原目标误触发恢复能力。

**随机流和洗牌的类型保持。** 源数值算法对一个有限的 RandomState 值作计算，owner atom 读取独立副本、校验返回状态后提交同一流组件，故不会通过宿主随机或另一份 World 改变继续执行。数值算法与源的对应仍由独立差分验证，非此所有权证明自动推出。洗牌只对有限输入数组执行交换，按交换次数归纳保持原元素多重集及元素类型 T；所以模块可用一个经过该不变量论证的泛型 wrapper，将内部 unknown[] 校验/交换效果暴露为 `Input<readonly T[]> → Command<readonly T[]>`，无需让内容作者逐处断言类型，也不允许 wrapper 改写元素。

**离场程序仍持有当前来源。** removing 表示已占用离场机会、尚未完成清理，不等同于实体已经删除。dispose 在来源栈顶为该实体时可选择并调用其静态配置的离场效果；其他来源不得借 removing 实体取得新的动态入口，排队任务也不获得此例外。调用前后检查同一来源栈，恢复保存该栈与 removing 相位，故可暂停的离场程序保持定理 34 的权限不扩散；最终删除之后任何动态引用都失效。不能为实现离场 hook 而把整个配置或函数放进 Context。

## 31. 卡牌实例与状态内容的细化前提

卡牌定义仅含静态元数据、纯升级策略及效果入口。实例状态分为身份字段（长期/战斗、master、战斗 uniqueId）和可变字段（升级标记、specialData、cost/costForTurn、单次免费与保留）。所有内容改动经 card owner 的有限提案；升级策略只能返回可变字段，schema 拒绝身份字段，故按提交次数归纳不会因升级/降费改变实例身份。新战斗副本取相同定义和 master 的升级/特殊数据，重新计算初始费用并清除临时标记，分配新的 Context 实体身份；静态代码共享不意味着动态牌实例别名。精确费用运算和特定升级策略仍须对照独立 CardInstance，而非由此身份不变量自动推出。

卡牌离场先经 zone owner 移出当前区域，再确认 location=null，随后执行其类型化离场 hook；hook 返回后再次确认未重新进入区域，才允许通用实体删除。等待保留已有身份、来源和移动结果，不重建卡牌，也不重复执行已完成前缀。若规则替换取消必要移出，离场不能静默删除并留下悬空区域引用；必须显式故障或由调用方另行结算。

纯策略同样使用类型化 Query 引用，不能把裸 JS 函数塞进实体配置。对选择器〈kind,select〉，链接器在有限实体定义集合上预先计算被选 Query 表并把其依赖纳入可达闭包；依赖图边同时包含全部可能被选 Query，静态环拒绝。纯查询必须显式声明该选择器，运行时按实体定义索引取对应 Query，再以相同只读世界求值。由有限表的引用模拟和依赖图拓扑归纳，选择结果确定、无写入且保持原输出类型；Context 仍只持有实体身份和数据。未声明选择器、错误 kind 或未链接的私有依赖拒绝，不利用自动发现扩大组件读权。

状态模块以〈registry,actor,definition〉查找唯一未离场实例，definition 的比较由已链接 Program 的定义身份完成，不按显示名匹配。registry 仅保存实体与定义引用；层数、active、justApplied 在对应状态实体上，inactive 不删除原数值。creating/attached/removing 是状态模块的贡献寿命：贡献查询只认可 attached 且 active，初始化可先提交原值再安装能力，安装完成才开启贡献；离场先关闭贡献，再执行结束能力并移出 registry，最后通用实体删除。registry 关闭先禁止新加入，再依次移除成员并确认空。按创建/合并/移除三类提交归纳，保持定义唯一性、引用不悬空和贡献寿命；若生命周期回调形成相互删除等不满足收尾前提的循环，则明确故障，不能静默丢失剩余登记。

伤害由检查点、格挡提交、未格挡伤害检查点、HP 提交收据及事实派发顺序组合。格挡事实（实际目标、原请求量、吸收量）由 owner 保存，后继替换只能修改将提交的 HP 请求，不能篡改已经发生的格挡事实。HP 来源显式区分 direct 与 damage，使“直接失去 HP 的限制”不会在格挡/Buffer 后把已经归零的攻击重新变成伤害。零未格挡请求不进入 HP 提交；反击等可在此前检查点运行。每个前缀均符合已有提交/调用模拟，跨等待保留已消耗格挡、检查点进度及 HP 收据，不把完成前缀回滚或重做。具体 STS 的 Float32、Buffer/Torii/Tungsten 等顺序仍是内容/独立差分义务。
## 32. 抽牌续接与区域操作的细化前提

本节先给出下一迁移单元的构造，随后由独立 C++ 差分检查具体内容。令四个区域为有序序列 D/H/C/X，位置函数 L 是唯一成员归属；抽牌顶是 D 的末端。取牌先通过区域 owner 从 D 移到空位置，派发 drawing，再依据此刻手牌容量经 owner 进入 H 或 C。drawing 可以暂停，但卡牌身份和取牌动作已经保存在当前帧/Context；恢复不会再次 pop。恢复前提仍是静态 Program 和输入 schema 一致，监听效果有限，扩展不得伪造已提交的区域事实。

设本次抽牌数 n=min(request,10-|H|)。当 |D|>=n 时，先增加 drawn 计数 n，再依序取末端 n 张；所有具体状态（如随机费用、禁止抽牌、抽牌触发）由声明的 Query/事件组合进入，不在区域 owner 中按内容名称分派。当 0<|D|<n 时，设 r=n-|D|：先向队首插入 draw(r)，派发 shuffling（其监听可向队尾排任务），再向队首插入 shuffleDiscard，最后在当前帧完成 draw(|D|)。因此当前调用返回后的队列前缀严格为 shuffleDiscard,draw(r)，其后才是 shuffling 与当前抽牌监听加入的队尾任务，与源 addToTop/addToBot 的次序同构。|D|=0 时同理，无当前帧抽牌；D+C 为空、手牌已满、request<=0 或 canDraw=false 时不抽样、不加任务。

shuffleDiscard 只使用声明的 shuffle RNG，通过一次 randomLong 驱动 Java 洗牌，然后把 C 的排列依次移动到 D 末端。即使 C 为空，显式 shuffleDiscard 仍消耗源规定的一次 randomLong；draw 的空牌堆拒绝则不消耗。区域移动保持 L 与各序列互为逆映射；任一替换拒绝移动时，调用方必须终止该语义操作或重新检查，不能在已拒绝移动后继续假装发生了抽牌/弃牌/消耗。原子提交保证单次移动不丢牌；整个复合效果不是数据库事务，已经完成的前缀按约定可见并可恢复。

消耗采用“离开原区域、exhausting、进入 X”的显式控制流；来源内容仍为独立实体，X 不是删除实体，因此监听可以检查牌的定义、升级及私有状态。计数与事实只在对应语义成功后写入。普通弃牌与回合末弃牌用字面量标记区分；手牌逆序弃入 C 保留源的排列。回合末费用重置只遍历 H/C/D，不处理 X，逐牌调用既有费用原子，保留负费用哨兵的源语义。

该构造只证明可用现有 call/Local/forEach/队列/事件表示这些控制流，并保持已声明的区域与恢复不变量。它不证明完整战斗队列、回合结束、保留/虚无、战斗胜利清队列或全部卡牌内容已经接通；这些仍须分别实现和验收。

开战牌堆构造以永久卡实体的有序列表 M 和瓶装实体集合 B 为输入，不使用牌名字串。先验证 M 内身份唯一且均为永久实例、B 是 M 的子集、目标四堆为空且尚未开始装配，再占用一次初始化机会。令 P 为一次源 shuffle RNG 的 Java 排列，I(i) 为永久牌的 innate 或 i∈B；构造顺序为 P 中非 innate 的稳定子序列连接 innate 的稳定子序列。对每个索引 i，copyIntoCombat 复制定义和永久升级/特殊数据，但使用全新实体、master=M[i]、uniqueId=i 和重置后的临时字段。故按排列长度归纳，初始化结束时永久牌与战斗副本一一对应、无共享可变牌状态，抽牌顶部的 innate 分组与源相同。生成数量及当前循环索引均在 Context，卡牌 created hook 等待后不会重复分配已完成前缀。额外 innate 抽牌仅作为队尾任务登记，常规起手抽牌仍由后继战斗开始流程决定，不能在此偷偷提前执行。

队列首次登记必须把空序列写入 Context 后再读取其受管视图进行插入；不能修改赋值表达式返回的宿主临时数组，否则 COW 存储虽保存了空序列，却不会观察后继宿主数组写入。queueSize 是调度器只读表达式，只观察实际 pending 序列长度，不包括 scheduled 或已经取出的 running 项；不暴露任务函数或给第三层队列写权。

## 33. 出牌快照、任务优先级与战斗结束的细化构造

本节在新增主流程代码之前给出构造及义务。一次待用牌保存〈单调 play 身份、物理卡实体、定义引用、CardState 值快照、目标、用牌标志〉，不是 CardConfig、函数或物理卡状态的可变别名。当前牌与牌队列由战斗 owner 唯一维护；物理卡的私有组件仍只属于原实体。执行内容收到 CardUse，其中 state 是本次出牌的值快照，card 是能被 owner 原子更新的实体身份。于是排队后另一效果改变手牌费用，不会偷偷改变既有出牌快照；私有计数又不会因制造执行副本而重置。消耗和使用能力牌只改变区域/出牌处置，内容实体保留至战斗 scope 结束，以供已经排队的复制出牌使用同一静态入口；不存在从已删除来源取得新动态入口的例外。

当前出牌按以下前缀顺序降低：取出牌项并保存 current；检查目标及 canUse；占用出牌机会并增加总用牌数；调用由定义选择的 use Effect；增加类别计数并派发 used；将 after-use 清理排到行动队尾；派发 otherCardPlayed；由区域 owner 移出手牌并经资源 owner 付费。牌程序安排的普通行动在该前缀完成后才被调度，因此攻击看到的手牌与能量已经是离手/付费后的值；伤害数值何时计算仍由内容明确选用值快照或执行时查询。used/otherCardPlayed 可以等待，保存其中任意 IO 边界时，已完成计数、队列与派发游标均在原 Context，不重做前缀。

行动调度每次仅取一个待执行任务，完成后重新检查当前战斗结果，再考虑下一行动；行动为空时才取下一牌项。drainQueue 复用同一个 drainOne 构造，不另外维护取项语义。由任务数及调用轨迹归纳，它保持“先行动、后牌项”的优先级和 running 项跨等待恰好一次执行。死亡应停止后续所有行动；胜利则取消源中 clearOnCombatVictory 的行动，保留牌清理、攻击玩家或指定可继续的效果。此差别用已有作用域表达：战斗 scope 的空子 scope 只承载可取消任务，不承载实体或登记；普通行动使用子 scope，清理等使用父 scope。胜利关闭当时的子 scope，通用寿命清理删除其 pending/scheduled 任务，正在执行的任务完成；随后重新建立空子 scope 并更新战斗/牌堆引用，允许 after-use 按源规则继续排入未来任务。物理卡/状态实体仍在父 scope 中，保留任务可以继续。不能把“清除当时的任务”误作“禁止以后入队”；胜利后的保留伤害仍可令玩家死亡。它不要求新增 VM opcode、游戏专用 Task 字段或宿主侧清队列。

after-use 先派发 enemy/after-use 能力，再对非 purge 牌清除单次免费标志并选择 Discard/Exhaust/DrawTop/Vanish 的字面量处置。处置可被声明的 checkpoint 替换，但不能篡改已经提交的付费/离手事实。写回 CardMutable 只修改可变字段，身份字段保持；Discard/DrawTop 使用区域移动而非手动弃牌事件，Exhaust 通过既有消耗流程，Vanish 留在无区域状态。无触发的回合末牌使用独立的定义入口和延后弃牌流程，不增加常规出牌次数。以上是结构/恢复证明，具体权限、整数边界、FreeAttack/Corruption、源的清队列缺陷及全部卡牌内容仍须独立差分；本节不把尚未实现的回合、敌人和冒险宣称为完成。

状态自身的 attach 程序需要由 actor 找到当前战斗；不能依赖卡牌调用者偷偷补做状态初始化，也不能为查找关系导出整个世界。补充 QueryRead.entities(component)，仅枚举显式 reads 中组件实际存在的实体身份，按数值身份排序并返回只读数据。其准入沿用 component 读权验证，求值仅访问有限 Context 实体表，既不授予写权也不扩大组件集合；已有组件写入 overlay 不改变组件归属集合。因此纯查询的有限确定性和权限证明保持，只增加显式有限选择步骤。战斗 owner 可在自身 state 上构造 forActor，并检查唯一性；具体状态通过该公开查询取得战斗引用，随后仍只能调用牌堆/卡牌 owner 的语义入口。

单卡选择模块只接收〈battle、发布提示、互异的候选卡身份〉，维护 pending 实体、选择事实与既有 chooseOne 续接；它不依据提示选择卡牌执行代码。具体卡牌在第三层指定候选区域和后继移动，并显式决定单候选是否抽样。候选为有限值快照，返回的是其中一个身份；pending 在接受回复后先销毁，再发布 chosen，允许后继监听开启新的选择而不留下两个 current 选择。非法回复沿原守卫保持调用、记录和 Context；头槌/战吼的空/单/多候选、单候选 RNG、付费后待清理、分支及冷恢复均为实例检查义务。canContinue 只在无行动/牌项可执行且战斗仍未定时决定是否因无牌失败，不能在牌尚在 limbo/清理尚在队列中时提前宣布失败。

## 34. 敌人机会与回合阶段的细化构造

本节先于对应实现。敌人定义提供类型化的意图 Query、随机选招 Query 和执行 Effect；实例仅保存 actor、battle、RNG 引用、招式历史及〈turn,claimed〉，不保存配置函数。open(t) 只允许时间单调前进，同一 t 不重置 claimed；take(t) 在调用内容入口前把 claimed 从 false 改为 true，并保存当前意图值。于是同一机会最多执行一次，即使内容在选择处等待，恢复时仍在该已占用入口的调用帧内。提前执行与正常敌人阶段调用同一个 take；后者观察 claimed 后跳过，不需要另外复制一份敌人行动或撤销标志。招式选择只通过指定 AI 流抽样，setMove 同时把旧第一历史移到第二历史，不由显示名选择代码。意图 checkpoint 可以取消执行，但不能改写机会身份；取消仍消耗本次机会。攻击分类是定义声明的元数据，复合意图需要在内容中按动作粒度使用同类 checkpoint，不能把“含攻击”误作整段复合程序都免于抑制。

回合控制器另有有限状态〈ready,ending,enemies〉、敌人游标和保留区域。每次先调用已有 battle.settle，行动及牌项均无可执行后才推进阶段。结束项先发布回合末遗物、预牌状态事件，再按当前手牌顺序为具有 endTurn 入口的定义排无触发牌项；随后发布回合末状态事件、排清牌队列和手牌整理任务，立即重置 H/C/D 的临时费用，最后排进入敌人阶段任务。内容通过带显式顺序的事件登记，不进入 controller 的名称分支。敌人游标在调用 take 前递增；该调用返回后重新优先结算行动，因而敌人 A 的伤害/死亡先于敌人 B 的机会。轮末依序发布各存活敌人的回合末事件、玩家轮末事件、各存活敌人的轮末事件，再增加回合号，发布开始阶段、重置格挡、排抽牌、发布抽牌后阶段、清计数并补充能量。事件调用与任务插入的区别保留源顺序，不能用一次无阶段回调代替。

保留卡按手牌原序移动到专用有序区域 R；先向队首排恢复 R，再排普通弃牌，再按余下手牌原序向队首排虚无消耗。因此实际执行为逆序虚无、逆序普通弃牌、原序恢复保留。每次移动仍经 zone owner，保持所有区域与 location 的互逆关系；R 也是 Context 数据，不是宿主临时数组。恢复任务清除临时 retain，但不改变定义自带 selfRetain。轮末等待时，区域、游标、机会占用和已排任务均可由同一 Context 恢复，不重做移动、随机或事件前缀。能量补充是资源 owner 的独立语义提交；直接设为每回合能量不能伪装成 gainEnergy，否则会错误发布获得能量事实。可保留能量的内容经公开纯策略决定补充量。

上述构造由已有 sequence/call/while/Local/事件/任务/区域操作组成，逐项适用定理 24 与第 29–33 节的模拟和不变量，故可在现行 Core 表达。它证明结构上的可表示性与恰好一次机会，不证明任何具体敌人、状态、全部回合边界已经符合 STS；Cultist 的初始/空转 AI 抽样、Ritual 首轮跳过、DemonForm 排队、弱化/易伤时长及保留/虚无须由独立 C++、native、controlled 差分承担。

## 35. 持久牌实体、批量获得与冒险接线的构造

本节先于持久牌堆实现。永久牌堆保存有序实体身份列表 M、瓶装原始索引 B 和源的计数器；牌值仍仅保存在 cardInstances owner 的组件中。追加前验证永久模式、未归属其他永久牌堆、容量和身份互异；移除原子地从 M 删去一个身份，后继才经卡实体生命周期删除。战斗构造只读取 M 作为 masters，再由既有 copyIntoCombat 创建战斗副本；冒险和战斗共享持久 actor，但不存在两份可变永久牌值或 HP/金币回写。因此按追加/移除次数归纳，牌堆成员身份唯一，恢复/分支保持相同 master 关系。删除永久 master 前必须结束引用它的战斗，不能借此留下悬空引用。

批量获得先经带定义引用、升级标记、特殊数据、数量的 checkpoint。取消或数量归零不分配牌；接受后创建首张永久牌并应用明确的强制升级策略（例如获得时的升级），冻结本批副本值，再占用本批的计数与剩余追加数。登记本批后发布 obtaining，之后依次生成/追加互异的牌实体，最后发布 obtained。尚未追加的数量由 pending 批记录解释，计数不必在中途等待时等于已经可见的 M；批内循环索引、首张实体和被冻结的副本值均在调用帧/Context。每次实际追加消耗本批一个额度；最后额度归零才移除 pending。嵌套获得使用不同单调批身份，不能消耗外批额度。于是等待、fork 或冷恢复既不重复获得金币等前缀，也不重复创建已经追加的牌。全部批结束后的数量/计数仍须逐步对照源 Deck，而不是从结构唯一性推出数值正确。

升级的资格查询与“明确应用一次升级”分开：前者可拒绝重复升级，后者表达源永久牌升级/蛋对已升级灼热攻击仍再次增加 misc 的语义。共同入口仍经过 beforeUpgrade，并返回实际目标和 applied 收据；牌堆据实际目标找到其所属牌堆再更新对应计数，不能把重定向后的升级记在原目标。普通牌、不能升级的诅咒、强制重复升级及取消由同一纯策略/提交流程表达，不新增牌名分支。

瓶装保留源的原始索引与计数转移，包括源 anyCardBottled 的反向谓词及移除诅咒不调整索引的行为；不把它们加强成“索引永远有效”的错误不变量。对外需要实体引用时另由 M[B[i]] 查询得到，无法解析的索引不伪造实体。具体不能变换的诅咒、蛋、御守、陶瓷小鱼、寄生虫离场由第三层纯策略/有序检查点/事实 hook 组合，永久牌堆 owner 不按这些名称派发。以上是手工条件构造；全部源计数、强制升级与 RNG 数值、正常开局及生产替换/旧代码删除仍需独立验收。

获得前的策略需读取尚未分配实例的定义元数据。QueryRead.definitionConfiguration(definition,kind) 复用实体定义引用的 Program/索引校验，并要求 kind 出现在该 Query 的显式 kinds 中；只返回已冻结静态配置给纯 Query 的内部计算，Query 输出仍经 data-only 校验。它与 configuration(entity,kind) 的权限相同，仅以定义引用代替“先创建临时实体再读配置”，不增加组件读权、运行期装配或 Context 中的代码对象。跨 Program、错误 kind、未声明 kind 均拒绝。由第 30 节有限定义表的引用模拟，保持纯查询与恢复同构。

遗物的持有关系由 kind 的 owner 组件保存〈actor,definition〉；创建先验证同 actor/定义未存在，再写关系并执行安装入口。枚举该组件的实体得到获取顺序，删除生命周期同时注销其监听和持有关系。具体计数仍可由第三层私有组件维护，通过 data Query 的修正贡献只读投影，不在冒险再复制一份计数。恢复保留该组件及登记，不能为生成发布重新安装遗物。

正常开局把十四条随机流、持久 actor、永久牌堆和起始遗物经现有 kind 创建，返回这些身份及地图/遭遇计划等数据。地图是仅依赖 seed 的有限纯构造；遭遇和 Neow 逐次调用 RNG owner。对 weighted 的 Float32 累加、接受/拒绝循环、首强敌限制及 Boss 排列按源抽样轨迹归纳：每轮选择相同值，拒绝时只改变同一 RNG 流而不增加已接受计数，接受时追加同一条目。Java 洗牌显式选择 counted=true 的 randomLong 或 counted=false 的 nextLong，后者不增加计数；此选择不能通过复制 RNG 状态后另行写回冒险实现。该论证是有限源执行的模拟，不保证任意自定义拒绝循环总会终止。开局效果不调用旧 Adventure 构造器；后续冒险仍须把这些返回身份接入唯一生产入口。

退出先发布终局事实，再关闭战斗 scope。领域 scope 的 dispose 必须在通用实体删除前，经 zone owner 将四个牌区及保留区的成员移到 null；区域实体仍拒绝带成员删除，不能假设通用实体编号等于依赖删除顺序。每次移出由既有 move 不变量保持双向一致，等待保留待清理列表与游标；取消必要移动应明确失败。清理不是弃牌/消耗，不发布那些内容事实。随后通用删除解除战斗副本与监听，持久 master/actor 不在战斗 scope 中，仍保持身份和值。此时才允许移除永久 master；资源由退出 hooks 原位更新，无 World→Adventure 的 HP/牌堆复制。

## 36. 冒险选择、奖励与内容目录的细化构造

本节先于实现。冒险 owner 仅保存持久 actor/牌堆/药水/RNG 身份、路线及展示数据、池、奖励和候选快照，不保存第二份 HP/金币/永久牌值或可执行回调。目录由有限的〈来源标识、类型化定义引用〉组成，在装配时把定义降低为 Program/索引数据；候选抽样及内容选择读取引用，执行仍调用相应实体的静态入口。标识可用于来源数据/展示对应，不用于解释器内拼接函数名。元数据存在不等于内容使用程序已经实现，缺失内容必须显式失败，不能用无效果模板充当完成。

一次永久牌选择先冻结〈牌值定义/升级/特殊值、原 deckIndex〉候选，再用既有 chooseOne 请求一个候选。接受后 owner 原子地从候选删去该项并追加到 selected；未满足所需数时再次请求。候选和 selected 均在 Context，非法回复保持原调用；最后一项才进入内容 Effect 的后继。source 的按逆选择顺序移除原 deckIndex 与“按实体身份删去原卡”并不总等价，因此兼容源的内容必须显式按其原始索引顺序取当时的牌堆成员，不能由通用选择模块替作者改规则。变换、升级、复制和瓶装由后继组合 owner 入口，选择模块不依据屏幕字符串或具体卡名执行。

奖励窗口为 owner 管理的有限容器。每次选择冻结合法动作，chooseOne 返回后调用对应的获得/移除原子，再重新求当前奖励和候选；嵌套选择/奖励是普通 call，其父帧保留未完成的后继，不使用宿主闭包或重新运行开局前缀。hasContinuation 等来源展示字段仅描述源窗口，不承担执行派发。对每个有限选择轨迹，按接受回复次数归纳，待决候选、已选择列表、容器剩余量及源 RNG 抽样一致；恢复保存同一帧/owner 数据，故不重付代价、不重抽奖或重复领取。具体 Neow 的先诅咒后奖励、两张变换在展示前加诅咒、源抽样浪费及遗物开嵌套窗口的次序仍须独立差分。

药水 owner 单独维护容量、槽位和数量；obtain 的允许策略可被遗物贡献，成功插入只占一个空槽，满容量或不允许时保持原状态。丢弃/饮用分别移出一个实际槽位，后继内容依据移出收据执行。资源代价区分获得金币、消费金币、上限增加而不治疗、直接裁减 HP 与伤害事实；不能为了复用伤害路径而错误触发减伤/治疗监听。全部仍是现有 call/Local/Query/atom/choose 的组合，数学论证不替代完整冒险生产替换或内容验收。

## 37. 唯一入口与发布续接

旧生产文件整体删除后，新入口只链接上述规则模块；它初始化一次持久身份，再 call 正常冒险程序。窗口的执行后继属于调用帧，screen 仅参与只读投影。尚未实现的具体内容不得返回伪造成功、改用旧函数或另选内容。

端口绑定是装配期的 Effect 引用，链接为已有 request/return；既有端口字符串只出现在绑定声明，不成为内容执行名称。一次发布先读取已接受历史的未发布后缀，call 原有事件端口，然后提交 published 游标。若停在事件端口，游标尚未前进，恢复从同一 call 返回点继续；不重新执行产生历史的动作。每次需要外部选择之前立即派发 requesting 事实，根模块的监听先完成发布，再进入选择 call。因此嵌套窗口也交付相同事件前缀；自动单候选不记录为外部动作。按外部端口返回次数归纳，调用帧、接受历史及发布游标保持一致。

公开投影是对 owner Query 的只读组合，不重新装配实体、安装监听或推进 RNG。私有验收投影另行组合种子、池和计数，生产端口不构造此私有图。schema 只接受数据；fork/restore 复制 Context 而共享同一静态投影与内容。此为条件模拟证明，具体投影字段、合法动作顺序、内容覆盖及整局结果仍由末尾统一差分验收。

## 38. 群体行动与留存后继

群体攻击可由第三层普通 Effect 构造：先对当前目标枚举和计算有限伤害矩阵，逐项 call damage.hit，最后调用 battle.checkOutcome；它与逐次单体行动不同，不能在每个成员之后提前清空当前行动的后继。Reaper 使用逐项实际生命损失收据累加治疗量，治疗行动位于战斗父 scope，再检查终局，因此胜利清除普通行动不会删除应当留存的治疗。随机多段攻击则每段重新从当前活目标抽取，先抽样再把单体 hit 插到队首；即使只有一个目标也保留来源的 RNG 消耗。

FlameBarrier 在伤害已经提交格挡后捕获来源和当前层数，把反伤以普通任务插入队首；回合阶段注销效果资格而不改动已经捕获的反伤数据。Metallicize 在明确的阶段只贡献原始格挡量，不再次套用卡牌敏捷/脆弱计算。上述组合仅使用已有查询、事实、任务寿命和 owner 入口；按有限目标/段数归纳保持资源与队列次序，等待保留矩阵、游标和收据总和。源细节仍须统一差分验证。

敌人选招本身使用 Effect，纯 Query 只计算意图/资格/静态健康策略。roll 先消费一次指定 AI 流，再调用该实体 choose Effect，允许条件追加随机抽样及更新该实体私有计数，最后提交所选招式。这样 JawWorm 等源分支中的附加概率抽样通过普通 call 保存，不在 Query 内改变 RNG，也不按名称在通用调度器补偿抽样。此为既有控制流模拟定理的直接实例。

## 39. 有限多选、生成、复用与阵容构造

本节细化仍只使用已有原语的构造，不宣称尚未运行的实现已经通过验收。多选冻结候选身份与原始位置的双射、数量上下界和排序约束；chooseMany 在同一等待守卫验证整个回复，后继只使用返回的身份列表。原始位置用于外部动作编码，不能把经过筛选的候选序号误当作手牌/抽牌堆下标。单选自动完成和外部多选分别发出一次接受事实；等待实体只承载待决数据，返回后删除，不承载执行函数。相同 Context 与回复产生相同身份子集，按消耗/移动次数归纳保持区域唯一性。

第三层复用工具在装配时展开为 Effect、Query、字面量与有类型的调用，具体招式表在链接时展开条件分支；运行期不通过名称查找宿主回调。多段/群体/斩杀奖励可先捕获伤害，执行原始 hit，依据实际终态和可贡献的奖励资格查询执行后继，再检查战斗结果。复制保留牌值快照与物理身份的区别；修改当前出牌快照必须经过 battle owner，不能在内容程序直接写其私有组件。队列“插入首项之后”只是有限序列插入，仍由既有 owner atom 提交，不新增 VM 指令。

持续能力的层数、堆叠次数、计数和延迟槽位由能力实体的私有组件保存。回合事实触发只读资格，Effect 更新当前来源的私有组件并提交后续任务；其生命周期由战斗 scope 承载。显式的 skipFirstDecay 把持续时间语义与来源 actor 身份分开，避免为表达跳过首次递减而伪造一个敌人来源。成功施加状态在检查点、提交和附着/合并完成后才发布 applied；被抵消的申请不发布该事实，相关后继可据实际成功收据组合。

阵容程序允许在选择一个候选之前实际构造多个候选并消费各自的健康随机流。选中者返回〈定义引用、actor 身份、参数〉，未选中者只删除尚未参战的构造实体。HP 从始至终只由资源 owner 保存；返回值不复制 HP。这样能表达参考中“先构造临时怪物数组、再选择其中一个”的 RNG 消耗，而不是选完后补造若干名字特例。根程序在全部构造完成之后才依次安装控制器并选招，保持所有初始 AI 先于开战能力的顺序。空槽位用 null 表示，不分配伪造怪物。分裂/召唤通过相同构造工具、阵容 owner 更新及机会 claim 组合；同一轮的已占用机会不能因更换控制器而再执行。按构造/部署次数归纳，阵容只有实体引用，资源、状态与机会仍各有唯一所有者。此构造还要求具体内容正确给出新生机会是否已占用、是否消费健康 RNG 以及动作插入顺序，留给末尾差分检验。

开局的“创建事实”和“标准开局抽牌已经入队事实”分开：前者允许内容立即增加初始资源或排入抽牌前的行动，后者允许内容将行动追加到标准抽牌之后。两者仍为 owner 发布的事实，根调用帧保存唯一发布次序；领域没有遗物名称或专门的抽牌分支。能量的每回合基数与保留贡献为不同 Query，UI 可读前者，实际充能 Effect 组合两者，避免为保留剩余能量而污染 energyPerTurn 的含义。

## 40. 只读展示元数据与边界发布记录

状态的展示键、布尔标志与外部槽位来自定义中的不可变 presentation 数据。投影只读取 owner 的 presentation Query 与实际状态，不在查看器维护另一份具体状态定义注册表，也不通过展示键派发执行。新增状态携带自己的展示声明即可被同一投影枚举；删除展示数据不会改变结算。定义身份仍由 Program/索引验证，不能用显示名称替代类型化定义引用。

固定参考的私有外层 GameContext 在战斗期间保留入场时的资源、永久牌及遗物计数；其公开发布用实际战斗 HP、上限、金币和药水覆盖对应字段。新架构只维护一份参与规则求值的资源/物品值；为保留这一观察语义，在进入战斗、任何开战内容执行前捕获一次不可变的外层观察记录。该记录只由 frame/publication Query 读取，任何支付、治疗、伤害、牌组、随机和内容 Effect 均不得以它为输入。它随战斗 scope 删除，退出后重新投影唯一 owner 的当前值。因此表示关系可包含“当前规则值＋上一边界公开记录”，不需要第二套可变 World 或退出回写。恢复保存该数据记录与实际 owner，既不重放入场，也不重新采样发布前缀。这是观察缓存的条件构造；末尾须比较参考外层展示与实际战斗未来状态，不能用此缓存遮蔽规则差异。

永久增长的回传也可作为类型化内容 hook：CardConfig.returned 接受〈战斗、物理牌、master〉，通用退出程序只按规定牌区顺序枚举仍归属牌区且具有 master 的物理牌，再调用该卡的静态 returned Effect。内容决定哪些实际值回传；通用 battle owner 不知道牌名，也不复制完整牌值。RitualDagger 在战斗中只更新当前快照/物理牌，退出时才把实际 specialData 写入既有 master；临时复制重分配身份后 master=null，不会错误回传。若同一 master 有多个来源副本，区内和区间顺序固定，最后实际回传者决定最终值；等待保存枚举游标，因此恢复不会重跑已完成回传。

胜利目标集与普通可选目标集为不同的纯 Query；能力可贡献“哪些目标是胜利所必需”及“当前是否延后终局”。胜利判定只组合这些查询与玩家生命，不枚举 Boss/爪牙/复活名称。这允许领袖死亡但爪牙尚存、暂时半死等待重生与普通消灭全部敌人共用同一 owner。持续反伤/自伤群攻则贡献 canContinue，而不是向牌堆伪造一张牌来阻止无牌失败。上述贡献有普通来源资格和 scope，来源离场后自动失效。

卡牌与遗物 kind 的 id 为普通展示标识字符串，不再把定义限制为固定参考的枚举成员；身份和执行选择仍依赖类型化定义引用。参考专属的有序池、排序数值与准入目录属于第三层。第三层新增一个定义不需要修改第二层名字枚举。额外持牌区域可由 zone 原子创建并附着到牌堆的辅助区域列表；通用 scope 收尾一并解除这些区域成员，额外区域不自动参与抽牌、费用重置或永久牌回传，具体机制显式组合这些操作。

敌人构造明确分为创建资源、控制器初始化/选招、恰好一次 prepare 三个步骤。prepare 的 owner atom 先提交 prepared=true，再派发该实体的准备事实，重复准备明确失败；根程序可在全部初始 AI 完成后逐个准备，召唤工具也调用同一入口，或显式延后到一组召唤全部选招后再准备。具体预战状态仍由第三层监听组合，不依赖“整个战斗再开一次”的伪造 started 事实，因此新生实体不会导致玩家遗物或既有敌人重复开战。


## 41. 可复用 hook、可选选择与只读对照的延伸义务（未验收实现批次）

本批次新增内容仍只构造既有 Effect/Query/实体与登记。敌人 prepare 事实先完成一次性 claim 再派发；召唤者通过 owner 部署新 actor/controller，另行 claim 当前机会，不依赖怪物名字的通用分支。时间扭曲将待取消的自动机会按原队列次序保存为 Context 参数，经通常的收尾与处置检查点处理，再提交结束回合机会；不能重跑 use，也不能丢弃应执行的收尾。其正确性仍须由完整轨迹与定向等待恢复检验，本节不宣称新代码已通过。

可选单选增加一个独立的跳过编码。设原候选到外部位置的双射为 i，跳过编码 s 不在 i 的像内，则解码仍为单射：候选回复落入 i 的逆映射，s 唯一落入 skipped。该选择及其返回后的分支保存在原 Effect 的帧中；普通单选保留既有空集/单候选语义。内容工具可因此复用发现候选的生成/临时实体/清理，并用字面参数分别组装手牌获得和宝典洗入。

内部 inspectRuleQuery 仅保存 Definition 到链接绑定的静态 WeakMap。它对调用者提供的本 Program Context 执行同一个 evaluateQuery，并保留 Query 声明的读权、依赖及输出数据检查；既不调用 Effect，也不构造或初始化其他 World。inspectRuleQueue 只观察该 Context 的实际队列长度。这是差分的只读关系，不是第二执行器、生产 IO 新字段或快照旁路。入战不可变记录现在保存完整外层游戏读模型，公开接口只投影公开字段；规则求值不得读取该记录替代资源、牌堆、随机或遗物 owner。

暂存卡牌的观察通过第三层 combatStorageViews.slots 的纯修正贡献组合；卡牌仍由实际区域 owner 唯一持有，展示层不枚举具体状态定义执行规则。固定参考中禁用的斗兽场/记忆游戏，以及源明确为空或保留零初值的遗物逻辑，与其正常可达机制区分记录；不能据游戏常识添加参考中不存在的效果，也不能把这一限定用于绕开正常可达内容。

## 42. 内容私有计数与嵌套奖励的观察关系

私有计数仍属于其定义实体，观察 Query 只通过该定义安装的纯 modifier 贡献值。对没有该定义的 actor，默认值等于源未持有该机制时的初值；持有时读取原组件，不能按历史重新推算。由 Query 的读权和纯性，不会修改队列、随机流或帧。燃烧次数、炸弹三个槽、盘旋剩余张数、遗物计数和复制/药丸标志据此纳入未来状态关系；卡牌区域的受限牌计数来自实际区域及装配期类型标记，打击计数来自实际登记集合。比较器须拒绝任一计数、身份、顺序、随机或待决选择变化，不能只比较最终 HP。

领取遗物可在获得程序中开启嵌套窗口。为模拟源同步调用返回前对奖励容器的删除，创建一次性领取凭据，保存〈run,index,done〉。嵌套请求前或获得返回后，由同一个 settle Effect 删除当前容器的对应索引并置 done；第二次 settle 无操作。对这两种控制流归纳，删除恰好一次，且先于下一次对外发布；无嵌套请求时仍在获得之后删除。凭据和 done 是 Context 数据，恢复不重复领取。嵌套程序完成后是否恢复旧窗口，由内容调用的显式返回决定；不能将所有窗口一概当成可返回的 UI 栈。源删除后的 Sapphire 比较也在删除之后对新容器求值。

以上是表示构造与前提，不等于当前实现已验收；完整正常 run 和等待恢复仍以末尾执行结果为准。


第 42 节实现修正：组件的声明位置不等于写权。defineComponent 在模块 build 中声明但未被 m.own 领取时，仍是实体私有组件；只有 own 建立静态写权。链接器保存这项静态关系并据此拒绝把受保护组件附着为私有数据、直接更新或越权读取，运行期私有写入仍须 active source 等于目标实体。即使拥有者模块未链接，已经领取的组件也不能被误当成无主组件。该关系属于 Program 静态图，不加入 Context。

装配期 utils 的有限嵌套定义由当前 builder 捕获并加入同一静态链接图，捕获窗口在异常时也恢复。新 Query 仍通过原 validateQueries 进行依赖、读权和环验证，新的 Effect 仍只降低为原 Card Core 步骤。事先存在但没有显式链接的外部 Effect 继续拒绝；不能借此加载运行期代码。此扩展的前提是作者构造的静态图有限，且新 Effect 不捕获外层 Value/Local；跨帧数据必须作为参数传递。该前提与原有限 CFG 装配前提相同，Context 结构和运行期控制机制没有变化。

固定源的“是否免费执行”与牌自身 freeToPlayOnce 分开；复制机会可免支付但不写入牌自身标志，免支付策略不能被当成这个标志的别名。Corruption 的首次生效明确遍历四个实际牌区，按每张牌的当前费用更新原实体；以后抽牌/进入手牌仍通过其既有 hook。全部只组合牌区查询与牌实例 owner Effect，范围、顺序和当前出牌快照没有第二份执行副本。

绿色钥匙精英房间通过正常入战内容 Effect 组合资源及状态操作，发生在敌人 prepare 之后、玩家遗物开战之前。资源加成、力量、金属化、再生都是原有 owner 原子与定义引用。空阵容槽不创建 actor；其固定源外观可由不可变的入场参数投影，因为它不可行动/不可选为目标，后续在此槽召唤会完整替换该占位描述。此投影不能取代实际敌人的资源或状态值。

附加动作不结束当前领域选择：choose 在原 Effect 帧中循环，记录并派发附加动作后重新发布同一选择，只有属于调用者原候选集的结果才返回。由循环不变量，调用者的 Local、待决奖励和后继未被附加动作消费；保存恢复保留同一个循环位置。阵容替换由 owner 接受显式旧/新实体映射，同时提交敌人序列、当前牌目标、排队机会目标和上次目标，避免把同一阵位的后继错当成已消失的位置。映射的旧实体必须在原阵容、新实体必须在新阵容，第三层不能越权修改这些字段。

固定参考的 GameAction::execute 在处理药水后缺少 return，会继续按同一 bits 操作当前屏幕。seed=0 正常开局的随机脚本在第 3 个合法输入丢弃药水时因此尝试获得 INVALID 卡并在 Deck.cpp:178 断言退出。测试以 upstreamAdvance 精确保留并验证这项原 helper 缺陷；正常参考驱动只对冒险药水改为调用原 GameContext::discardPotionAtIdx/drinkPotionAtIdx 一次，不修改固定 src/include，不注入状态或更换游戏规则。独立期望要求丢弃只改变原槽位、数量、决策编号和可选域，其余完整状态相同；新原生/受控程序均须符合。三条成功碎心动作带没有冒险药水输入，仍逐步使用原 GameAction/Action。此处是明确的测试驱动边界修正，不能宣称未经修正的原 helper 在这些输入上可运行。

棱彩碎片保留源的正常出现资格。固定 GameContext.h 的 disablePrismaticShard 恒为 true，获得时的法球扩展也是源 TODO，因此此固定基线没有跨色奖励或法球副作用；不能因此把它从商店或合法遗物池过滤掉。


### 固定源内容程序的边界（最终内容差分）

元数据不蕴含可执行效果。147 种元数据中的 14 种外职业原型，在固定 C++ 的 useAttackCard/useSkillCard/usePowerCard 没有 case，执行进入显式断言；对应新程序保留具体定义身份并明确 fault。正式矩阵分别检查两侧失败，不能用空 Effect 将它们宣称为已实现。

对于参考已实现的程序，动作队列顺序也是状态关系的一部分：Jack of All Trades 依次生成 c1、c2 并向队首插入，因此实际创建 c2、c1。Dark Shackles 的参考参数是正 9／15，且仅在原目标有 Artifact 时排入 Shackled；Panache 的参考原始计数初值为零、下个回合才设为五，每次使用递减且触发后不重置。新程序保留这些具体源语义，数学表达能力本身不证明其符合商业原版说明。


### 有序槽位与已确定参考缺陷

敌人阶段令槽位游标为 c，实体槽位集合为 S，总长度为 n。下一候选是 min {s∈S | s≥c}；原子 seek 保持 c 单调，取机会后推进至当前 c+1。集合可在行动中合法变更，但新实体的 claim 位与旧实体独立，已 claim 的新机会不会再次执行。没有候选时 c 至少为 n；内容主动前移越过 n 时保留实际值。该规则同时表示空槽、成批召唤、分裂跳过新机会与源保留的越界结束游标。RNG 抽取不能提前跨越其他抽取：两个地精类型都在两个 AI roll 之前确定，延期 roll 只是构造参数与普通调用顺序。

固定参考 `RelicContainer::replaceRelic(o,r)` 的循环错误地搜索 r 并再次赋 r，故遗忘祭坛实际只改变两个 membership bit，展示列表仍保留 Golden Idol。唯一生产语义移除旧遗物并获得 Bloody Idol。正式事件场景精确断言参考原展示列表未变、旧 bit 清除、新 bit 设置，再独立构造预期的移除／获得列表，完整比较其余游戏状态；这是明确列出的源差异，不是严格基线通过或任意字段忽略。

源 Matryoshka 的获取计数为零；Toolbox 使用 Discovery 选择界面却不设置 haveUsedDiscoveryAction；Entropic Brew 的 limited 抽取会先丢弃一次样本，再按稀有度且排除 Fruit Juice 重抽。Designer 的 case 3／4 贯穿到 case 5，立即执行升级／回地图回调，撤销尚未回复的移除界面。新程序按具体参考保留这些顺序与计数。

| Designer 的两个布尔选择与活动事件缓存金额 | 对应事件帧内首次请求前 assign 的值 | 不同初始选项、选择后继续、回调贯穿、奖励与永久牌变化 |
| Falling、N'loth、We Meet Again 的候选位置与身份 | 候选 Local、定义引用、永久牌／遗物 owner 实体 | 不同选项、重复牌、多选逆序移除、父关闭后的两代分支 |
| 牌选择候选、已选集合、恢复位置、RNG 引用 | 选择 owner 与活动帧／作用域 | 非法回复不推进、同／异输入 fork、逐等待恢复、冷恢复后下一边界 |

固定源正常发布的等待点中，已完成敌人的跳过标志与额外空 roll 已被消费；尚有中途选择的出牌／回合流程则保留上述任务及帧。新增内容不能仅凭同一 screen 标签套用这些对应：新增捕获必须是 Context 可达数据，并另给可区分的后续。这份手工模拟关系及有限差分不是对所有改模程序的形式化验证，也不把已列出的源缺陷当作商业原版规则。

觉醒者的两次阶段转换进一步区分死亡清除与复活动作：首次死亡清除当时的负面状态；此后由 Bash 等效果施加的负面状态必须保留到复活之后，复活只钳制负力量为零，不再次全量清除。对应第三层以公开 powers 查询／提交原子组合表达，四个阈值／死亡／再生场景实际执行并对比完整战斗状态和有序合法域，不以常规九回合场景替代此分支。

对字符串属性存储，抽象状态是当前分支的`(name,value,insertionOrder)`集合。共享名称槽表只定义寻址，不定义属性存在性；存在性由分支值表决定，枚举由分支顺序表决定。因而兄弟分支分配同名或不同名槽不会改变当前分支的查找与枚举；删除重插取得新的分支顺序位置。每次写只修改该分支的持久索引路径，fork及首写均不遍历其他属性。此论证不替代实际结构计数及恢复用例。

### 最终性能失败后的值传递与表示融合证明条件

私有边界凭证的三个集合可等价编码为同一弱表的位：owned=1、tree=2、dense=4，增加证据按位或，查询与原集合成员关系逐项一致。凭证仍不附着于公开对象。已审计parser的结果根足以证明本次比较的形状/别名；若最终沿用原基线，丢弃结果子节点的凭证不可观察；仅在结果被选为发布值时才登记其子投影，不改变公开副本和parser调用次数。

规则值融合只对编译期证明没有自定义回调、opaque解析、默认值或变换的SchemaPlan使用私有结果交付。先lower获得独立数据图，随后纯计划只读该图并构造数据节点，因而结果不存在作者可写别名；原地冻结该私有结果与再次复制再冻结在值/别名拓扑上等价。任何可能保留引用的计划仍执行必要隔离。不可变块已由私有品牌证明只有固定数据字段，复制可直接读取这些字段，已拥有的不可变版本直接作为只读引用交付；用户明确内部持有引用，旧实现每次读取的新副本身份不再作为接口契约。写入发布新版本，先前引用保持旧值；别名和循环保持，公开可写出口仍独立。

COW回调遍历与原迭代器按同一radix顺序列出同一键值，消除的pair和iterator从不进入作者可见状态。fork仍只共享根并失效所有权令牌，首次写只复制有界路径。完整枚举只用于本来要求枚举的导出/反射；GC继续使用分片游标。

对固定Program的trace，位置序号与(effect,block,index,kind)一一对应；深度逐项保存。因此两个等长数值序列可无损重建全部DTO。外部存档准入逐项验证序号在布局内、深度为正安全整数，并拒绝长度不等；公开trace、故障前缀及分支记录不变。
