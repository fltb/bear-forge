# 并列卡牌执行后端

本方案按 2026-10-17 用户指令实施，替代把 async 组合库等同于专用执行器的结论。旧通用编译/执行能力完整保留；卡牌后端不经过通用编译器。对外 Core、Instance、BaseGame、capture、persistence 协议保持不变。历史组合库和通用执行测试继续有效，但不能证明本后端的实现。

## 当前优化目标：完整原生游戏与受控增量分别验收

本节按用户最新纠正替代此前“裸 Core → Instance → BaseGame 逐层加预算”的性能口径。用户已要求持续推进并明确继续，当前按本节恢复实施；目标与方案不表示实现已达成。进度仅在 plan.md 维护。

### 完整游戏基准

原生基准是通过统一 Card Core 执行的完整、可交互 GameHost：使用生产 cardDefinition 和 GameContract，包含初始化、规则结算、玩家观察、完整合法选项、动作与会话输入验证、事件投影及真实交付、终局和关闭。Instance 是这一局的唯一运行实例，BaseGame 是游戏交互接口；接口职责不要求串联多套世界副本或所有权管理。

原生默认只承担正常游戏工作，不启用训练采集、COW、分支版本、存档准备、核心步骤记录或外部调用记录；未请求执行限额时，也不运行受控步骤预算计数。游戏自身需要的事件和历史仍保留。显式要求审计/记录的消费者按原有可选能力另列配置，不能伪装成默认原生成本，也不能删除已请求的记录。使用现有提供者装配及 LoadedCore 的可选 capture/persistence 语义，不新增公共开关、字段或另一套执行接口。

受控基准是同一个完整 GameHost，在相同游戏工作上开启状态隔离、预算、完整外部记录、核心记录及保存/恢复/fork 能力。正常对局包含这些能力的维护成本；实际 save/restore/fork 另做明确次数的负载，不能把未调用的持久化序列化混进每一步。模型推理、训练更新和网络等待不属于执行器基准；本地玩家策略使用同一确定脚本，其计算计入两种模式，不能在其中一边换成预先算好的动作。

两种模式必须逐请求比较玩家观察、合法选项、动作接受、事件交付与终局；基准必须绑定实际事件消费者，不能因没有 onEvent 而跳过正常游戏事件路径。固定回复带只用于差分和可重复诊断，裸 CardMachine/Instance 计时只定位局部成本，不再作为完整原生基准或包装预算的分母。

### 原生游戏自身的优化目标

原生路径必须先独立审查和优化，不能将现有 Core 或 GameHost 的全部耗时认定为不可避免的底座。检查范围包括规则 helper、CardMachine.current/export、Frame 投影、schema、GameContract、Controller、binder，以及初始化和关闭时的实际分配。

| 目标 | 验收标准 |
| --- | --- |
| 唯一执行现场 | 每局只有一份权威可变世界及结算栈；接口外壳不持有第二份可推进的世界 |
| 未启用能力零负担 | 默认原生中，COW/版本页、记录容器及条目、训练轨迹、存档容器及序列化的构造次数与分配字节均为 0，未请求的受控预算计数为 0；仅关闭出口而仍内部构造不合格 |
| 内部转发不处理世界 | 纯内部 Core/Instance/BaseGame 交接新增的全图复制、全图准入/比较和全历史扫描次数为 0；请求身份与驱动管理只处理本次元数据 |
| 删除原生多余路径 | 同一逻辑边界内重复导出、解析、选项计算、观察构造、历史扫描须逐项判断；无独立语义作用且等价性已证明的重复工作清零，不能只加速复制循环 |
| 必要输出按实际交付付费 | 回调/玩家/公开返回仍符合原隔离语义；每次完整处理必须对应具体输入、规定校验或实际消费者，不得将内部转发称作外部交付 |
| 生命周期 | 关闭后释放执行世界和派生根；无记录配置不因隐藏记录保留旧世界，重复创建/关闭不积累旧局引用 |

数据处理是否冗余按语义判定，不能把“所有 schema 只执行一次”作为口号。同一个逻辑检查的多份框架副本可消除；不同逻辑边界的 parser 调用、拒绝位置和自定义检查语义继续保持。用户已选择 GameContract 纯只读借用稳定发布数据；schema 与真实外部消费者保持独立普通数据。共享载荷须证明与活动世界及外部可写值分离，不能仅依赖 TS ReadView、freeze 或函数名称。

全历史扫描也须检查原生游戏自己的实现。例如 Forge 的事件序号计算、两游戏观察历史构造，以及斗地主 Frame 规范化都属于待审查路径；这些不是已经确定可删除的工作。增量计算必须保持事件身份、顺序、隐藏信息、别名及错误行为；若既有公开结果要求完整历史的独立副本，则实际交付成本单独报告，禁止删历史换取线性成绩。

### 受控能力的优化目标

受控路径复用同一正常游戏工作，不另造游戏循环、观察/动作流程或完整数据模型。原生优化若改变共享实现，必须同时重测两种模式：不能把共同收益全部记为 COW/记录优化，也不能只因受控变快就接受原生退化。

| 目标 | 验收标准 |
| --- | --- |
| 受控额外成本可归因 | 相对同版本完整原生，分别说明 COW 访问/写入、预算、两类记录和必要隔离成本；总差额不能命名为笼统包装费 |
| 分支只处理根与请求凭证 | Instance fork 不扫描世界/历史、不序列化、不初始化、不重放；BaseGame 只允许按当前请求数重建身份；中位 fork ≤0.05 ms 的既有门槛保留 |
| 首次写不补全量复制 | 分支首次推进按实际触及的共享节点/页和索引路径分离；记录旧前缀共享，追加不扫描旧记录 |
| 无额外世界管理层 | COW 管唯一 Context；Instance/BaseGame 引用稳定载荷，不各自再建版本系统或持久化世界 |
| 持久化与记录正确 | 完整记录、重放、跨进程恢复、父子隔离与释放继续验收；无记录诊断仅归因，不能替代受控正式成绩 |

### 复杂度与数据口径

保持规则实际读写、请求数和真实交付量不变，单独扩大无关世界与历史（沿用 32、4,096、32,768 对象负载）。原生纯包装额外访问无关节点的数量必须为 0；受控只允许必要存储寻址和受影响页/索引分离，不得新增整世界遍历。结构证据和计数为主，不能用单次计时“看起来持平”代替复杂度证明。原生规则如果已经有重复历史扫描，也必须独立定位，不能以两模式同样低效认定同阶目标完成。COW 页大小、宽对象复制、索引深度及回收扫描分别说明，不能把存储维护藏到首次推进或下一次边界。

重新取得完整原生基线 N0 和完整受控基线 C0；每次候选同时测 N1/C1，分别报告 N1 对 N0、C1 对 C0，以及 C1−N1 和 C1/N1。新增能力导致的差额不作为原生优化收益；关闭原先误开的记录须单列为配置修正，不能与同配置下的实现提速合并。

两游戏分别报告每局/每个已接受决策的中位、均值、P95、吞吐、累计分配、GC 时间/次数、保留堆和关闭后堆；RSS 仅作进程指标。冷装载/初始化、热对局、关闭和显式持久化分别报告，同时保留包含创建和关闭的整局总时。基准使用相同硬件/Node、生产定义、种子、确定玩家及事件消费者；正反序独立进程，每序至少 8 局预热、24 局采样，准备和正确性断言不计时，诊断/测试/构建不与计时并行。

原生与受控各自的同配置中位/P95 回归上限为 5%；一侧改善不能抵消另一侧退化。此门槛仅防退化，结构目标未达时不能据此宣布优化完成。绝对 ms/局及受控倍数预算须在 N0/C0 和必要工作归因完成后、实施候选前写入 plan.md；当前不从不等工作量的数据编造下界。旧 3.55/4.12 ms 裸 Core、20.89/27.50 ms 带记录完整路径均不是新原生基线；18/26 ms 预测和旧逐层 5/7/10/15 ms 预算不作为当前目标或合理下界。

实施先纠正能力配置和完整工作量基准，再优化原生自身，随后优化受控增量，最后做同版本双模式验收。原生显式审计使用已有 recordCore:true，同时提供完整 capture；默认无记录时不发布 capture。实验装配等需要记录的消费者显式请求，普通 CLI 不自动重放。源码级语义检查、结构检查和性能成绩分别报告。

作者游戏源码只声明公开规则、schema 和契约，不引用 boundary/runtime 私有所有权工具，也不按 schema 结构自动信任任意被替换的 parse 方法。此前将已审查 schema 私有构造凭证直接放进游戏模块的实现已撤回，相关较快数字不作为结构验收结果。用户已明确选择纯只读借用：GameContract 在两模式下直接读取私有稳定发布值，schema、玩家及公开返回隔离保留；未知提供者的值先隔离准入。证明见 card-core-proof.md 第 13 节，实际完成及指标见 plan.md。

## 执行定义

Card Core 共享不可变规则包：稳定规则身份、状态初始化、端口 schemas、静态效果定义。效果由 operation、sequence、branch、repeat、forEach、invoke、request、return 组成。普通查询及有界规则操作是受信任同步函数；不能把可恢复流程藏进 async、生成器、宿主闭包或外部状态。执行器不分析或编译 TS，不要求作者填写 PC；装载只为嵌套定义分配稳定块身份并校验引用。

Instance 动态根包含世界状态、结算帧、局部数据、等待信息、结果/故障、随机状态及必要游标。静态函数/模块导出不进入动态根。invoke 帧独立拥有 input/locals/返回目标；结构组合的块共享所属调用的局部环境。forEach 在进入时捕获成员及顺序并保留元素身份，每个成员有独立调用环境。repeat 每轮子块完成后重新求条件。动态调用通过规则包中的效果身份选取，不生成活动函数。

request 发出端口输入后停机；收到通过外层校验的一次回复才写入指定结果槽并继续。输入在跨边界时隔离；机器等待期间禁止内部推进，因此内部待决载荷可以共享当前图中的引用；交给宿主时必须隔离复制，回复后先解除等待引用再修改世界，不在每次请求时复制并重新登记整张游戏图。return 丢弃当前调用尚未完成的结构块，将结果交给调用者；顶层 return 才是终局。没有活动帧且没有 return 定义为显式 undefined 结果。异常/预算耗尽为 fault，不能保存故障现场或假装回滚。

## 两种运行模式

原生卡牌模式采用相同定义和推进器、普通实例数据；内部连续同步执行，到 IO 才返回。不声明保存和 fork 能力。受控卡牌模式使用分支隔离数据存储、有限步预算、边界校验、调用/返回记录及可选内部步骤轨迹，支持 save/restore/fork。受控指本领域定义下的确定性和状态管理，不冒充旧通用编译器对任意 JS 的准入/宿主隔离保障。规则操作必须是确定、有界、无宿主副作用的受信任实现；任意回调内部无法由步骤预算抢占。

## 数据与分支

受控存储仅接纳原始值、普通数据对象和数组的引用图；拒绝函数、资源、访问器及特殊对象。每个节点有稳定内部身份，帧/局部值/世界之间的引用通过同一图保持别名与循环。外来数据复制准入，规则操作不得保留或继续修改已移交的原生对象；跨步骤值通过局部槽或状态引用传递。父子分支有独立访问视图，禁止把一个分支的活动代理注入另一个分支。完整根导入完成及每个 IO 边界后，丢弃该区间的原始对象身份索引；已管理的节点引用和别名继续保留。fork 只复制节点编号上界，各分支独立分配后续节点，临时子分支不推进父分支的编号。私有发布叶缓存附着于实际存储行的非枚举派生属性，写入前失效，COW 克隆不继承；它不进入逻辑字段、快照或公开数据。

持久索引按所有权 token 分离，fork 共享根并使父子后续写入均分离。数组按固定大小页分离，避免首次追加复制整个历史数组；对象修改只分离本节点字段。fork 与首次推进均不扫描整个状态图。完整快照按可达图编码，允许 O(可达数据) 成本；不能将这一成本称为常数时间。不可达数据在完整边界按阈值标记回收，父子分支首次推进跳过回收；回收不得失效另一分支的节点。规则要求导出的 IO 视图可按载荷大小复制，不能将这种输出成本混作 fork 准备成本。不可达数据回收与快照编码、fork 区分，禁止用完整重放代替恢复。

## Instance 与外层

卡牌执行器实现现有内部 Execution 接缝：current、advance、dispose、snapshot。Controller 继续处理独占驱动、绑定回调、输入输出 schema、调用凭证及记录。Card Core.start 仅初始化新局；fork 和 restore 不调用初始化。BaseGameBinder 继续使用各游戏原 GameContract，不修改隐藏信息/合法动作/会话语义。

在内存 fork 时，执行图根、待决外部状态和 Records 前缀都应共享不可变数据；不得经 Controller 构造器再次复制整个等待载荷。对宿主的 inspect/capture 输出仍须隔离。保存关联规则身份，保存状态、CallId 和记录前缀；恢复使用新 InstanceId、原 CallId、空宿主绑定。transfer 保留身份并撤销旧句柄。事件发布批次和时间点严格沿用游戏，不因内部效果数改变 BaseGame 决策数。

## 记录与重放

权威外部记录沿用 started/called/returned/completed/faulted。只录已接受的回复；回调失败/取消/非法回复不成为成功返回。重放从 setup 用同规则包驱动，逐一核对每个 called 的端口/输入、returned 及终局/故障；随机状态必须显式，不能重新询问外部策略。CallId/InstanceId 使用保持引用关系的规范化，不删除业务身份或更改数组顺序。可选核心步骤轨迹记录稳定效果/块位置及步骤种类，验证内部执行顺序；不能把记录重放成本加到正常 fork/restore。

受控模式默认按实例记录核心步骤，readCardTrace 通过伴随能力读取，不向共用协议新增字段。其持久 Records 前缀随 fork/restore 继承，包含在卡牌快照中；replayCard 可同时核对外部记录和核心轨迹。trace 回调只是有界诊断观察器，收到隔离 DTO；其修改/异常不影响权威记录或游戏执行，异常不会伪造成不可重放的规则故障。

## 迁移

Forge Duel 将主循环、发布、动作、卡牌与攻击子步骤声明为同一专用执行器的静态定义；规则原语及原 GameContract 继续复用。斗地主将世界、随机流、published 和当前 frame 等全部纳入实例根，发牌改用显式随机状态的同步规则操作，保留全不叫重发、双 slot、控制输入和事件批次。两游戏的正式执行定义统一为 cardDefinition，原生/受控模式都由同一卡牌 Core 执行，再接现有 Instance/BaseGame。不能把新增命令等同于完成游戏、实验及演示入口迁移。通用编译后端保留用于通用程序；旧游戏程序仅作测试及历史参考。

斗地主专用路径的当前 Frame 仅借用唯一世界，不在每轮再次复制/登记整张世界。事件与决策之间不修改世界；仅移动 published 并替换 Frame.events。出口仍隔离复制，公开 FrameSchema 保持，接受动作后旧 Frame 不再读取。此具体优化的证明见 card-core-proof.md 第 9 节，不改变通用入口的旧 frame helper。

借用不能改变故障顺序。规则可达状态保持结构/牌数/评分不变式；对可能无界的 deal/stageSequence/boundarySequence 和 deadline，每轮在 event 前检查安全整数，越界时回退原 frame 校验，保留原错误及零额外事件。不得把合法极大时钟导致的失败推迟到后续 decision。

定义可提供静态纯出口投影 project，仅接触已隔离的导出停止态。斗地主在此对 decision/done 用原 FrameSchema 规范化别名：last.play/事件、result/终局事件在旧 Frame 中是分别拥有的值，不能把世界内部共享关系直接作为外部 Frame。投影不会重新登记到执行图，保存/恢复以相同 D 的投影解释当前外部状态。该要求来自证明和完整轨迹检验中发现的实际缺口。

## 正确性和性能验收

数学语义与证明见 card-core-proof.md，证明中的前提必须在代码/测试中落实。先完成语义证明与缺口回填，再写实现。证明不是机器检查的实现证明；测试不能代替全称命题。

同一回复带比较独立旧原生、卡牌原生、卡牌受控完整 IO/终局，以及 BaseGame 观察/动作/事件/控制、非法回复、文件恢复、分支异输入、父关闭和错误预算。复杂样例覆盖动态嵌套、局部返回、同场面不同续接、来源/对象身份和捕获遍历。

正式基线与验收按本文件“当前优化目标：完整原生游戏与受控增量分别验收”。生产 GameHost 的两模式执行同等完整游戏工作；旧参考及回复带只用于差分和诊断。裸 CardMachine 和 Instance 数据不能作为完整原生下界或合理包装预算。无实测时不承诺原生倍数；优化以归因证据和完整语义为约束。

## 入口迁移与薄封装执行方案

本节保留上一轮入口迁移、所有权约束及实施记录。数据隔离、协议和正确性义务继续有效；逐层成本模型、固定转发数据流及旧数值预算由上方完整 GameHost 目标替代，不再据此恢复循环优化。具体完成状态仅在 plan.md 维护。

### 目标与边界

正式路径只有同一份卡牌定义的两种模式：

```text
cardDefinition + 生产 GameContract
    → 同一 CardProgram / CardMachine
        → 原生数据，或 COW + 预算 + 核心记录
    → 同一 Instance 协议
    → 同一 BaseGame 协议
    → 对局、策略、实验、演示、记录重放
```

通用源码编译后端继续服务通用程序，不参与两款卡牌游戏的正式装载。旧游戏循环仅留在独立测试参考中。不能把 Card Core 包成 async Program 后重新交给通用编译器，也不能保留两套正式游戏循环。Core/Instance/BaseGame、GameContract、capture、persistence 的公共字段、枚举和方法不变；新方案不引入公开的 fast/unsafe 参数、新后端枚举或私有推进旁路。

薄封装的含义是：驱动、凭证、租约和游标只处理小量元数据；大载荷只为必要的准入、规定的投影及实际交付付费。不承诺大 IO 的 O(1) 复制，也不把规定的历史、观察、合法动作或记录删掉换速度。

### 三层职责与成本归属

| 层 | 应保留的工作 | 应消除的工作 |
| --- | --- | --- |
| Card Core | 共享静态规则，在 Instance 的独立上下文中推进世界和结算栈；受控模式执行实际写入的 COW、预算和步骤记录 | 通用 JS 编译、Cell/原生对象适配、在游戏外另写规则循环 |
| Instance | 端口校验、驱动租约、停止态、调用身份、外部记录、公开交付隔离 | 同一私有停止态在状态和记录间反复复制；已准入载荷的重复结构检查 |
| BaseGame | GameContract 投影、观察、合法动作、动作/控制校验、请求凭证、玩家回调 | 接受 run.state 后再 inspect；每次回调前重建规范 view；fork 时重新扫描世界和计算合法动作 |

推进的数据流固定为：Core 导出停止态 → Instance 建立私有规范载荷并共享给记录 → run 交付独立停止态 → BaseGame 认领这份尚未暴露给其他接收者的副本 → 校验契约产物并保存私有 view → 玩家及公开查询各自取得副本。每个作者 parser/投影函数仍取得独立、普通、可修改的入参；返回值仍须验证和隔离。回复则由 Instance 保留私有记录原值，向执行器交付独立副本，防止执行器修改历史记录。

验收时分别报告规则执行、COW/核心记录、Instance 增量和 BaseGame 增量。BaseGame 增量包含契约规定的观察及合法动作计算，另用诊断定位其份额；完整时间不能全部归因于驱动包装。元数据管理应为 O(1)，BaseGame fork 为 O(当前请求数)；准入、回调隔离及真实公开交付的成本按对应载荷大小计，完整记录则按实际新增记录量计，不扫描旧历史。任何“薄化”都要明确消除了哪次遍历，而不能仅移动其计时归属。

一次接受输入的执行约束如下，作为代码审查和反例测试的依据：

1. BaseGame 校验请求身份和动作，调用既有 Instance.run；Instance 保留验证后的私有回复，给 Core 独立副本。停止态和记录可以共享私有载荷，执行器不能取得记录的可写引用。
2. CardMachine 从当前结算栈推进到下一端口或终局。静态规则和校验函数复用，只有当前实例的可变世界、局部值及控制位置随推进改变；不得重新运行旧游戏循环或初始化程序。
3. Instance 建立新停止态，BaseGame 直接消费本次 run.state。正常推进不追加 inspect，不为把同一载荷从状态放进记录而再次完整复制。
4. 只有实际发布新 view 才替换私有规范 view。按原有顺序执行必要的契约回调、schema 和逐动作检查；交付玩家回调或公开调用者时建立对应的独立可变副本；纯 GameContract 适配借用稳定发布数据。不能把不同逻辑边界的一次次校验合并成一次。
5. 替换或关闭时解除旧缓存根，记录按既有释放协议处理；fork 共享私有不可变结果并重建当前请求凭证，不扫描世界、历史或重新计算合法动作。

成本分账采用 `完整耗时 = 规则推进 + COW/预算 + 核心记录 + Instance 边界工作 + GameContract 计算 + BaseGame 边界工作`。两层边界工作分别列出准入、parser 及结果检查、交付复制和小量驱动元数据；总耗时用无插桩进程测量，分项用单独诊断。层间时间差包含该层增加的实际工作，不能直接称为纯函数调用开销。若载荷大小为 B、当前请求数为 R、新增记录量为 L，则必要数据处理分别按实际载荷 B 和新增记录 L 计费；驱动元数据不应随整个世界或历史长度增长，BaseGame fork 仅允许 O(R)。

| 问题 | 已定位代码与成本 | 本方案处理 |
| --- | --- | --- |
| 基准存在无 Core 的 native 分支 | runtime-card/tests/benchmark-support.ts 直接调用传入的旧 program.run | 删除该正式分支；旧参考仅生成期望轨迹 |
| 基准用了旧 GameContract | 两游戏 card-benchmark.ts 从 tests/reference 取契约传入 BaseGame | 实际执行只传 src 的生产契约 |

| 每层重复处理整张数据 | boundary read 与 runtime-card schema wrapper、binder 中的 copy(view)/read/多次 parse | 私有已验证数据内部复用，真实回调/公开交付仅做必要隔离 |

### 数据所有权与校验规则

采用“私有不可变快照 + 明确的交付复制”。私有快照是从当前停止态导出的数据，不是活动世界或 COW 代理。每个新停止边界生成新快照，推进只替换引用；同一快照可供停止态、记录和适配元数据共享。禁止冻结规则世界，禁止在内部流转时反复复制同一快照。

| 数据位置 | 所有权与处理 |
| --- | --- |
| 活动规则世界、调用栈、局部值 | 仅当前 Instance 拥有；原生或 COW 存储，按原语义修改 |
| 私有停止态、已验证 view、记录载荷 | 已隔离、已准入的不可变数据；框架内部可共享引用 |
| schema 入参 | 独立普通副本；保留 parser 调用、完整准入及值保持比较 |
| GameContract 适配函数入参 | 按用户确认的纯只读契约借用稳定发布值；与活动世界和外部可写数据隔离 |
| Instance/BaseGame 的公开返回、玩家 handler 入参、capture.read | 返回独立可变数据副本，调用方修改不影响内部或其他接收者 |
| 外部回复与适配返回值 | 外部回复和新建未知图按原规则准入、隔离、校验；只读适配原样返回已拥有根时可复用基线，schema 仍执行 |

内部使用不可伪造的所有权/准入凭证，绑定具体对象和其验证结果；凭证不进入公共 DTO、记录或快照。只有框架已经证明无外部可写别名的数据，才可以少一次内部复制。不能仅凭“对象来自 Core”“对象 frozen”“schema 身份相同”推断可共享；尤其 project/schema 的返回对象可能被回调保留。无法证明所有权时保留安全路径，不按游戏名称设豁免。

私有发布值保持普通对象和可变属性描述符，不用冻结或代理实现借用。GameContract 可反射读取字段、键序和属性，保留的只读引用在推进后仍指向旧发布值。借用的依据是用户确定的纯只读约定加实际隔离所有权；活动世界不直接交给适配函数，schema 和公开消费者的可变副本仍独立。

已有准入证明的标准对象/数组 DTO，交付复制保持循环、别名、空洞、undefined、特殊键和数值。先对照 V8 structuredClone；若它成为瓶颈，可使用带继承属性防护的私有 DTO 复制循环，保留实测有效的实现。原始输入、访问器、Proxy、资源及自定义结果仍先按既有准入规则处理，不能让快速复制提前触发 getter。准入归一化后的原型和属性语义应与当前 boundary.copy 一致。

schema 一次逻辑校验仍包含输入隔离、拒绝变换及别名一致性检查。对私有已准入基线，可复用基线、用一次快速克隆给 parser、准入并隔离其结果，再直接比较两个已验证图；去掉为同一基线重复建立的副本。普通 copy/read/sameData 对未知调用者仍保持原行为。不得缓存或跳过任意自定义 parser/refinement 的执行，也不得因只读而省略其原有拒绝行为；不同逻辑边界的不同 schema 不合并。仅在已有验证凭证确实覆盖相同静态结构检查时复用该结构结果，不能从 options 合法自动推出所有 action schema 已检查。

| 8. 重做验收与成本 | 两游戏测试/基准、runtime/card/game-host/experiments/CLI 检查、文档 | 独立旧参考仅用于正确性期望；正式基准只运行同一卡牌定义与生产契约。完整检查、结构检查和下述指标均有证据后，才重新标记迁移完成 |

第 2 步只调整 experiments 包内的装配依赖与配置类型；公共 contracts 不增加 loader/backend 字段。禁止用类型断言把 CardDefinition 塞进 ProgramModule，也不能用 async 包装满足旧实验类型。原通用实验由其装配提供旧提供者；卡牌实验由装配提供 CardLoader。保存的数据不包含这些工厂或静态函数。

第 3 步的实验实现指纹必须包含新增 card-engine/runtime-card 的真实源码与依赖清单；仅冻结卡牌规则身份或旧通用后端不足以检测执行器变化。恢复在装载前核对冻结指纹，拒绝变更后的实现；该实验冻结机制与单个卡牌存档的规则身份/格式兼容检查分别验证。

第 1–3 步完成且完整轨迹一致后，先采集尚未做薄化的生产接线基线，原始采样放 /tmp，再进入第 4 步。不能先优化再重建一个不同接线的所谓优化前成绩。

第 6 步第一轮不跨公开查询缓存任意作者函数的执行。复用的是已有规范数据及同次刷新中已验证的派生结果。view 的有效期跟随实际产生 view 的停止态：事件端口没有新 view 时保留原 view，不因 event CallId 改变就替换它。事件投影按既有玩家可见顺序处理；不提前执行本来不会触发的玩家观察或异常。失败回复、取消、过期凭证不得推进该有效期。

层级本身不是复制边界。对于 BaseGame 已接管的真实 Controller 句柄，框架核对原方法身份后，以本次调用专有的私有 receiver 调用既有 inspect/run；方法只在返回停止态时选择内部转发，全部检查与推进仍执行。普通调用、代理及包装方法取得公开副本，不能由外形或恢复原方法取得私有交接能力。BaseGame 绑定的恒定回复闭包只读取已准备 output，不读取调用输入；按该具体函数身份省去未使用的世界副本。任意作者或包装 handler 仍接收独立普通输入，回复复制、输出 parser、异步排队和取消保持。两项内部交接不新增公共字段、方法或推进旁路。

遍历优化以现有证明为条件：私有树的复制不建立身份映射；树基线与 parser 结果比较只用结果准入已有的集合检测新增别名/循环，非树保留完整映射。运行存储的普通对象不分配仅供数组整数索引使用的空分页容器。两项均保持外部数据、校验和分支语义，收益分别按分配和保留堆实测，不承诺据此达到全部时间目标。

后续候选仍须对应具体遍历：未知输入在一次准入中建立互不共享的私有基线和 parser 副本；密集数组复用已证明的索引结构；parser 结果比较同时完成准入与别名检查。两游戏固定、纯数据 schema 可在专用模块装配时选择等价的静态校验快路径，先比较值、键序、别名、失败消息和输入不变性；不得自动改写任意用户校验器。这里优化的是数据校验，不是编译卡牌程序。各候选先做对应反例回归，再单独实测；没有完整路径收益则撤回，不能仅凭微基准保留额外机制。

受控存储可在私有导出构造过程中建立准入及图结构证明，省去随后相同的描述符扫描。其条件是：根确属本存储、行内数据已经严格准入、结果尚未到达作者、没有任意 project 回调；公共导出和其他情况保留原路径。只含原始值的叶行按行身份复用私有导出，写入/删除/长度改变在修改前删除缓存，含子引用的行不缓存，避免漏掉后代修改。不为普通状态行增加修订字段；公开图不维护私有导出缓存。分支按原 COW 取得独立可写行，缓存不进入实例现场或存档。此类共享必须同时检查批量出口：卡牌 capture 按逻辑记录独立复制，隐藏新增的跨边界物理共享；单条记录内别名和循环不变，通用 capture 的默认整批复制不变。该实现只适用于已证明的存储构造路径，不能扩展成“来自 Core 的对象都可信”。

原生模式继续使用同一 structuredClone 隔离出口。无 project、实际调用宿主原始克隆函数且导出当前停止态时，可复用克隆构造出的数据字段保证，仅扫描支持的对象类型、别名与数组密集性；未知克隆函数、project、非协议对象不取得此证明，仍走完整准入。给活动规则的回复副本不取得凭证。该条件只消除重复描述符读取，不删除克隆、schema、结果比较或公开隔离，不能扩大成静态 schema 或作者回调的豁免。

### 必须先补齐的证明

在 card-core-proof.md 增补四个引理并先落实其实现条件：

1. 所有权引理：没有作者/宿主的可写引用能到达私有规范数据；公开交付的副本与私有图不共享可写节点；别名、循环、键和数值语义保持。
2. 组合细化引理：使用 run 返回停止态与再次 inspect 在同一稳定边界产生等价观察；消去 inspect 不改变接受、故障、取消或请求凭证。
3. 校验/回调引理：减少框架副本不减少所需校验、不改变自定义回调的隔离、调用次序、拒绝位置及后续可观察效果。反射或捕获引用的反例须进入正式回归；证明不成立的省略不实施。
4. 分支引理：共享私有派生值不共享绑定、可写控制状态或跨分支凭证；重建小请求外壳后与重新投影得到相同协议状态。restore 可以重建派生缓存，不能初始化或重放规则。

### 最终验收与交付

正式回归覆盖同一定义两模式、完整调用及别名、全部卡牌/目标、斗地主重发/clock/timeout/极大时钟、非法/过期/跨分支输入、取消竞态、父关闭、嵌套返回、预算、保存及真实新进程恢复。增加 callback/parser 保留与修改参数、反射、访问器/Proxy、特殊键、循环/空洞、公开返回值被修改及派生数据生命周期的反例。

结构测试必须证明两款正式游戏与 CLI/实验/演示不执行旧 program.run、不调用通用编译器，不以 tests/reference 契约驱动生产或基准；正常推进不会 run 后再 inspect。校验调用数、各所有权边界的复制次数及大图遍历应进入相应模块的正式测试，不写只匹配实现字符串或时钟阈值的脆弱测试。运行所涉模块 check、整仓 check/build，确认公共协议无差异；通用执行测试保留，不能删掉旧语义断言凑通过数量。

实际检查和指标仅回填 plan.md；日志、CPU/堆诊断和临时消融放 /tmp，不新建独立验收报告。交付时逐项说明入口、语义、结构及性能，未达项保持未完成。当前按完整 GameHost 新目标继续实施；提交、合并或推送仍须用户明确指令。
