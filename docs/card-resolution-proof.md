# 卡牌执行内核：形式语义与正确性证明

本文是 [卡牌结算设计](card-resolution-spec.md) 的数学附录，讨论同一内核承载斗地主和 Forge Duel 的充分条件。证明对象是下述抽象语义；生产实现、现有 TS 编译器和 COW 后端仍须分别满足这些条件。本文不是机器检查证明，也不宣称尚未实现的 card-engine 已与旧实例等价。进度仅维护在 plan.md。

## 1. 对象、假设与可观察行为

固定一个游戏规则包 G。不可变定义表为 D，包含效果代码、端口声明和规则操作。运行配置写作：

```text
C = ⟨σ, e, ρ, κ, w, q⟩
σ：实例全部可变存储，包括游戏状态、PRNG、发布游标和对象身份
e：当前效果；ρ：其参数及局部环境；κ：调用与返回续延
w：无等待，或当前端口请求及其续接位置
q：running | waiting | done(v) | fault(f)
```

这些符号是实际 Context 的逻辑分解，不要求新增公共字段或另建一份状态。ρ、κ 中引用的可变对象也属于 σ 的实例所有权范围。κ 表示现有 runtime 保存的执行续延；领域 frames 不另建竞争的 PC。D 不能持有随实例执行而变化的捕获值。

转移记为 `C —ℓ→ C'`。ℓ 为内部步骤 τ、端口调用 `call(p,x,c)`、回复 `reply(c,a)`、拒绝 `reject(a,r)`、完成 `done(v)` 或故障 `fault(f)`。实际端口名、批次、数据及回复均保留；publish 若调用 event 端口，同样需要等待其回复。Instance/BaseGame 的 accepted、pause、玩家请求等由原适配器从这些转移产生，比较时也属于观察。

执行轨迹是删去 τ 后的标签序列。随机凭证可经保持引用关系的双射 α 比较；业务 ID、数组顺序和私密字段不可借 α 改写。分支、关闭和持久化作为生命周期操作另行比较。

证明采用以下前提：

1. 规则操作在其声明的合法输入域上有界终止，返回值、故障及写集合符合约定；纯查询不修改存储。内存不足等宿主失败不在规则语义证明内。
2. 随机数来自 σ 中显式 PRNG；外部时钟与玩家输入通过原接口进入。给定输入顺序后，操作、遍历顺序、数值计算及异常处理确定。两个农民的回复次序不假设可交换。
3. 端口适配器在消费输入前完成身份、请求、类型与业务合法性校验；拒绝路径不改变规则状态、续延或待决请求。诊断计数若存在，单独列为非规则数据。
4. runtime 正确保存所有跨等待的活跃数据和续延，保持别名、循环、局部值及定义引用；所有实例可变读写遵守隔离。

这些是待实现满足的约束，不是从 TS 类型或测试通过自动推出的事实。

## 2. 最小组合语义

用下列核心项表达设计中的组合器；这是证明用记法，不要求游戏作者写新语言：

```text
e ::= return v | op(o,a) | bind(e,x.e₂) | if b then e₁ else e₂
    | invoke d(a) | while b do e | request(p,a)
```

sequence 是忽略中间返回值的 bind；checkpoint 是调用规则包检查操作或效果；publish 是构造原批次、执行 request 及在原位置更新游标的组合。responseWindow 由规则包组合，内核不预置优先权规则。

关键规则如下，省略未变化的配置分量：

```text
⟨σ, bind(e,x.e₂), ρ, κ⟩ —τ→ ⟨σ,e,ρ,(x,e₂,ρ)::κ⟩
⟨σ, return v, ρ, (x,e₂,ρ₂)::κ⟩ —τ→ ⟨σ,e₂,ρ₂[x↦v],κ⟩
o(σ,eval(a,ρ)) = (σ',v)
  ⇒ ⟨σ,op(o,a),ρ,κ⟩ —τ→ ⟨σ',return v,ρ,κ⟩
eval(b,σ,ρ) = true / false
  ⇒ if b then e₁ else e₂ —τ→ e₁ / e₂
while b do e —τ→ if b then bind(e,_.while b do e) else return unit
```

invoke 在 D 中查找定义，把实参绑定到新的词法环境，并压入调用者的返回环境；返回值交给原 κ。静态代码可共享，参数槽和局部变量不能共享。forEach 的“进入时捕获集合”与“每轮重新查询集合”分别展开，不能互相替换。

request 首次执行产生一个 call 标签并转为 waiting，记录请求凭证、待决数据及原 κ。waiting 不再执行该 request 或自动发出第二个 call。有效 reply 消费 w 一次，恢复为 `return a`，随后按返回规则继续；无效 reply 产生 reject 并保留规则配置。凭证校验还包含原协议的实例归属，不能只比较 c。

最外层 return 产生 done；操作异常按原错误契约进入 fault。done/fault 不再推进游戏效果，检查与关闭仍走原生命周期接口。故障不等于事务回滚，不能从这一规则推出 σ 恢复到操作之前。

## 3. 组合正确性与确定性

**引理 1（续延组合）。** 对任意有限、正常完成的 e，其结果为 `(σ',v)`、可见轨迹为 t，则 `bind(e,x.e₂)` 先产生相同 t 和 σ'，随后恰好从 `e₂[x↦v]` 继续。e 等待时，e₂ 不执行；e 故障时，e₂ 不执行。

**证明。** bind 首步仅压入返回帧。对 e 的有限执行步数归纳：内部操作、分支和调用均不消费该帧；request 把整个 κ 保留；只有对应的 return 消费该帧并绑定 v。fault 没有正常返回规则，因此不进入 e₂。空执行及每种转移都保持结论。□

**推论 1。** sequence 保持顺序且不重做已完成项；invoke 的子效果结果只交给对应调用者；branch 不执行另一分支。循环的每个有限前缀等价于相同次数的展开。嵌套调用和循环用执行推导长度归纳，不以“语法有限”推断递归终止。

**定理 1（条件确定性）。** 固定 setup、D、初始 PRNG 和按顺序到达的完整输入带，执行轨迹与终态至多有一个（忽略新鲜凭证命名）。

**证明。** 对每个 running 配置，e 的外形选择唯一规则，查询与操作由前提确定。waiting 配置对给定下一个输入的校验和消费结果唯一。done/fault 不推进。逐步归纳即得唯一轨迹；无限运行则每个有限前缀唯一。□

**类型保持与进展。** 若每个操作 `o:A→B`、端口 `p:A→B`、定义及返回帧类型一致，σ 满足操作所需的不变量，则每步保持该类型关系；可达配置或者可内部推进、等待外部回复、正常完成或已故障。证明逐条检查规则，bind 的结果 B 正好填入 B 类型槽。规则包必须另证其状态不变量的保持；动态输入必须经原 schema 校验。这里不证明非法 TS 回调永不抛错，也不证明外部一定回复。

## 4. 暂停、保存与分支

定义 `C ≅ C'`：实例可变图存在保持值、边、别名、循环和业务对象身份的同构；效果位置、环境、续延、待决请求、PRNG、事件发布游标对应；D 的定义语义相同。不能只比较棋盘或手牌。

**引理 2（恢复充分性）。** 若在允许保存的 waiting/done 边界上，`decode(encode(C)) ≅ C`，且恢复绑定按原协议重新建立，那么同一后续输入带产生同构状态和相同后缀轨迹。

**证明。** 每个表达式读取的值、随机状态、引用关系和待决请求均由同构保留。每次读写和续延转移在另一图上存在对应转移，因此对后续步骤归纳成立。waiting 恢复点位于已发出 call 之后，保存的是其续接而非入口，故不会重新执行之前的发牌、扣费或发布。□

此处“不重放”是保存完整续延的推论，不是禁止其他后端实现方式的新协议。不得把已有外部副作用再执行一次来重建状态；外部消费者在崩溃后的投递去重仍依赖现有记录协议，本定理不额外保证分布式 exactly-once。

**定理 2（fork 非干扰）。** 若 fork 后 A、B 的逻辑存储初始同构，所有可变地址归各自实例，或共享物理页具有完备 COW 写屏障，且 D 不可变，那么只推进 A 不改变 B 的逻辑配置；两者给相同输入产生对应后缀轨迹。

**证明。** 对 A 的步骤归纳。读不改 B；写只改 A 私有地址，或先获得 A 的私有版本；局部槽、请求、随机状态和游标同样属于 A。分配产生 A 的地址，D 无写操作。故 B 每步不变；相同输入的结论由定理 1 和初始同构得到。□

写屏障必须覆盖数组、闭包捕获、Map/Set、内部槽等准入可变类型。一个漏掉的宿主别名就构成反例，不能用本证明替代 runtime 审计。父实例关闭安全还要求资源回收按存活分支可达性/引用所有权进行，不能把共享页随父实例直接释放。

恢复保留原保存 CallId/记录前缀并生成新的 InstanceId；fork 凭证遵循现有协议。跨分支拒绝须实际校验，不能用 α 将非法凭证“规范化”为合法凭证。

## 5. 新旧实例功能等价

分别令 O 为冻结的旧实现、N 为新内核实现。把有限内部执行折叠为宏转移：`C ⇒ℓ C'` 表示 `τ* · ℓ · τ*`，在同一事件、请求或终局切点比较，不要求内部栈布局相同。

关系 R(O,N) 要求：业务状态及对象身份相同，PRNG 与发布进度相同，待决请求语义相同，且新旧续延表示同一剩余规则流程。私有局部结果可用关系映射，不能仅因公开观察一样就忽略其未来影响。

**定理 3（双向模拟推出轨迹等价）。** 假设：

1. 相同 setup 初始化后 R 成立。
2. R 成立时，O 的每个可见宏转移在 N 中存在相同标签（允许 α）的有限宏转移，且后继仍满足 R；反方向也成立。
3. 回复接受/拒绝、终局及规则故障对应；新增内部调度不能在一个旧步骤对应区间内无限运行。

则在相同输入带下，新旧所有有限可见轨迹、边界观察及终局结果相同。对于无限执行，若双方还保持内部发散行为一致，则无限可见行为也相同。

**证明。** 初始 R 是归纳基。每取一条 O 标签，由条件 2 在 N 中匹配，有限内部步骤不增加标签，后继 R 支撑下一次归纳；条件 3 保证匹配不会永远停在内部步骤。反向模拟排除 N 额外产生行为。完成、拒绝和故障由条件 3 对应。无限情形逐个有限前缀匹配，并以发散条件排除“一方永远内部循环、另一方继续输出”的差异。□

这是可用于迁移的证明方法，不是把“功能相同”直接作为已知事实。实际证明需把宏步骤拆到下列局部义务，并用引理 1 组合：

| 局部义务 | 斗地主实例 | Forge Duel 实例 |
| --- | --- | --- |
| 初始化对应 | LCG 调用数、洗牌次序、重发延续随机状态 | carry、两座位洗牌抽牌和首个 begin 次序 |
| 校验前不写 | actor/stage/slot/deadline；clock/timeout 分支 | 完整 legal/sameAction 校验先于扣费、移牌 |
| 操作前后状态对应 | 叫分、两农民各自 slot、加倍揭示、牌型与结算公式 | play/attack/end 拆分及 step/cause 收尾 |
| 组合顺序对应 | 发布事件→游标更新→原 decision；双农民两种提交顺序分别证明 | 攻击伤害→反击→deaths；按座位死亡处理及存活 witness |
| 中途终局对应 | 最后一手、春天与各农民倍数 | supply 首抽致命后第二抽短路；双致命、回合上限 |
| 观察适配对应 | 原事件遮蔽、合法动作及顺序、底牌公开时机 | audit/owner 投影、机会事实、pending 批次 |

例如 supply：设 draw 操作对满足 R 的两状态产生对应状态/事实，且在 result 已存在时均为空操作。由引理 1，`bind(draw,_.draw)` 与旧连续两次 draw 对应；若第一次疲劳致命，第二次两边都为空操作。若去掉第二次的终局守卫，证明立即失效。

攻击同理必须组合“伤害目标、反击、deaths”。在第一次伤害后插入死亡删除会导致死亡目标无法按旧规则反击，构成明确反例。由此可见 checkpoint 是规则语义的一部分，不能全局自动插入。

不同游戏可以使用不同状态空间 S 和不同操作集合。定理 1–3 对满足前提的任意规则包参数化成立，所以同一个执行器能复用；这不意味着斗地主与 Forge Duel 的状态或规则彼此等价，也不推出完整万智牌规则已实现。

## 6. 隐藏信息与训练接口

令 `view_p(C)` 为玩家 p 的原 observation、可见事件、请求和合法动作接口。全状态等价及相同投影函数直接推出新旧 `view_p` 相同，故迁移不增加该接口的泄漏。

更强的隐藏信息非干扰不能仅由“遮掉手牌字段”推出。定义 `C ≈p C'` 为 p 当前允许知道的信息相同。若每次推进对 ≈p 保持对应、可见标签相同，直到规则允许的信息公开，则逐步归纳得到公开前玩家轨迹相同；公开后按相同公开值重新建立关系。这是带允许披露的非干扰条件。

合法动作集合、错误消息、候选数量、业务 ID 和事件存在性也在可见标签中。例如双农民第一人的选择不能影响第二人的可见候选或揭示前事件内容；两人都提交后的公开属于规则允许披露。是否满足该条件必须检查规则包，内核组合本身不保证。宿主耗时、RSS 等侧信道不属于此接口级证明。

训练适配器若仅使用这些玩家观察并原样提交合法动作，可以沿用同一轨迹语义。训练可读取完整状态的搜索能力应单独授权；fork 能复制真实世界，不代表策略有权知道复制后的隐藏信息。

## 7. 终止、预算与空间边界

**不能证明所有游戏脚本终止。** 无限循环、无限触发和无回复等待都可合法表达。有限自动结算段若存在自然数秩函数 V，且每个内部步骤令 V 严格下降，则至多 V(C₀) 步到达等待、完成或故障。有限 forEach 可用“剩余元素数＋当前子项秩”的词典序构造秩；递归还需要规则包提供下降条件。

另可在数学模型中加入每个内部步骤都递减的 fuel B，则至多 B 步停止自动推进或报告预算耗尽；前提仍是单个 primitive 有界。此 fuel 只是证明工具，不新增公共预算接口。实际保障继续由现有 computeStepBudget 等机制承担，需另证其对相应执行步骤的覆盖。

新组合器增加内部指令，所以**相同数值预算不保证相同耗尽位置**。定理 3 的功能等价范围为双方资源充足的执行，以及已对应的规则故障；资源耗尽行为单独验证原故障契约，不能无证据宣称预算边界完全相同。若要求逐预算结果一致，须再证明成本模拟关系，或报告该要求无法由当前重构保证。

设 d 为最大活跃调用/组合深度，a 为活跃环境和结果所占字节，w 为待决请求数据，s 为业务状态，h 为规则要求保留的历史，则在完成帧及时释放、无额外缓存保留的条件下，逻辑活跃数据为 `O(s+h+d+a+w)`。这不等于 V8 堆占用或 RSS，也不推出常数大小快照。

若物理存储支持固定大小根描述符共享，则 fork 的根操作可为 O(1)；平衡页索引下单页首次写入可为 `O(log P + pageSize)`，P 为页数。存在多根扫描、未索引图编码或整图复制时不能套用该界。本文不证明现有后端已达到此成本，也不给出没有测量支持的吞吐或 GC 数字。

## 8. 与实现验收的关系

上述推导建立了明确的正确性条件和反例判据。落地时分别验证：组合器按第 2 节执行；规则操作满足第 5 节局部对应；runtime 满足第 4 节图同构与所有权；原契约满足输入验证和玩家投影；预算故障维持现有协议。差分、定向反例、跨进程恢复和结构检查均进入原正式测试流程。

测试是这些义务的实现证据，不是对所有输入的数学证明。只有补齐实际代码的逐操作对应证明或机器验证，才能把抽象定理提升为实现级全称结论。当前交付为设计层证明，不勾选双游戏迁移或实现等价性完成。
