# 受控编译与原生差分规格

本页落实用户要求：受控程序在构建时编译，运行时只装载编译产物；差分验收同时覆盖游戏和通用程序。它补充 implementation-spec.md 第4、13、14节，不改变已冻结的公共协议。本文是实施合同，尚未实现的编译器和差分套件不能据此标记完成。

## 1. 编译底座

采用 **Babel + EffectfulJS core v2 的完整续延转换**：`@effectful/core/v2/compiler`、v2 debugger preset、裁剪的续延运行库和 `@effectful/serialization`。源码先由 TypeScript 检查/去类型，再把 await 的后续计算、跨等待点存活的局部变量和同步/异步闭包环境显式化。生成 JavaScript 由 V8 直接运行，不在运行时逐条解释作者 AST。编译指 JavaScript 到 JavaScript 的提前转换，不要求生成机器码。

实测调整：最初的 es-persist 路线不能序列化捕获外部局部变量的嵌套 async 闭包，因此改用同一项目的 v2 完整闭包转换。运行库原来在函数注册时使用 Function 构造器，本项目在构建时生成对应函数工厂，运行时禁止动态代码生成。裁剪包不携带调试 UI、编译器或网络能力。项目采用 MIT 许可。引用感知的序列化器保留共享/循环引用；现成库仍须接受下面的真实恢复验收。

库只提供转换和状态机制。完整实例隔离、模块工厂、端口设备、稳定点判定、预算、格式兼容与持久快照由本项目实现。不能把库的 clone/示例注册宿主对象当成跨进程保存的证明；闭包、SDK、Zod 和实际游戏都须通过下述验收。

2026-10-11 核对并采用 npm latest：core/debugger/serialization 为 **2.0.12**，Babel 为 **8.x**，esbuild 为 **0.28.2**，Zod 为 **4.6.5**，TypeScript 为 **7.0.2**。不同包的版本号不作横向大小比较。最新 es-persist 2.0.13 发布元数据含 workspace:^，并有上述闭包反例，现已退出实际依赖。core/serialization 和裁剪的 debugger 运行库保留相同最新上游源码，修正 workspace 引用及 Babel 主版本，并在 vendor/effectful 中记录必要补丁。lockfile 锁定实际版本。实际采用 core v2 的提前静态工厂路线；产物 ABI 为 effectful-v2-static-2，快照私有格式为 3。程序/schema 共同进入恢复对象图，保持模块变量共享。正式命令为 npm run check；关卡以 docs/plan.md 的实测状态为准。

## 2. 两条构建与装载路径

同一入口、同一闭合依赖图、同一 setup/schema/批准的内建语义产生两条独立路径：

| 路径 | 构建 | 执行 |
| --- | --- | --- |
| 原生 oracle | TS 检查、去类型、模块实例化；无续延转换 | 原始 async/await 和 V8 Promise；直接调用 ProgramModule.run |
| 受控目标 | TS 检查、去类型、依赖准入、模块实例化、持久续延转换、预算插桩、产物验证 | ControlledCoreLoader 装载产物，V8 运行生成 JS；保存显式现场 |

原生 oracle 不得经过受控续延转换或复用其解释/状态调度器。两端共用游戏源码、schema 和 SDK 是必要的；不得共用受控转换结果来制造一致。生产原生 runner 另与直接调用源码的 oracle 对照，避免两种 runner 共用边界错误。预算插桩独立检验，不用指令计数相等作为语言语义正确性。

构建步骤：

1. TS 类型检查与闭合依赖解析，固定版本；检查全部可达源码，拒绝不准入的构造和隐式宿主效果。
2. 去类型与模块转换；依赖初始化生成实例工厂，可变模块状态在实例内。循环导入、初始化顺序、导入绑定语义须验证；不能把所有模块变量简单复制一遍。
3. 对可挂起调用链应用 core v2 续延转换。按上游要求分离转换 pass，固定实际顺序。不删 await、不把 SDK IO.call 改成同步函数、不要求作者手写 PC。
4. 在循环、递归入口及批准内建调用插入预算点；随后校验生成代码和所有运行时 helper 的能力边界。纯同步计算可直接使用 V8，但其挂起点可达对象图仍要可保存。
5. 生成 CompiledProgram.content：JS 执行载荷、模块/续延构造器表、schema/端口描述、source map、编译及适配/runtime/快照 ABI 版本、准入策略身份和内容校验。以上是私有格式，不添加公共字段。

Loader 只做格式、版本、完整性和能力校验以及装载执行，不再读取 TS 源码、做 Babel 转换或解释 AST。V8 正常解析/JIT 生成 JS 属于执行引擎行为。运行部署不携带 TypeScript/Babel/转换插件；以仅产物和 runtime 的子进程执行测试证明这一点。恢复须使用与快照匹配的产物；不提供任意新代码热迁移。

生成程序使用固定的模块解析表和批准能力；不得允许作者 require 任意包。Node vm 单独不构成安全隔离证明。续延转换本身也不构成沙箱，准入、能力封闭和执行预算是独立必需项。

## 3. IO 与现场适配

受控 IO.call 返回实现库 AsyncValue 接口的端口等待对象；库要求原生模式也可等待时，该对象须具备兼容 Thenable 接口。原生 oracle 仍用独立的 Promise IO 绑定。端口设备只捕获实例内逻辑设备身份、调用数据和可序列化续延，不捕获宿主回调、Promise resolver、计时器或 AbortSignal。

程序 await 原生未决 Promise 会导致库状态不可序列化，必须由准入/运行检查拒绝。顺序 IO 的内部 continuation/job 链在确定性实例调度器中管理；稳定点必须只有一个对外待决调用，内部可运行队列已排空。若仍有库的异步队列状态，必须纳入现场，不能用默认宿主 event loop 代替保存。不得注册活动宿主函数为 opaque object 来逃避检查。

快照包含续延根及其可达对象图、实例模块环境、随机状态、内部调度状态、待决调用、记录前缀和正常终局。编译产物提供稳定构造器标识，恢复先重新装载并注册同一张构造器表，再读对象图；不序列化 JS 函数字符串后 eval。注册静态代码身份与保存宿主函数是不同的操作，注册表不得接受作者/绑定端注入的活动对象。

fork 深复制该图或使用经验证的隔离复制机制；同一图内别名保持，不同分支之间不共享可变对象。库文档中的 continuation 重复 resume 会共享已修改变量，直接重复 resume 不等于 fork。

Zod 按可达代码验证，不能整体包名放行；自定义检查、错误结构、parse/safeParse 和 schema 构造须保持原生行为。暂时无法序列化的现场是准入失败/实现缺口，不能降级成重放前缀或只存游戏 JSON。

## 4. 差分测试 harness

测试归属 `packages/compiler/tests/` 的转换语义和 `packages/runtime-controlled/tests/` 的装载/保存/分支；游戏集成放各游戏 `tests/`。通用夹具不依赖 BaseGame、玩家或合法动作。全部进入各模块 check 和根 npm run check。这些生产模块及正式测试已经落地，完成验收仍以 docs/plan.md 为准。

每个 fixture 声明源码入口、setup、确定性外部输入规则、预期准入结果、独立算法 oracle、输入 seeds 和允许挂起位置。输入规则以逻辑调用序号、端口名和参数生成响应；两个端点维护独立游标。发现端口/参数不一致立即失败，不能继续分别生成响应掩盖首次分歧。游戏用冻结策略/脚本在原生侧生成合法输入带，受控侧严格消费；另用独立规则 oracle 检查两端共同的规则错误。

记录逐项语义轨迹：端口名、参数、回复、事件顺序、正常返回或语义异常。生产接口测试额外核对协议状态/故障原因、接受与暂停结果、待决调用和记录前缀。比较每一项及最终结果，不能只比较胜负或 checksum。

规范化仅排除明确的非语义元数据：新 InstanceId、宿主租约身份、耗时、source map 行号；用一致的身份映射检查同一身份重复使用和跨分支隔离。CallId/记录前缀在保存恢复语义中的保持关系仍必须断言，不可全删。数组与事件顺序、合法动作顺序、错误类型/业务消息及公开错误路径保持。错误 stack、原生与生成代码的函数内部名称不作为 oracle。

比较器覆盖准入值域：Object.is 数值比较保留 -0/NaN，缺失属性与 undefined 区分；内部夹具还检查空槽、引用相等/不等及循环图，不用 JSON.stringify 充当通用比较器。BigInt/Map/Set 等只有实际准入并实现编码才进入正例，不能把未支持类型静默转 JSON。端口仍严格遵循其 schema，不为测试扩宽协议数据范围。浮点同样输入同样运算顺序默认精确；需要误差界的算法独立 oracle 可使用预先声明误差，不能用误差放宽双端轨迹比较。

## 5. 通用语义和 benchmark 集

每类均包含无 IO 的整段计算和通过已有 IO.call 插入固定检查点的版本；原生/受控输入相同。检查点由 fixture 作者显式插入，不修改第三方 benchmark 来暗改算法。量级使用固定小/中/大数据集，日常 check 运行小/中，扩展集进入模块 test 命令的显式选项；不能跳过唯一覆盖某项语义的测试。

| 组 | 代表程序与边界 | 验证目标 |
| --- | --- | --- |
| 控制流 | 嵌套 for/while、continue/break、switch、短路表达式、带副作用的求值顺序 | 每步日志/求值顺序和结果；循环内等待 |
| 调用与递归 | Fibonacci、树 DFS、互递归、参数/返回中 await | 深层续延和各层局部值；使用独立迭代 oracle |
| 闭包与引用 | 计数器、多个闭包共享变量、闭包逃逸、对象别名/环、实例模块计数 | 等待后引用关系、写入可见性及实例隔离 |
| 异常 | try/catch/finally、等待前后 throw、finally return/throw、await 参数求值抛错 | 完整事件次序、返回覆盖语义；程序异常与执行器 fault 分离 |
| 数值/字符串 | 整数溢出位运算、-0/NaN、Unicode 遍历与切片、字符串扫描 | 精确数值和 UTF-16 行为；不假设数学整数等同 JS number |
| 排序/数组 | 稳定归并排序、批准的 Array.sort 比较器、稀疏数组、map/filter/reduce | 排序元素/稳定性、空槽和回调副作用；仅支持的构造作正例 |
| 图计算 | BFS、DFS、Dijkstra 的固定连通/不连通图 | 全访问序列与距离数组，对照独立最短路 oracle |
| 动态规划 | knapsack、编辑距离、矩阵乘法 | 全结果/中间检查点，对照穷举小规模或独立实现 |
| 数据处理 | JSON 解析/构造、对象枚举、深树转换、循环图现场 | 外部合法数据值与内部引用图分开检验 |
| 随机算法 | 显式 seed 的 PRNG、洗牌、Monte Carlo 固定迭代 | PRNG 消费顺序、完整样本及结果；禁止 Math.random |
| 小型解释器 | fixture 内实现表达式计算器/字节码虚拟机 | 被测程序是普通算法，与执行器解释作者代码无关 |
| 依赖 | SDK、实际 Zod schema、嵌套纯库函数/闭包 | 转换覆盖实际可达依赖、schema 错误和库内部 await 链 |

通用 benchmark 是正确性输入集，并记录编译一次、装载、计算吞吐、峰值内存、保存大小/时间、恢复时间。性能测量不参与语义轨迹归一化，也不预设受控与原生同速。比较相同算法、数据量和 IO 数，区分冷/热运行、编译/装载/计算/序列化时间；同机器/Node 版本、交错执行、多次重复报告中位数和范围，不以单次墙钟测量判失败。性能阈值在真实测量后定，不能编造已达到的倍率。

## 6. 每个 fixture 的执行模式

| 模式 | 做法 | 必须断言 |
| --- | --- | --- |
| 连续执行 | 同源原生与受控一路到终态 | 完整轨迹与终态相同 |
| 分段驱动 | 每个端口暂停后用现有 run 继续 | 不遗漏/重复调用；与连续轨迹相同 |
| 每点恢复 | 在每个稳定 IO 点 save，销毁实例，再 restore | 原生后缀一致；调用/记录前缀正确 |
| 跨进程恢复 | 进程A写产物/快照并退出，B只读两者和输入后缀 | 不依赖A对象/宿主注册/源码；不重放已完成前缀 |
| 双分支 | 同快照两次 fork，分别输入相同/不同后缀 | 相同后缀相同；不同后缀各对独立原生 oracle，父与兄弟不串 |
| 重复使用 | 同一个不可变快照多次 restore；不同调用顺序运行分支 | 快照未被 resume 改写，执行顺序不影响结果 |
| 多实例 | 同产物多个实例、交错推进/释放 | 模块变量、随机流、构造器注册无污染 |
| 终局恢复 | 完成后保存/恢复 | 已完成结果和记录相同，不再发端口调用 |

跨进程测试把外部响应前缀封存且不给B；调用计数器/前缀 side-effect spy 证明不重复请求。额外检查B不装载 compiler/源码；只销毁包装对象而保留A进程的活动 Promise 不算通过。等待嵌套递归、闭包更新前后、try/finally 内以及 SDK 方法链的点均须覆盖。无 IO 程序只在正常 Done 保存，不要求运行中任意指令都可保存。

fork 的原生分支 oracle 可从入口用原生前缀重跑再给不同后缀；这是测试生成预期值，绝不允许受控实现这样恢复。分支创建本身不得调用任何外部端口；不同输入不能只对照兄弟分支的结果。

## 7. 游戏与故障测试

斗地主覆盖完整原生对局输入带、全部牌型/叫分/加倍/超时及正常结束；forge-duel 覆盖两种构筑、固定随机流、伤害/死亡/抽牌/疲劳及终局；双潮焚契按其已登记压力案例接同一 harness。每个游戏至少有多种策略、多个 seeds 和每个真实决策点恢复。除了底层 IO 轨迹，还比较逐玩家观察、合法动作、公开事件、审计事实与结算。隐藏信息反例和合法动作独立 oracle 继续保留，不能因为双端相同就认定正确。

负例分三类，避免混比：

- 编译准入拒绝：eval/Function、动态依赖、环境熵/时间、脱离现场 Promise/并发、宿主闭包、不可保存值。需要精确源码位置和原因；原生能运行不代表必须受控接纳。原生执行拒绝样例只用安全夹具，不执行真实外部效果。
- 语义异常：准入程序的业务 throw、catch/finally、非法输出；比较真实声明的故障类型与稳定前缀。宿主非法回复/取消按协议测试，不伪装成程序抛错。
- 执行限制：无限循环、深递归、超预算、失效快照、版本不匹配、损坏产物。预算不足双端内部步数不同，分别验证终止与现场合法性；正确性差分给足预算。运行时 fault 不能被作者 catch 清除。

生成测试从明确准入的语法子集生成有界程序及输入，不生成任意 JS 再把差异归咎于不支持。首轮固定32个 seeds、每种模板至少4种形状，覆盖等待位置/对象别名/异常分支；固定 seeds 纳入正式 check。扩展随机测试失败输出 seed、最小源码和首次差异，收缩后作为普通 regression fixture 保存；不提交随机日志/审计账本。生成模板不能复用受控状态转换逻辑作为 oracle。

通过故意改变转换的等待后变量、交换两个调用、破坏别名、漏 finally、复用模块状态、恢复时重放前缀等可控 mutant 验证 harness 会失败。比较器自身用手写轨迹测试，确保删除语义字段、把顺序排序或 JSON 化数值时会被发现。

## 8. 验收与顺序

先解决最新版依赖安装/转换 API，再做最小同源嵌套 async → IO 等待 → 序列化 → 独立进程恢复 → 原生后缀对照。随后完成通用语义集、通用 benchmark 集和 SDK/Zod，最后接完整游戏和真实 Loader/Instance 生命周期。任何阶段发现 admitted 源码无法保存，优先修复转换/适配，不改业务规则或冻结协议。

C02 的编译路线通过条件：构建后只装载产物可执行；所有已准入构造的固定正例/负例通过；完整逐调用差分通过；每个稳定点保存恢复、独立进程恢复和 fork 隔离通过；两游戏集成通过；预算及依赖边界检查通过。声明文件/typecheck、库 README、同进程 clone 或只比较最终结果均不能代替上述条件。

本轮仅修改规格并核实候选与安装问题，未加入生产编译依赖，未声称这些未来 diff tests 已运行。当前正式检查仍是既有 npm run check。
