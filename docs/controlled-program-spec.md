# 受控程序规范

## 受控对象

Core 接受经过准入的程序与全部传递依赖。Instance 拥有该程序在外部 call 边界的完整 Context，包括显式调用帧、必要局部变量、闭包捕获数据和对象引用图；代码与不可变元数据属于共享 Program。游戏作者使用 TS 纯计算和 IO.call；不手工编写 PC，不将任意宿主函数注入规则计算。

## 编译和装载

受控路径提前编译 TS/JS 与闭合依赖，输出可由 V8 执行的 JavaScript 及显式续延/环境描述；Loader 只装载产物，不运行源码转换或解释作者 AST。现有实现采用 Babel/Rollup 与修改后的 EffectfulJS core v2，已修复记录中的上游反例；剩余工作是当前实现的范围、恢复与性能验收。历史候选比较不是尚未确定底座，也不要求无具体反例地重新选型。库及适配边界见 [编译与差分规格](compiler-and-differential-spec.md)。准入与完整现场要求不因编译方式改变。

源码和传递依赖只接受 ES Module；模块天然使用严格语义。`.js` 与 `.ts` 按 ESM 解析，`.mjs` 与 `.mts` 明确为 ESM；`.cjs`、`.cts`、Script 输入和非严格语义不准入。静态导入的每个依赖在任何链接或转换之前做相同检查。编译器内部为了加载产物生成的 CommonJS 包装不属于作者输入，也不能作为接纳 CommonJS 依赖的理由。

作者程序与运行时在同一进程中，项目不提供针对恶意作者代码的安全沙箱。源码准入是转译正确性与现场可保存性的检查：它一次性判定原始模块及依赖是否落在实现范围内；转译阶段以此为前提，不重复判定同一源码特性。转译阶段可以保留内部一致性断言，用来发现转译器自身丢失信息。只有对象身份、访问器、回调等静态源码无法决定的条件，才留给运行时在实际操作处检查；这些检查服务于行为与恢复正确性，不宣称同进程安全隔离。

## 语义与差分基准

已准入能力以目标 Node/V8 对未经转译原程序的实际执行行为为语义基准，覆盖结果、副作用、异常及求值顺序。Test262 是用例来源，不以规范预期替代原生对照；与目标原生行为不同的用例须单独报告。目标引擎未实现的能力不要求自行模拟，不算已支持。引擎升级后重新核对范围，不自动扩大白名单。当前核对环境为 Node 26.5.0 / V8 14.6.202.34-node.24，不代表已验证所有声明兼容的 Node 版本。

静态导入属性中，空属性子句可用于普通 ESM；数据资源仅支持目标原生已实现的精确 `type: 'json'` 请求。当前 Node 加载器会在链接前拒绝普通模块的其他属性，因此这类请求不属于生产准入，不能用裸 V8 模块链接器对它们的结果证明生产符合性。文本、字节模块及不可变 ArrayBuffer 暂不要求。`import defer` 与动态 `import()` 仍明确排除。此决定取代此前“其余全部支持”中超出目标原生实现的部分，不改变 IO 恢复、实例隔离及公共协议。

## 准入边界

准入顺序固定为：默认拒绝，匹配白名单，再执行白名单内黑名单排除。白名单的单位是带使用条件的特性，不是包名或单独的函数名。作者代码、SDK 和全部传递依赖执行同一规则；不允许按包名跳过检查、注入依赖专属配置或因为已有示例通过而放行。

对一次操作及其使用条件 x，允许条件为 `x ∈ 白名单 && x ∉ 黑名单`。不在白名单中即拒绝，不以“黑名单未命中”作为允许依据。黑名单只能收窄白名单，不能新增能力；新语法、新内建方法及新依赖路径也不得自动获得准入。

| 检查面 | 白名单必须声明 | 黑名单必须排除 |
| --- | --- | --- |
| 源码 | 语法、控制流、静态模块依赖及转换语义 | 未实现的语法、动态依赖和动态代码生成 |
| 调用 | 目标函数、接收者、参数、回调及可能触发的隐式协议 | 未支持的构造行为、反射、species、访问器或宿主调用路径 |
| 状态 | 值类别、内部槽、别名、原型及属性描述符的复制/保存语义 | 无保存实现的状态、宿主资源和共享可变引用 |
| 依赖 | 同一源码与调用检查覆盖闭合依赖图 | 未检查的传递依赖、外部能力和按库名豁免 |

能静态确定的不支持行为在编译时拒绝；动态条件必须在该操作产生副作用前检查。无法提前检查的特性不能准入。编译成功不保证所有输入路径都受支持，但每条路径必须保持已声明语义或明确拒绝，不能静默错误，也不能第一次 fork 才发现之前已放行的状态不受支持。

新增白名单项必须同时证明普通执行语义、IO 边界恢复和实例/宿主隔离。仅检测已知危险函数、然后无条件调用其余原生函数，不符合本规范。运行时对标准值内部槽的实现属于统一特性实现；依据依赖名称或游戏内容决定放行属于禁止的业务特判。

以上是验收要求，不能当作现状完成声明。生产检查的实际缺项以 plan.md 顶部当前清单为准。

当前原生入口表位于 `packages/runtime/src/native-policy.ts`，按内建函数身份列举，不随 V8 新增方法自动扩大。已有数组结果构造限制：map/filter/flat/flatMap/slice/splice/concat 的数组接收者只接受数据属性形式的默认 Array 构造器或 undefined；自定义构造器、species 和构造器访问器拒绝。Array.from/of 只接受 Array 作为接收者。apply 的参数列表按数组式读取，不引入迭代器或 species 调用。该表仍需完成隐式原生调用与可保存结果值域的审核，不能仅凭入口匹配断言完整受控。

当前已实现的特性边界如下；本表不替代上述未完成的整体审核，也不承诺表外的完整 JavaScript：

| 特性 | 白名单内支持 | 白名单内排除 |
| --- | --- | --- |
| 变量声明 | var、let、const；using / await using 经资源清理转换，覆盖正常及异常退出 | 目标原生引擎未实现的声明形式；整体语义验收仍按计划进行 |
| 数组结果构造 | 默认 Array 构造及已列明的方法 | 自定义结果构造、species、构造器访问器 |
| Promise | 受控任务队列、resolve/reject、then/catch/finally、all/allSettled/any/race/withResolvers | 子类、自定义构造器或 species、原生宿主任务混入现场 |
| 可保存迭代 | 数组、字符串、类型化数组、Map/Set 和 RegExp matchAll 的受控游标；同步及异步生成器 | 原生游标的私有状态不直接写入 Context、外部传入执行帧；直接读写执行帧不是作者 API |
| 字节数据 | 固定长度 ArrayBuffer、类型化数组和 DataView，共享底层 buffer 的别名保留 | 可伸缩 ArrayBuffer、共享内存 |
| 属性定义与描述符读取 | 描述符继承、字段及描述符表访问器、对象属性键的一次受控转换；源码访问器与明确列出的原生访问器；原生描述符结果交付前检查其 value/get/set 中的函数 | 把普通原生方法安装为访问器；在描述符结果中夹带未准入的原生函数 |
| 模块 | 静态闭合依赖、实例独立的模块可变数据、JSON 导入属性、模块级 import.meta 对象和 url | 动态加载、defer、文本/字节模块、宿主环境访问；import.meta 的 Node 宿主字段在程序自己覆盖前读取会明确拒绝 |
| 隐式方法分派 | String 的 match/matchAll/replace/replaceAll/search/split、Object.toLocaleString/toString、Array.toString、Promise.catch 中的可调用钩子与属性读取经受控操作处理；RegExp.flags 的可覆写标志字段也按顺序受控读取；返回的受控游标可保存 | 未列明原生函数的取值和调用；依赖本地环境的 Array.toLocaleString/Number.toLocaleString |
| 原生正则协议 | matchAll 按 species、flags、lastIndex 与 exec 的调用顺序产生 Instance 拥有的游标，允许受控自定义 species/exec；有真实 RegExp 内部槽、默认 exec、原始值控制字段的 match/replace/search/split；search/split 及公开 global 为真时的 match/replace 保留不被转换的对象型原始 lastIndex，split 的对象型 limit 经受控强制转换；公开 global 为假、内部标志为真时的 match/replace 只执行一次；test 的自定义 exec 经 invoke | match/replace/search/split 的自定义 exec、控制字段访问器、其余对象型控制字段、split 自定义 species；match/replace 的公开 global 为真但内部标志为假（重复匹配可能无法前进）；RegExp.$1/lastMatch/input 等环境静态访问器 |
| 错误对象 | Error 系列构造器的 options.cause 经原对象的受控访问写入结果；Error 的常规数据及显式赋给 stack 的数据随 Context 保留 | 读取默认 V8 调试栈、调用 `Error.captureStackTrace`；两条执行路径均不得把宿主栈交给作者程序 |

受控路径在 Program 装载时创建独立 V8 Realm，并在其中装载作者代码、内建值、原生操作表和续延设备。正式回归检查：程序正则匹配不改写宿主可读的 `RegExp.$1`，宿主内建对象的后续变更不会进入已暂停的 Program 及其分支。Instance 仍只保存、复制 Context；Realm 不进入快照，也不在 fork/restore 时重建。

标准错误构造器与固定字节类型的直接名称、globalThis 属性使用同一组受控能力：Error、TypeError、RangeError、AggregateError、ReferenceError、SyntaxError、EvalError、URIError；ArrayBuffer、DataView；Int8Array、Uint8Array、Uint8ClampedArray、Int16Array、Uint16Array、Int32Array、Uint32Array、Float32Array、Float64Array、BigInt64Array、BigUint64Array。调用仍受原生入口及其排除条件检查；除 undefined、NaN、Infinity 外，全局绑定可以在实例内替换或删除；实例数据在 Context 中独立保存，共享内建构造器对象及原型不能被作者修改。

全局 `Function` 保留目标 V8 的真实值身份、名称、长度和原型关系；读取或跨 IO 持有它不构成动态代码执行。直接动态构造在源码准入拒绝，经变量别名、反射或构造路径发起的实际调用仍由运行操作拒绝。不得用占位函数冒充原生 `Function` 后把普通属性读取误报为等价。

`Math`、`Date`、`Proxy` 的全局值以及 `Math.random`、`Date.now` 的函数值保留目标 V8 身份；已准入的数据属性读取、同一性比较和跨 IO 持有不使用占位值。实例全局不注入 Node 的 `navigator`、`URL`、`File`、`atob`、`btoa` 等宿主入口；对缺失名称，`typeof` 返回 `undefined`，直接读取或写入抛出 `ReferenceError`。需要宿主能力的游戏声明端口并通过 `IO.call` 调用；作者可将纯算法编入受控依赖图。随机、当前时间及不具备受控现场表示的构造调用由统一调用操作拒绝，其中随机和时间尝试即使被作者代码捕获也保持实例故障。共享内建值不能被实例修改；这并不授予外部通信能力。

程序对外通信仅通过声明端口的 `IO.call`。V8 内建函数和已编入程序的纯计算依赖在程序内部执行，不因为实现位于 V8/Node 就被视作 IO；反之，Node 恰好暴露的环境对象也不能仅因存在于 `globalThis` 就进入实例。实例全局的可见集合由运行时显式构造，作者源码中未解析的名称一律通过该集合解析，不能回退到 Node 全局对象。
编译器生成的模块/控制流辅助代码也不能回退到 Node 全局：所需 ECMAScript 内建值从 runtime 显式提供的 `intrinsics` 取用，未知自由名称导致编译失败。私有工厂只接受既有执行能力，不捕获打包器或宿主的环境变量。


拒绝位置也是验收内容：静态违规必须在编译阶段定位到源码；依赖运行时值的违规必须在执行该不支持的操作之前拒绝。不能以返回近似结果、忽略该操作、降级到未经检查的原生路径或延迟到保存/分支时失败来替代拒绝。动态检查失败不意味着撤销程序此前已完成的合法操作；它意味着该操作不得执行。

隐式分派不能采用“检查后把原对象再次传给原生方法”的方式：访问器可能第二次返回不同函数。字符串协议读取钩子一次，将实际调用交给统一 invoke；无钩子的原生回退只接收已完成规定转换的值。正则输入转换先执行，随后检查实际接收者，避免转换过程中改变 exec 的检查时序漏洞。Object.assign/entries/values 与 Reflect.get/set 也复用属性访问约束，拒绝原型链上的未准入环境访问器。原生普通访问器与源码访问器仍依各自白名单条件工作。

instanceof 的 Symbol.hasInstance 同样经 invoke；运行时管理的绑定函数以私有绑定记录识别，默认 instanceof 使用原目标的语义。原生后端的受控 bind 包装在 V8 中显示为 native function，因此按该绑定记录证明调用路径，而不是因其显示为 native 就豁免所有绑定函数。没有该记录的未知原生绑定仍被拒绝。默认调试栈不能在恢复后悄悄换成新栈；已存入 Error.stack 的业务值属于显式状态，不受该排除项影响。

编译器生成的迭代器辅助调用也走上述边界。V8 同步原生计算内部产生的游标，不得未经适配就作为返回值或回调参数进入作者状态；受控程序在该值交付给源码之前拒绝它。普通数组/字符串/Map/Set 迭代入口仍使用可保存的受控游标。这一区别以实际调用路径和对象类别判定，不以源码是否使用某个包判定。

采用构造白名单及白名单内部排除规则。依赖图必须封闭；动态导入、eval、Function、宿主对象、环境全局变量与未声明的外部状态不能进入受控计算。真实时间、外部随机熵、网络或用户输入通过声明端口进入；显式 seed 驱动的伪随机计算可以在受控程序内执行。冻结常量与受控局部可变数据可以使用；影响执行的可变模块状态必须实例隔离并纳入现场，不能在实例间共享。

函数、递归与闭包在内部可以存在。跨端口的数据由各端口 schema 声明，不允许把指向活执行对象的引用泄漏给宿主。request.respond、observe、projectEvent 及可选 session 处理器同样受依赖与副作用检查；TS readonly 和 linter 不能独立证明纯性。

## 调用与恢复

一个稳定 Instance 挂起一个外部调用。程序须顺序等待受控调用；多个外部参与方通过显式事件输入协议表示。不得存在未受控的异步任务或脱离现场的效果。循环与递归的后续计算必须可保存；仅持有原生 Promise 不是可持久化现场。

端口返回经过当前声明检查后才能被接受，接受一次后继续执行。外部 bind/run 只有一个活动驱动租约；回调显式 reply/pause，取消撤销租约，迟到返回不能接续其他实例。稳定回调等待点可保存/分支，但宿主 Promise、AbortSignal 和绑定表不进入快照。宿主回调的非法返回为 pause/invalid_reply，不改变待决现场；程序发出的非法调用或正常返回值不符合 schema 为终态 fault/invalid_output，普通程序异常为 fault/program_failed，均不可被程序捕获后恢复为正常推进。运行预算故障不代表游戏输赢。保存只针对稳定调用或正常结束边界，运行中或故障的半现场不作为正常快照。

## 数据与 schema

固定类别用枚举/字面量；动态引用和游戏输入由对应 schema 定义。边界 schema 保持值，不使用 transform、coerce、default、catch 等隐式变换。显式游戏适配函数可以转换数据，但每次转换必须有声明的输入与输出契约。对象参数与返回隔离，禁止访问器、Proxy、宿主资源和共享可变缓冲区跨界；复制在探测原型、属性或数组内容之前识别并拒绝 Proxy，不能执行宿主 trap 来验证所谓数据值。

packages/contracts/tests/support/schema-admission.ts 是正式测试使用的辅助代码，用于验证固定结构、显式批准的检查回调及边界值隔离。原生消费者的 parseBoundaryValue 检查值保持和复制隔离，声明准入由各模块 schema 测试单独执行；它不自称生产准入器。C02 的生产准入与执行实现需保持对象别名、闭包和控制现场的语义。

## 原生差分

ProgramModule.run 可直接由 V8 调用，IO 由测试绑定提供。同样的 setup 与外部调用返回序列下，已准入程序的原生和受控可观察调用/结果轨迹应一致。NativeCoreLoader 与 ControlledCoreLoader 具有同一外部 Core 形状；直接传入的原生函数属于受信任代码，不经过闭合依赖检查，也不承诺 IO-only、实例状态隔离或保存/fork。原生游戏及逐玩家消费者在 C01 验收，受控后端和双端轨迹对照在 C02 验收。

差分集同时覆盖无游戏依赖的通用语义/算法 benchmark、SDK/schema 和完整游戏；逐调用比较，并验证每点保存、独立进程恢复及分支隔离。具体 oracle、规范化规则、fixture 矩阵与通过条件见 [compiler-and-differential-spec.md](compiler-and-differential-spec.md)。

## 服务与快照

Core 不内置随机或游戏时钟。内侧 SDK/设备库在 program.run 内创建，其闭包与可变局部属于 Instance。外侧 BaseGame 只能有可重建缓存，不另存随机流、输入封存或事件发布进度。PortBindings 可提供真实外部输入；这不授权把游戏内部状态藏进宿主函数。保存与分支只处理 Instance，未来外部回复由调用方显式提供。

编译器只需确保外部 call 边界及正常终局的 Context 完整。调用之间的同步计算不要求任意位置可恢复；内部 await 不是新增公共保存点。循环、递归和异常处理在 call 之后仍可能需要的控制状态应显式保存。动态闭包以代码标识和捕获环境表达，不能因其可达而把代码、整份 moduleExports 或依赖注册表序列化进 Context。

## 实施验收

后续 C02 必须验证：嵌套循环/递归/闭包等待点保存；双分支隔离；不靠完整重放恢复；白名单覆盖依赖；外部输入与随机服务可回放；预算、故障与正常完成区分。C01 的协议、作者包和消费者测试提供上述验收的输入契约。

## 内侧库准入

`@bear-forge/game-sdk` 是程序依赖，不是宿主能力提供者。createGameSDK 仅以 IO 和已声明端口建立同名函数，捕获固定端口键和该实例 IO，不捕获外侧 GameContract 处理器。依赖白名单覆盖该包及全部传递依赖；当前包只有公开类型依赖，没有运行期依赖。端口声明为普通自有可枚举数据属性；动态构造、隐藏属性和访问器不得绕过固定端口表准入。冻结方法表不替代 Instance 的数据隔离和续延保存。原生差分允许直接使用同一库。

受控程序与宿主的唯一运行时通信边界是已声明的 `IO.call`。非语言内建的宿主函数、回调、对象和全局环境不能作为普通依赖或实例全局值直接供受控程序调用；外侧处理器只接收端口数据并返回端口数据。纯 ECMAScript 内建计算属于程序使用的 V8 语言能力，不构成一次宿主调用；其中若某个入口读取时间、随机数、宿主调试信息或其他 Context 外部状态，则该入口仍必须拒绝，需求方通过游戏声明的 IO 端口获取相应数据。编译器生成的内建引用从显式能力表取得，未知自由名不能回落到 Node 全局；这张表不是对宿主效果的调用许可。第三方库必须随受控程序源码一起编译并遵循相同准入规则，不能把库函数直接绑成宿主回调。

`import.meta.url` 是编译时确定的代码元数据。编译器按目标 Node 的模块元数据键集识别其他宿主字段，在实例元数据对象上提供“读取即拒绝”的入口；这样直接引用、别名、动态属性读取和 `Reflect.get` 均不会把宿主解析或路径状态静默当成 `undefined`。作者程序可以先赋值或定义同名数据属性，此后该值属于 Instance 的普通状态并随 fork/restore 复制。编译阶段只读取宿主字段名称，不将其值或函数注入程序；需要实际解析服务时由游戏声明 IO 端口。

## 主 runtime 实施约束

产物提前编译成普通模块工厂，在主 runtime 内创建实例。受控路径只在共享 Program 装载时创建一个 V8 Realm；实例独立状态不依赖每实例 VM、Worker 或子进程，不改变宿主全局对象或原型。不提供强制抢占/硬超时；编译预算检查负责可插桩代码，原生调用等待其返回。受控函数调用返回的文本在公共返回口按每满 1024 个 UTF-16 代码单元扣一预算步；字符串及正则原生扫描按已转换输入文本长度计费。ArrayBuffer、类型化数组新建底层字节时每满 KiB 扣一步，字节复制按触及的 KiB 扣步，创建已有缓冲区的视图不按底层容量重复计费。类型化数组的原生扫描和原地批量方法按接收者容量作为工作上界计费，小于 1 KiB 时仅承担调用插桩成本。这些是原生操作返回后的计费，不声称能中断原生操作内部；早于末尾命中的扫描可能按输入长度上界多计。存档、恢复、fork 仍必须完整保存状态并遵循冻结协议。

`atob`/`btoa` 不作为实例全局准入；运行时也不为它们产生的 `DOMException` 保留专用 Context 编码。已准入的 Error 系列仍须保留普通属性和显式赋给 stack 的数据。

运行时提供的内建方法不一定在 Function.prototype.toString 中显示为 native code。原生操作表以可见内建值及明确准入的入口为根，按原型与自有属性描述符遍历记录函数来源；遍历发现函数只证明来源，不授予调用权限。运行时提供的方法仍必须命中调用/访问器白名单，内部符号方法不得因实现语言是 JS 而获准。受控执行器在共享 Program 装载时也将可见内建值的可达图登记为共享值，供 fork/存档按身份引用；这项登记不进入每次分支，也不把内建代码复制到 Context。共享原型仍按统一写保护规则拒绝修改。

原生能力登记与共享写保护使用同一组对象根：登记方法时，其所属对象也进入根集合。因此没有公开构造器可达的 Array/String/Map/Set 迭代器原型仍受保护；可调用入口与其可达宿主函数的来源检查共用这些根。普通游标对象及每个作者生成器函数自己的 prototype 不属于共享根，仍允许维护实例状态。同步/异步生成器的 next/return/throw 为明确登记的控制方法；共享生成器原型不可修改。
