# 唯一实施计划与 checklist

当前授权完整实施三层与横向能力收敛：请求直接指定 player，动作不含时间，会话控制可选且独立；run 单步并返回具体接受结果；保存/分支/捕捉独立路径；同步斗地主、消费者、有效文档和证据后提交推送。C01 交付协议与作者包，C02/C03 交付生产提供者。验收见 evidence/C01/convergence-acceptance.md。

本轮补充：配套内侧 SDK lib、请求/事件共享端口声明及外侧功能对应表；C01-03/05 已重新验收，生产执行器仍在 C02/C03。

规则：checkbox 与 checkpoints.json 必须一致；[x] 只代表有证据通过。[执行规则](workflow.md) 约束状态转换和证据，不能因为预估超时删项。

## C00 文档重整与执行机制

交付：22 份旧文档保留原文归档；唯一有效文档；项目 AGENTS；状态账本；可运行的一致性检查。此关不包含系统实现。

- [x] `C00-01` 归档前后 SHA-256 一致，原文件不丢失，旧 spec/docs 不再作为有效入口。
- [x] `C00-02` 有效文档自包含，保留 R01–R09 边界，无引用归档来补要求；唯一顺序与状态明确。
- [x] `C00-03` AGENTS、工作流、账本与检查脚本齐全；跳关、缺证据、状态不一致等负向用例会失败。

验收命令：python3 tools/check_project.py；python3 tools/check_project.py --self-test。原始输出和产物摘要在 evidence/C00/，语义边界按条款逐项审阅。

## C01 落实首版游戏与可执行契约

前置：C00。当前交付为 docs/doudizhu.md、实际接口 schema、完整参考游戏源码及 evidence/C01/acceptance.md；运行底座选型文档待对应实施授权。遵循 architecture.md 的 Core / Instance / BaseGame 能力边界。新增文档须登记到有效文档清单。

- [x] `C01-01` 按用户最新范围固定斗地主规则版本、歧义解释及完整单副牌覆盖；确认动作、观察、事件和作者协议边界。系统闭环的替换干预与真实快照能力仍留在后续关卡，不以本参考游戏测试代替。
- [ ] `C01-02` 按固定协议列明首版模块能力与复用边界；引入依赖时核对版本/许可。执行、编译及保存内部方案留到 C02；未知项不伪称已验证。
- [x] `C01-03` 按本轮审核范围落实 Core / Instance / BaseGame 公共 type 与固定 schema；默认十个入口，功能子路径隔离；请求直接指定 player，动作与可选会话控制分离，单步返回接受结果。上层直接组合公开接口。类型消费、封闭类别及边界检查通过。会话回执、策略记忆等具体协议在对应后续关卡落实。
- [ ] `C01-04` 为 C02 的每项验收确定真实命令/样例和期望值；给出工作拆分及本地/API 预算。若协议落地出现缺口，关联具体业务 case 提出变更，不擅自删需求。

- [x] `C01-05` 完整斗地主游戏包通过公共 Program/IO 与 GameModule 声明实现 SDK、循环、全部牌型、叫分/加倍/出牌/超时/结算；规则测试、动作独立核对、真实原生程序完整对局、隐私、输入转换、协议消费和无旁路检查通过。生产运行底座仍由 C02 验收。

本轮验收声明、游戏作者代码与原生消费者。模块复用和实施拆分分别在 C01-02/04 验收，生产执行底座在 C02/C03 验收。字段报告见 evidence/C01/boundary-migration-review.md。

## C02 执行器与 toolkit

前置：C01。交付：执行端口、保存恢复扩展、受控构建、请求/记录能力及业务验收。内部实现按协议评估现成成果后选择，不预先锁定解释器。

- [ ] `C02-01` 白名单检查覆盖传递依赖；禁止路径与动态绕过被拒绝，允许的纯计算可运行。
- [ ] `C02-02` 在嵌套调用/循环的决策等待点保存与恢复，继续结果一致；保存控制状态、局部值、随机流、请求及记录游标。
- [ ] `C02-03` 从同一快照分出两个分支，动作/状态/日志不串；恢复不靠完整前缀重放；宿主能力重绑定有反例检查。
- [ ] `C02-04` 相同显式输入可复现；预算中止、错误和 Done 分开；半执行中止现场不能冒充有效快照；只依赖 run 的入口可独立运行。

检查：真实自动化正反例、固定输入输出及恢复对照。不得只测试 JSON 数据复制。

## C03 游戏与会话

前置：C02。交付：首版游戏包、GameAdapter、会话协议。

- [ ] `C03-01` 游戏自有循环推进至真实决策/终局；完整动作到下一决策，内核无领域分支。
- [ ] `C03-02` 合法观察与历史投影通过隐藏信息反例；动作约束不泄露信息；真实事实由游戏输出。
- [ ] `C03-03` 重复、过期、非法、错分支动作不修改世界；游戏期限与计算超时分开，虚拟时间可回放；并发/限时竞争、多主体输入封存遵循协议。
- [ ] `C03-04` 目标规则的代表性与交互案例通过；同一协议可接无动画客户端，动画状态不影响权威结果。

检查：按 C01 锁定的规则范围验收；不能把局部游戏称为完整商业游戏。

## C04 固定策略共用接口

前置：C03。交付：PolicyRouter、策略版本/记忆管理、四类首版策略。

- [ ] `C04-01` RandomLegal、FirstLegal、LastLegal 和至少一个规则策略通过同一接口完整对局；排序/随机采样定义明确。
- [ ] `C04-02` 策略记忆按局/席位隔离，仅合法动作提交后更新；错误/过期回复不提交记忆；响应丢失经回执查询对齐，记忆按 commitId 只提交一次。
- [ ] `C04-03` 脚本只得到允许的数据/能力；冻结策略版本与随机配置能定位实际行为来源。
- [ ] `C04-04` 至少两种非相同行为得到可复现轨迹证据；基础脚本通过不能当强度裁判。

检查：真实对局、跨局污染/越权与重试反例。未训练模型不宣称模型已接通。

## C05 实验与数据

前置：C04。交付：单机 ExperimentRunner、任务清单、事实/轨迹存储。

- [ ] `C05-01` 多局组合策略/构筑/座次/种子独立运行，固定评测版本；不要求遍历全部组合。
- [ ] `C05-02` 故障注入后任务可恢复；task/attempt 区分、重试不重复计样本，实际预算可追踪；覆盖状态推进后存储失败和回执丢失，不发布部分提交。
- [ ] `C05-03` packet 原件、动作、行为版本、结果、事实与血缘可查询；逐 actor 轨迹奖励无漏重，隐藏审计不混入策略数据。
- [ ] `C05-04` 冻结策略卡牌替换实验提前写明可比条件、种子/座次、指标、机会分母、停止规则与独立确认集。

检查：落盘后重新加载与聚合，与原对局结果对照；空缺/故障不当作输局或零值。

## C06 关系估计与展示

前置：C05。交付：关系估计器与可查看的图/证据界面。

- [ ] `C06-01` 输出条件对局关系及至少一种卡牌替换关系，注明观察/干预、对手/构筑与适应范围。
- [ ] `C06-02` 有不确定性、机会分母、覆盖和未知状态；同局/分叉不伪装独立样本，无差异不称等价。
- [ ] `C06-03` 图可筛选上下文并定位证据样本；循环关系和冷区可表达，不强制总排名。
- [ ] `C06-04` 在预先留出的确认集复核候选关系；结果可为未知或反驳，不以必须发现超模卡作为通过条件。

检查：已知关系的统计夹具、缺数据反例及真实游戏输出；不只验收漂亮图形。

## C07 首版端到端交付

前置：C06。交付：可重放运行命令、依赖锁定、完整样本报告、限制清单。

- [ ] `C07-01` 从干净输出目录执行一条登记命令，跑完真实游戏→脚本→批量对局→事实→关系图，不依赖手工造最终数据。
- [ ] `C07-02` 另一组冻结输入可复现语义结果；非确定布局/耗时与语义结果分开比较。
- [ ] `C07-03` R01–R09 对应首版实现/明确后置的追踪表齐全；所有必需项有实际验收证据。
- [ ] `C07-04` 报告业务运行的实际成本、规则覆盖和局限，不增加性能 bench；无“通用完备已证明”“训练已成功”等未支持结论。

检查：重放命令、产物对照、全套必要检查。C07 done 仅表示首版范围完成。

## 明确后置，不混进本轮验收

神经网络训练/推理合批、自动脚本演化、构筑/打法联合适应、受限规划搜索、更多游戏和正式真人产品。在扩展实施前建立新的 checkpoint 与验收，不挪用首版 done 状态。
