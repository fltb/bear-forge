# 下一阶段：玩家受限搜索实施方案

## 1. 授权与完成定义

2026-10-23：用户授权将下一阶段搜索计划完整落盘，并与当前已验收实现一起提交、推送。本次只交付设计与实施顺序，不启动搜索、训练、基准或玩家对局；搜索实现及运行预算须待后续明确执行授权。唯一进度清单是 [plan.md](plan.md)，本文件不另设完成勾选表。

目标是在既有 Policy → PolicyRouter → BaseGame → Instance → 共享 Program 路径上增加**只利用玩家合法信息的预算化决策搜索**。搜索返回普通合法动作；所有模拟继续使用现有 STS 组合规则。不新增第二套卡牌结算、隐含全知策略、搜索专用规则解释器或公共协议层。

首版以 STS 铁甲战士和沃利贝尔为对象：先做战斗决策及嵌套选择，随后覆盖完整冒险的有限前瞻。算法正确、信息安全、规则一致、预算可控与实际棋力分开验收；不承诺在短预算内碎心、优于所有策略或得到最优构筑。

本次单源收敛是基础，不代表搜索已经存在。现有 fork/save/restore、PolicyRouter 和生产规则可以复用；合法假设世界构造、信息集树、搜索评估接线及相应正式测试仍待实施。

## 2. 范围与明确不做项

### 首版交付

- 预算化根动作采样基线，以及根采样信息集树搜索；两者使用同一个合法世界构造器和模拟器。
- 根节点保留完整合法动作域，覆盖出牌/目标、药水使用与丢弃、结束回合，以及规则产生的选牌、迎战、可选触发等连续决策。
- 冒险阶段在后续里程碑接入路线、奖励、商店、休息、升级/删除/变换、事件、Neow 与三钥匙决策。有限前瞻之外使用冻结的公开信息策略，不把搜索深度之外的结果写成已知事实。
- 可取消、可恢复的策略接线和成本记录；模拟不推进真实局，最终每次只提交一个动作。
- 固定版本、独立种子、配对对照的棋力评估与可见决策证据。

### 后置或单独授权

- 从真实隐藏现场直接 fork 的全知上界/调试搜索。若以后授权，必须独立入口、标签和数据集，不作为玩家搜索成绩。
- 斗地主/Forge 的搜索适配、对手模型、自动构筑空间搜索、卡牌数值自动优化、在线自我训练、PPO/模型新增训练。
- 通用执行器重构、Rust、GPU/远程付费推理、分布式搜索、无限后台批量实验。
- 原冻结玩家会话、正式多 agent 评审和 C++ 对照均不因本方案自动恢复。

构筑搜索不是首版中的“选一张奖励牌”：前者是外层候选生成与实验比较，需要独立合法构筑域、适应预算和确认集；先完成内层玩家搜索，再另行设计并复用既有构筑实验，不把固定搜索策略的结果称为构筑理论上限。

## 3. 信息安全与随机性边界

### 3.1 搜索可以接收什么

只接收当前玩家的 PolicyRequest、公开合法动作、visibleHistory、已提交策略记忆和独立 localRandom。角色、难度、规则版本来自已准入配置。规则的公开静态定义可以使用，但不读取真实实例的隐藏状态。

禁止输入真实 Instance/Context、完整 Frame/capture、真实存档、真实 RNG 状态/游标、抽牌堆秘密顺序、尚未揭示的房间结果/奖励/敌人行动。即使 CLI 展示了局种子，公平搜索也不使用它重建未来；实验调度种子、局内随机种子和搜索随机种子分别管理。请求 ID、实体 ID、事件编号、异常文本只作关联或诊断，不得成为隐藏信息编码或随机预测来源。

Frozen Eye 公开的牌序可作为已知约束；Runic Dome 隐藏的敌人意图必须继续未知。不得因生产内部为了结算保留了数据，就让搜索器看到它。多张相同牌的公开身份与位置须保留，不按私有实体编号推断未来。

### 3.2 必须通过的不干涉性质

对两个玩家可见请求、历史、记忆完全相同，但真实隐藏世界不同的真实局：使用同一搜索随机游标及确定工作量预算，应产生同一候选动作、搜索统计及 nextMemory/nextRandom。测试应改变真实牌序、隐藏意图、未来奖励和 RNG，而不只检查函数参数名称。

墙钟预算受调度噪声影响，不要求逐位复现；信息安全测试使用节点/模拟次数预算，性能测试另行使用墙钟。父局状态、请求、事件、RNG 在搜索前后必须不变。

## 4. 游戏所属的合法假设世界构造

这是第一项实现关卡，不能把 fork 能用当成已经解决。

输入是合法公开前缀及搜索随机流；输出是与该前缀一致、能在原生产规则继续执行的假设游戏，以及采样方法、接受率/权重、覆盖范围和不支持原因。构造器位于 STS 所属适配代码，通用搜索器不认识卡牌、状态机或 RNG 字段。

### 4.1 先采用可核验的生产重放构造

1. 用独立假设随机源从正常 setup 创建候选世界，走同一个 Program 与初始化路径；不使用真实局种子。
2. 按玩家可见的已接受动作前缀推进，逐边界比较公开投影、合法动作及已揭示随机结果。
3. 不一致的候选拒绝；一致的候选可在真实等待边界成为模拟根。采样成本和拒绝次数计入搜索总预算。
4. 拒绝采样从明确先验出发；说明它条件于哪些观察，不能将任意“看上去合理”的拼装状态称为后验样本。
5. 缺少完整公开前缀、无法构造、接受率过低或粒子不足时，显式返回 unsupported/budget-exhausted，退回合法基线；不得暗中复制真实现场来提高成功率。

重放可能很慢，这是待测风险，不是已证明可用的性能方案。若需增量粒子过滤、条件采样或直接物化，只能由游戏提供并证明其约束/概率与继续执行语义正确；不得私造 PC、跳过生命周期、重掷真实局随机数或改变规则。

### 4.2 未完成流程与支持矩阵

构造必须恢复真实可继续的控制状态，不只复制 HP、手牌和敌人：包括嵌套选择、剩余多选次数、已选择集合、尚未完成的牌效果、动作队列、作用域/临时能力、触发顺序、目标存活变化和必要历史。首轮明确列出普通战斗决策、选牌、迎战、药水、事件及奖励窗口的支持状态。

通过生产重放自然抵达这些等待点优先于手工重建。不能构造的窗口在支持矩阵中保留未支持并测试回退；不能因此宣称全流程搜索已完成。

每个样本的公开投影及根合法动作须与实际请求一致。合法历史可以约束隐藏状态，但样本内部隐藏变量仍不得传给未来的策略或叶子评价器。

一期默认每个真实决策重新搜索，不跨请求保留游戏分支或可变树缓存。策略记忆仅存可序列化的必要信息；恢复后可以按冻结配置重算，不要求持久化整个树。跨请求树复用只能在信息边界、动作映射及取消语义证明之后再加入。

## 6. 算法路线与动作语义

### 6.1 R0：公开信息基线

实现一个明确版本、稳定破同分的合法基线，用于超时/不支持回退及效果比较。First/Random 仅作烟测，不能作为唯一棋力对照。启发式只基于公开 HP、费用、资源、牌组与当前合法动作，避免按隐藏未来或目标卡牌 ID 写“成功答案”。

### 6.2 R1：根动作采样基线

对同一组合法世界样本评估根候选，每个动作都由生产规则执行，后续用固定公开信息 rollout 策略。根候选的共同随机样本用于减少比较方差，但动作分歧后不承诺随机调用仍逐项对齐。记录每动作样本数、平均回报、离散度与截断率。

预算允许时先对全部根候选完成均衡首轮。预算不足覆盖全部候选时，明确报告未探索动作；按冻结规则回退或在已评估集合中选择并标注覆盖不足，不偷偷删除药水、结束回合或大多选组合。

### 6.3 R2：根采样信息集树搜索

以 R1 为可对照基线，在每次模拟从一致世界集合根采样，使用 UCT 类选择、实际合法动作扩展、冻结 rollout 与回传。初版不引入神经先验；探索常数、最大深度、叶子权重在开发集冻结。

决策节点键由玩家公开观察及必要可见历史组成，不含样本编号、真实 RNG、隐藏牌序或完整 Context。树中的后续策略只能用当时可见信息；不能在不同样本中提前知道秘密后分别选最优，再把这些全知价值平均回根（strategy fusion）。随机结果通过原规则产生，其被公开后才允许分开信息集。

节点动作的可用次数与访问次数分开统计；隐藏状态使候选集合不一致时，先核验其合法信息含义与构造正确性，不能用拒绝动作的错误文本探测真实秘密。根动作集必须与实际请求一致。

首版不采用隐藏全状态的置换表。未来若做缓存，必须包含规则/策略版本、信息集与预算口径，并通过别名、并发和污染测试。

### 6.4 动作映射与执行

模拟根中的动作映射到当前真实候选的公开语义：牌及公开位置/身份、目标、选择集合、饮用/丢弃/结束/跳过等。不能把分支内实体 ID、手牌旧下标或上一决策的展示 ID 直接提交到真实局。每次搜索最多提出一个动作；真实状态推进后重新观察和规划。

组合动作域不得因为枚举昂贵就伪装成完整：游戏可使用既有 construct 适配提供合法生成/排序，记录覆盖与采样概率；不修改合法校验器或限制作者表达来配合搜索。具体请求采用 exact 还是 construct，以现有正式契约为准。

### 6.5 评价与冒险扩展

终局使用真实胜负/碎心结果；非终局截断使用明确版本的公开特征评价，至少区分生存风险、生命与资源成本、进度、牌组负担和钥匙目标。权重是待冻结的策略选择，不写入规则定义，也不把估计值叫作规则事实或胜率。

战斗评估必须处理跨回合、消耗/药水价值、多个敌人和特殊胜负条件，不能只优化当前回合伤害。冒险扩展再加入当前地图已知信息、合法分支与三钥匙可达性；未知房间内容、奖励和未来 Boss 行动按合法世界采样，不能读取预生成的真实结果。两阶段分别报告成绩。

## 7. 预算、取消、回退与恢复

以下是**待执行授权时确认的首轮上限建议**，不是当前运行许可，也不是性能承诺：

| 项目 | 建议上限/规则 |
| --- | --- |
| 本地并发 | 1 个搜索 worker 起步；测清内存与取消后才增加，不默认多 agent/多进程 |
| 每真实决策 | 2 秒墙钟、256 次模拟、8 个接受世界样本、64 次构造尝试；任一上限先到即停 |
| 单次模拟 | 64 个玩家决策或 8 个战斗回合；终局、无法构造/继续或剩余预算耗尽更早停止 |
| 树与内存 | 最多 10,000 节点；进程 RSS 软限 1 GiB，达到后停止扩展并释放分支，不能宣称硬抢占内存 |
| 单局/批次 | 单局搜索累计 60 秒；首轮开发批次 10 分钟；后续比较批次每批 30 分钟，另设局数上限 |
| 外部费用 | 0；不调用付费模型、不租卡、不启动训练 |

构造、fork、推进、投影、特征计算、无效样本、重试与失败全部计成本。模拟次数只计完整约定的一次尝试，另记完成/截断/故障数量；不能把构造开销移到计时外。

两种预算模式分别支持：确定工作量模式用于复现与不干涉验收；墙钟模式用于交互延迟。同步 JS 推进不能假定 AbortSignal 可硬抢占；在安全边界协作检查预算，并测量最长不可中断段。若交互需要硬截止，使用受管 worker 隔离终止模拟进程，真实局不随其退出。没有硬截止保证时明确报告超时上界未知，不包装成已保证的 2 秒 SLA。

取消、过期请求、竞争失败和非法候选不提交策略记忆/RNG；所有分支在 finally 关闭。预算耗尽保留最后一个完整合法候选，否则返回冻结基线；若请求已失效则丢弃，不向旧决策发动作。搜索截断、规则故障、世界构造失败和真实输局分开计数。生产规则故障不得悄悄当作低分动作继续宣传搜索成功。

恢复复用既有游戏 snapshot 与策略路由状态；确认已接受动作后从下一真实决策继续。可重算未提交搜索，不重复已接受动作。冻结配置、策略版本、采样方法与搜索随机位置；版本改变使用新实验目录。

## 8. 实施顺序与关卡

| 阶段 | 具体产出 | 依赖与退出条件 |
| --- | --- | --- |
| Q01 信息契约 | STS 可见/隐藏字段及动作身份清单、支持窗口、独立种子规则、不干涉用例 | 先证明搜索接口不接真实实例；禁止先做全知搜索再补过滤 |
| Q02 合法世界 | 生产重放构造器、样本一致性验证、预算化拒绝、失败回退 | 每个支持窗口能继续原规则；不支持项显式列出，不手工伪造控制状态 |
| Q03 预算基线 | R0/R1、成本统计、取消释放、确定工作量复现 | 非法动作/真实状态污染为零；故障、预算不足可诊断 |
| Q04 信息集树 | R2、信息集键、访问/可用性统计、公开 rollout/叶子评价 | 与 R1 同域同预算比较；通过 strategy-fusion 与隐藏信息反例 |
| Q05 真实接线 | PolicyRouter、CLI/runner、恢复与证据；铁甲及沃利贝尔战斗窗口 | accepted-only 提交；当前动作映射正确；不调用测试 fixture 冒充生产 |
| Q06 冒险扩展 | 地图/商店/事件/奖励等有限前瞻、三钥匙规划及未支持矩阵 | 战斗关卡先稳定；所有未知结果保持采样，不混用真实未来 |
| Q07 正式验收 | 类型/规则/信息边界/取消恢复检查、限定成本测量 | 全部本批实现与测试编辑完毕再统一检查；只修具体失败，不新增全域重构 |
| Q08 独立评估 | 冻结版本/预算后的配对结果、区间、失败/截断与成本 | 实际运行须获预算授权；可得“未决”，不得为过关挑种子或调确认集 |

分工可按“通用搜索与预算”“STS 世界构造与动作映射”“测试/运行接线”划分互不重叠写范围。世界契约未确定前不并行造另一套状态；后续阶段依赖前一关卡证据，Lead 集成后统一检查。

## 9. 正式验收矩阵

| 维度 | 必须覆盖的反例与证据 |
| --- | --- |
| 信息不干涉 | 同可见前缀、不同隐藏牌序/意图/未来奖励/RNG；同搜索随机与工作量应同输出。Frozen Eye 与 Runic Dome 分别检验权限变化 |
| 单一规则执行 | 卡牌、药水、敌人、触发、生命周期均走生产组合；同一假设 setup/动作前缀在独立生产实例重放得到一致结果，不用搜索器自己的伤害表作 oracle |
| 未完流程 | 嵌套选牌、迎战、可选触发、多选、抽牌、死亡/复活、作用域及队列等待；恢复后不重复触发或重新初始化 |
| 隔离 | 父局与兄弟分支状态/RNG/历史互不污染；Program 共享，Context 独立；模拟结束及时释放 |
| 候选完整性 | 目标、重复牌、多选、药水饮用/丢弃、结束/跳过和状态改变后的动作重新映射；预算不足如实报告覆盖 |
| 搜索统计 | 信息集聚合、不预知随机、访问和可用次数、稳定破同分；确定工作量重放一致；非法候选不作为探测真实局的手段 |
| 事务与取消 | accepted/拒绝/过期/并发竞争/中途取消/恢复，只有 accepted 提交记忆和随机；无残留 worker 和重复动作 |
| 成本 | 构造接受率、模拟吞吐、fork/推进/投影成本、节点峰值、RSS、决策 p50/p95/最大延迟、超预算率、回退率；完整冷启动和摊销成本分别报告 |
| 效果 | 按角色、难度、战斗/完整冒险和固定预算分层，死亡/胜利/碎心/截断/故障分别报告；不以测试通过替代棋力证据 |

正式命令沿用仓库：`npm run typecheck`、`npm test -w @bear-forge/policies`、`npm test -w @bear-forge/runtime-card`、`npm test -w @bear-forge/cli`、`STS_COMPARE_CPP=0 npm test -w @bear-forge/sts`。新增测试必须纳入所属模块正式 test/check 脚本；若改动其他模块，再补对应命令。当前尚无可运行的搜索 CLI，本方案不杜撰命令或可用开关。

## 10. 评估设计、证据与停止规则

1. 分离开发、调参/筛选和最终确认种子；已有碎心夹具与熟知的 seed 130 只作开发/回归，不能充当独立确认成绩。
2. 建议开发每角色 8 个种子；冻结后的试验每角色 32 个新种子，R0/R1/R2 配对同 setup 比较，按批次预算可提前结束但保留缺失与停止原因。正式确认的固定样本量在试验后根据精度要求预先登记，再使用全新种子；未经批准不自动扩批。
3. 搜索随机重复嵌套在同一游戏种子内；分支、节点和同局决策不是独立样本。按种子块计算配对差值及不确定性，重复比较作相应控制；小样本/罕见碎心允许输出未决，不用零方差当确定结论。
4. 同时比较同墙钟预算与同模拟量两种成本口径，不能让 R2 用更多算力后只报告胜率。各角色独立报告，不用角色难度差掩盖算法差异。
5. 记录规则/策略/构造器版本、输入可见状态、真实已接受动作、搜索预算、各候选覆盖/估值、回退原因和实际开销。玩家记录不暴露假设内部秘密或真实隐藏状态；调试数据隔离并明确仅为假设，不能伪装真实未来。
6. 复用现有实验目录和查看证据路径，不创建独立验收账本或临时第二平台；模型/大量实验产物不提交 Git，必要的小型正式测试夹具归测试目录。
7. 出现信息泄露、规则分歧、真实状态被修改、不可回收资源或错误动作提交立即停批并修复；吞吐不足则报告瓶颈和支持边界，不回退成全知搜索。效果不显著或预算耗尽可以结束并报告未决，不因此继续扩大计算。

最终交付报告必须分别回答：哪些窗口能搜索、是否满足合法信息边界、是否复用唯一规则、运行成本多少、在哪些独立样本上有改善、哪些仍未知。只有全部约定工程关卡通过才勾选实现完成；只有真实授权实验产生结果后才填写效果结论。
