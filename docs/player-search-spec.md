# STS 玩家受限搜索：实现与验收规格

实施进度及实际检查、运行结果只在 [plan.md](plan.md) 跟踪。本文规定当前有效行为；历史方案中“构造假设根”“禁止接收真实 Context”“执行历史前缀”等要求已经撤销。

## 1. 范围与授权

交付铁甲战士和沃利贝尔的预算化玩家搜索，接入现有 Policy、PolicyRouter、BaseGame、实验 runner、CLI 和证据查看接口。战斗、嵌套选择及完整冒险均使用已有 STS 规则。用户已授权持续执行 Q01–Q08、有界开发和独立评估、最终 commit/push；不在内部阶段重复申请许可。

用户于 2026-10-24 明确的边界：

- 起点就是**完整真实当前 Context**，直接分支，不 mask、不从公开观察重造根。
- 严格 `next(current)`。分支、保存、恢复都处理现成 Context；任何初始化后执行历史、旧检查点动作前缀、动作带重放均禁止，包括测试与校验。
- 已经发生的状态固定。未揭示的未来排序采用新的随机空间，允许切断它与过去建牌顺序的相关性；模拟中随后产生的关联状态仍须保留。
- 当前已确定的敌人真实意图及其关联状态可作熟练玩家背板知识，包括 Runic Dome。**只能执行原敌人意图、行动、触发和结算路径**，不得再次执行已经发生的 choose。
- 未来尚未发生的选招仍执行原 choose，通过独立概率内核展开；不使用真实未来 RNG、隐藏牌序或奖励。
- 卡牌、敌人、资格条件、阶段切换、拒绝条件和结算全部使用原数据、原定义及同一执行器。差异仅在搜索、随机执行及隐藏排序内核；不得另写 AI 表、伤害公式或规则解释器。

不启动新增训练、自动构筑优化、Rust、C++ 对照、付费推理、分布式搜索、正式多 agent 评审或原冻结玩家会话。不以搜索结果保证碎心、最优解或棋力提升。

## 2. 信息与动作契约

策略评分只消费原 contract 给出的玩家请求、合法动作、visibleHistory、已接受策略记忆和独立搜索随机游标。执行适配持有完整 Context，负责按上述授权产生后继，不把内部状态交给评分器。

`information.ts` 使用严格原 schema，排除种子、RNG 和未声明字段；动作键是原合法动作的 bits。请求/递送 ID 不参与信息集键。详细事件中的实体关联标识按完整公开历史规范化，保留身份相等关系，不利用私有分配间隔。原 `card-change` 发布遵循原 Frozen Eye 可见性，不能通过隐藏牌堆的费用重置顺序泄漏牌序。

Frozen Eye 已公开的顺序是已知约束。Runic Dome 的公开观察仍隐藏意图；允许搜索沿原执行路径结算当前意图，不改变公共 contract。

不干涉验收：固定当前已授权敌人意图及关联状态，改变实际隐藏牌序、未来奖励池、未揭示宝箱内容或 RNG；公开输入与搜索随机游标相同、确定工作量预算相同，应得到相同动作、搜索证据、nextMemory 和 nextRandom。墙钟模式不要求逐位复现。每次搜索后父局的状态、请求、历史和 RNG 保持不变。

## 3. 数据结构与一次后继

通用接口在 `packages/policies/src/search/search.types.ts`：

```ts
type SearchCurrent = {
  position: SearchPosition; // 原公开观察、完整合法动作、公开叶子分数
  close(): Promise<void>;
};
type SearchSuccessor = {
  action: string;
  outcomes: { current: SearchCurrent; probability: number }[];
  representation: 'exact' | 'particles';
};
```

每个 current 拥有独立 Context，所有 current 共享原 Program。`next(current)` 惰性产生每个原合法动作的完整带权后继。每条执行边只推进一次；搜索保留其结果，后续访问读取缓存，不驱逐后再执行动作路径。

根为一个实际 current，权重 1。后继生成到随机点时，从该点的完整当前状态分支，乘以原随机操作给出的条件概率。自动 event 端口按原 contract 继续，到玩家决策或终局才交付。交付分布的每项概率为正、有限且总和为 1；取消、预算耗尽或异常导致的残缺分布不能归一化成一条有效边。

`ProbabilityFrontier` 保存带权当前 Context 及数据元信息。小有限空间精确枚举；超过容量时使用明确标记的有限粒子近似。一次粒子化不会因后续确定操作变回 exact。集合最多 8 行；每个分支保留全部调用帧、局部值、队列、作用域及未完成操作。

## 4. 概率与排序内核

- `packages/card-engine/src/probability.ts` 定义概率空间、坐标、精确/采样结果与独立熵源；`rules-probability.ts` 给原随机/排序原子登记概率执行方法。
- `CardMachine.advanceProbability` 与普通 advance 共用同一解释器和指令。仅在登记的概率操作处暂停，子 Context 接受一个坐标后由原操作提交结果，再继续原规则。
- `packages/runtime-card/src/probability.ts` 管理当前分支所有权、惰性后继、权重、自动端口、取消和释放。共享静态采样器不进入 Context；不能在子分支提交时再次生成同一结果。
- STS 的 `rules/random.ts` 普通模式保留原伪随机数、计数与流更新；概率模式使用独立搜索熵和原值映射，不以真实 RNG seed 生成未来结果。
- `rules/ordering.ts` 只接受原定义给出的值、权重、严格阈值或准入掩码，计算概率像及条件质量，不认识敌人或卡牌机制。

### 隐藏顺序

`order-space.ts` 的有序可交换块表达已知顶底牌与未知成员；分块内均匀排列数为各块阶乘之积。不能用连续块表达的中间插入、未知位置移除、部分位置公开，由 `order-language.ts` 的带权无环顺序图表达。图是当前分布，不是可执行的历史操作带。

顺序坐标使用稳定牌身份排序，不依赖真实隐藏数组顺序。抽牌只展开所需顶牌边缘；窥多张按连续条件概率展开前缀，保留未揭示后缀。原 reveal/move/触发操作更新条件空间。按顺序找牌须条件化“此前均未匹配”，不能简单删除匹配成员后把剩余牌均匀化。

普通后续洗牌仍先执行原排列、重排/移动与触发；只有原操作确认的新独立未知部分可声明 fresh。已物化或已揭示的部分不能在每个子节点重新随机化。初始分组洗牌使用原先天/瓶装分组，完整排列仍供原 created/注册回调执行，保留这些副作用；真实根的过去副作用按模型 1 固定。

### 冒险空间

普通/精英遭遇使用原 `encounterSelection` 的 float24 阈值、阶段和拒绝规则；排序内核仅计数并条件化。遗物抽取继续原资格循环、拒绝移除和池耗减。宝箱大小公开后，未揭示金币有无与档次通过**同一个原 chestOutcome 整数映射**联合生成，不能拆成独立变量或沿用真实缓存答案。

跨幕地图使用唯一的原 `map.ts` 算法，概率模式只替换随机整数来源。一般地图以 particles 标记；第四幕固定地图为精确单结果。商店折扣/补货、房间替换、事件资格、奖励与升级均执行原定义。

### 持久化及通用能力

STS 实例使用 `mode:'current'`：只持有真实当前 Context 与成本账户，不创建或维护历史 posterior。保存绑定模式，拒绝旧 posterior 快照混用。`takeProbabilityCurrent` 不执行指令、不读取历史集合、不重新选择当前敌人意图。

runtime 的通用 posterior、公开声明条件化及前向捕获能力仍供原当前分支操作和回归使用；它们不是 STS 生产根来源。一般条件化使用 `Z = Σ wᵢ L(o|Cᵢ)` 与 `wᵢ′ = wᵢ L(o|Cᵢ)/Z`，零支持显式失败，不能补入实际隐藏答案。即使使用公开约束，也只能继续尚未执行的当前输入，禁止回跑旧随机点。

## 5. belief 与概率 AND-OR 搜索

一个 belief 是具有相同公开决策的带权 current 集合 `B={(Cᵢ,wᵢ)}`，`Σwᵢ=1`。对动作 a，原后继核给出 `T(Cᵢ,a)={(Cᵢⱼ,pᵢⱼ)}`，联合质量为 `qᵢⱼ=wᵢpᵢⱼ`。按后继公开观察 o 分组：

- `P(o|B,a)=Σ_(i,j:O(Cᵢⱼ)=o) qᵢⱼ`
- 子 belief 中的权重为 `qᵢⱼ/P(o|B,a)`。

未来动作由公开 belief 决定，不能先在每个隐藏世界各取最优再平均。共享观察仍需保留内部 Context 的差异。完全相同的当前执行状态可合并质量；比较须包含控制状态、别名、对象身份与相关元数据，不能仅凭公开视图相同合并。

`evaluation.ts` 给出冻结的公开启发式 v，范围 [-1,1]；叶子成本 `c=(1-v)/2`，范围 [0,1]。评分只含实际原后继的公开生命、楼层、钥匙、金币、牌组负担等策略权重，不实现第二套伤害预测或结算。

每个节点保存 lower/estimate/upper：

- 终局或已到有限前瞻截断的叶子三值相等，等于该叶子成本。
- 未展开节点使用合法界限 [0,1]，estimate 为公开启发式成本。
- 动作 AND 边的三值分别是各观察子节点对应值的概率加权和。
- 决策 OR 节点分别取允许动作的最小值。

先覆盖完整根合法动作域，再优先扩展 lower 较小、estimate 较小的动作；其观察分支按 `概率×界限间隙` 排序。每次扩展后向祖先回传。公开 baseline 在满药水栏时优先离开而非反复领取无效果奖励；原合法动作与原获取规则不改。R1 的非根节点只允许公开 baseline 动作，R2 允许全部原合法动作。证据中的界限和最优性间隙仅针对**供应概率模型与有限前瞻叶子目标**；粒子采样误差不包含在其中，不能解释为完整游戏胜率或总体置信区间。

最终优先选择已认证的动作，否则选择完整根覆盖中的最低估计成本动作。根覆盖不完整时返回合法公开 baseline，并注明原因。普通实现错误直接报错，不吞掉后伪装成预算回退。

## 6. 预算、取消与成本

默认上限：

| 项目 | 限制 |
| --- | --- |
| 搜索 worker | 1 |
| 每决策墙钟 | 2 秒，协作式检查 |
| belief 动作展开 | 256 |
| 单带权集合 | 8 个 current |
| 通用观察尝试 | 64；STS 实际根不做假设构造 |
| 前瞻 | 64 个玩家决策或 8 个战斗回合 |
| 累计分配节点 | 10,000，包含瞬时概率分支 |
| RSS 软限 | 1 GiB |
| 单局累计搜索及相关宿主成本 | 60 秒 |
| 开发批次 | 至多 10 分钟、每角色至多 8 个种子 |
| 后续比较批次 | 各至多 30 分钟，局数事先登记 |

配置可采用更小上限，必须在运行前冻结并报告。work 模式忽略决策墙钟，只用于确定工作量验收；它仍受节点、RSS 与单局安全上限约束。wall 模式受调度和 GC 噪声影响。停止检查不能抢占任意同步 JS 指令，不能宣称硬实时保证。

`simulations` 是开始的 belief 动作展开数；`completed` 是原子发布的完整动作边；`advances` 是实际新执行后继；`nodes` 包含执行节点、belief 节点及瞬时分支；`truncated` 记录非终局截断叶子。它们不是独立统计样本。

根交接、fork、概率生成、推进、公开投影、分组、评分及释放均计费。保存/恢复的编码、存储、读取、解码及物化计入账户；阶段计时可能嵌套，不能直接相加。最长测量段可能包含嵌套调用或等待，不等于最长不可抢占同步段。CLI/runner 另报完整任务时间、CPU、RSS 和快照成本。

当前 Context 的增量回收按分配对象及实际字段写入安排扫描工作；避免宽帧不断产生新标记却始终无法清扫。fork 和首次写入不扫描完整世界；垃圾回收不通过重新执行历史换空间。

预算/取消不发布部分动作质量，全部未交接和已保留分支均释放。V8 低堆安全停止通过专门资源类型转换为 heap-budget 明确回退；不能靠匹配普通错误文本吞掉实现缺陷。单局耗尽明确标记 game-search-budget；缺少宿主当前能力仍是配置错误，不借耗尽降为合法调用。

## 7. 正式策略、恢复与证据

`createSearchPolicy` 接通 R0/R1/R2。宿主在真实 GameHandle 的稳定请求边界提前计算策略，forkCurrent 复制当前 Context；然后 BaseGame 验证并接受普通动作。不得在忙碌回调里取得已转交所有权的旧 Instance，不改公共协议。

PolicyRouter 只有在 accepted 时提交 nextMemory、nextRandom 与对应证据。丢弃、拒绝、过期和取消候选不能提交策略状态。宿主成本独立保存，包括被丢弃工作；不能通过恢复免费重置预算。

检查点同时保存原 Context、RouterState、成本及已接受记录。宿主自有记录在文件写入首个 await 前直接序列化为独立字节，不先深拷贝整个历史；后续调用方修改不能影响该次写入。恢复直接装入 Context；已提交任务不重跑。硬中断后的未知成本按原任务上限保守预留。原批次墙钟窗口包含停机时间，不因 resume 重置。

实验注册冻结规则、策略、依赖源码、运行时和参数身份，变更实现须使用新目录。R0/R1/R2 配对共享游戏 seed，策略熵 seed 独立于游戏 seed。公共 contracts 保持冻结。

运行入口：

```sh
npm run sts -- search OUTPUT_DIRECTORY CONFIG.json
# 读取原目录的冻结配置、Context 和记录
npm run sts -- search OUTPUT_DIRECTORY
```

`SearchRegistrationSchema` 严格限制角色、算法、预算、重复/污染种子和单 worker。示例实际注册与结果保存在忽略的 data/ 实验目录，不提交大量产物。现有证据查看接口按玩家返回公开请求/事件与**已接受动作的搜索证据**，不输出 Context、私有策略附加字段或真实未来。查看服务沿用 `npm run serve -- --output OUTPUT_DIRECTORY`。

## 8. 支持与验收边界

所有窗口共用原 decision/event 契约和同一概率执行器；没有搜索专用结算。正式测试覆盖：

| 范围 | 定向覆盖 |
| --- | --- |
| 两角色战斗 | 原 63 种遭遇的初始完整根动作，包括结束回合的加权后继 |
| 当前敌人意图 | Runic Dome 下 Book of Stabbing 连续两回合，原单次/多次攻击及直接恢复；未来选招保持随机 |
| 牌序与嵌套 | 抽牌药水、随机药水选牌、按序找牌/连打、沃利贝尔窥二/三张、Frozen Eye、耗尽后洗牌及原遗物触发 |
| 冒险 | 连续真实路径经过首战/奖励、商店、宝箱、精英、休息、后续事件 |
| 定向窗口 | Neow、永久升级/删除/变换/复制、补货商店、第二/三幕事件、特殊遗物奖励、三钥匙及三次跨幕 |
| 所有权与恢复 | 父局/兄弟隔离、禁止初始化、原未完流程直接保存恢复、accepted-only、取消及预算清理 |
| 数学与资源 | 非等权概率、观察归组、边界回传、精确/粒子标记、残缺质量拒绝、节点/RSS/时间计费 |

这是对实现路径和代表状态的验收，不是对全部卡组、事件分支和任意长度玩法穷举证明。预算不足可能使某次合法窗口根覆盖不全，必须显示回退；不能用持续回退冒充搜索覆盖。原游戏未实现或明确不支持的内容仍保持原行为，搜索不补造机制。

安全的正式检查入口：全仓 `npm run typecheck`；card-engine/runtime-card 的 `test:probability`；policies/game-host/experiments 的 `npm test`；STS 的 `test:search`、`test:rules`、`test:run`；CLI 的 `test:search`；证据查看模块的 `check`。不得运行旧入口中包含历史重放的测试，也不运行 C++ 差分。实际通过数、失败及范围只记入 plan.md。

## 9. 独立评估与完成标准

开发种子与冻结评估种子分开；已知 seed 130 等只作开发，不能当独立成绩。每角色冻结试验最多 32 个新种子，最终确认用未参加开发或 pilot 的新种子；运行前冻结样本量及每批局数，不根据胜负追加样本。

分别报告角色与 work/wall 口径；同配置的展开上限不等于实际消耗相同，必须同时报告实际展开/推进数、覆盖率、回退率、p50/p95/最大延迟、超时率、峰值 RSS、冷启动及完整任务成本。被资源删失的工作量模式不能冒充严格等工作量对照。

按游戏种子计算 R1−R0、R2−R0 的配对差值，战斗结果与完整冒险结果分开。决策、分支、粒子和同局多个战斗不是独立样本；缺失/截断不能当胜负。区间使用现有 analysis 工具并控制多重比较，小样本常量结果仍保留不确定性。原数据、注册和分析使用现有实验格式，不建立第二评估平台或独立审计账本。

出现信息泄漏、规则分歧、真实局污染、错误动作提交或不可释放资源立即停批修复。工程正确、资源有界和棋力提升分别判断；没有改善或统计证据不足可以报告未决，但不能用单元测试代替实际评估。

完成须满足 Q01–Q08 的工程产出、正式检查、有界成本及已授权独立评估；说明支持边界、未知项和成本。最后审查实际 diff、核对 Git 身份、提交推送并核对远端。未完成项不得提前勾选。
