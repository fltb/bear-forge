# Bear Forge：项目、实现与审核入口

Bear Forge 的目标是用同一份游戏规则，运行不同策略和构筑，保留真实对局证据，分析有条件的克制、卡牌替换和协同关系。它不把一次胜负当成平衡结论，也不承诺找出最优策略。

首版用固定脚本完成这个流程。现成 DouZero 学习器支持 WP 预训练、输入迁移、冻结对手和跨局更新；自研 Transformer/PPO 使用独立环境，为斗地主全部决策阶段与 Forge Duel 提供共用训练代码，冻结模型可进入原有关系实验和证据界面。具体运行及验收结果只见 plan.md。STS 已接入基于完整当前 Context 的 R0/R1/R2 玩家受限搜索，按 next(current) 用原执行器展开未来概率空间；实现、信息边界与独立评估见 player-search-spec.md 和 plan.md。策略进化、MCTS、正式多人运营和更多商业游戏仍是后续范围。搜索树属于策略层，概率分支属于执行适配；不重建假设根，不重放历史。

受控执行已拆分共享 Program 与独立 Context：同产物代码注册一次，装载时以临时 Context 检查 schema，新局 start 初始化实例数据，fork/restore 不再初始化模块或静态元数据。结构检查与行为差分分别验收，见 plan.md。

## 1. 一个普通任务怎么运行

两款正式游戏用 TypeScript 声明卡牌 Core 的同步步骤、调用和选择等待。规则、牌库、随机状态、尚未结束的结算都在实例内。需要玩家选择或发布事件时，Card Core 停在声明端口；拿到回复后继续执行。同一定义用于原生与受控模式，普通任务无需存档或分支。任意 TS 的编译执行另由并列通用后端保留。

外侧的游戏绑定器把这些端口解释成玩家请求、合法观察、合法动作和可见事件。策略按席位绑定，只看到自己的请求。游戏负责最终合法性和结算，绑定器不复制规则状态。

实验调度器选择规则版本、构筑、策略、座次和种子，运行完整对局。默认串行，可显式登记 1–4 局并发，仍在同一 Node 进程中运行。对局完成后，把输入、结果、实际策略请求、接受的动作、游戏事实和成本一起写入任务文件。分析从这些真实结果计算关系；界面读取分析结果和具体对局。

## 2. 三层协议分别负责什么

| 层 | 负责 | 不属于它的状态 |
| --- | --- | --- |
| Core | 装载程序、创建实例，以及可选恢复、记录访问 | 游戏规则、策略、实验调度 |
| Instance | 一个程序的完整执行现场、端口等待、单步接受和结束/故障 | 外部策略记忆、时钟输入队列、搜索树 |
| BaseGame | 把 Instance 的端口解释成玩家请求、观察、动作、事件和结果 | 第二套规则世界或结算引擎 |

公共协议位于 packages/contracts，字段、枚举、方法和导出路径保持冻结。其他模块组合这些接口。实验回执、策略版本和文件格式没有塞进 BaseGame。

Instance.run 接受一次端口返回。BaseGame.run 接受至多一个玩家动作或会话控制，然后交付后续事件，到下一请求、暂停或终局。accepted 只说明规则执行层接受了输入；它不表示实验结果已可靠保存。

## 3. 两条执行路径

正式卡牌游戏的两模式都直接执行同一份同步 Card Core 定义，不经过通用编译器；原生使用普通状态，受控增加 COW、记录、分支和保存恢复。下面的 async/await 与续延对照表描述保留的通用程序后端，不是两款卡牌游戏的实际执行循环。

| 项目 | 原生路径 | 受控路径 |
| --- | --- | --- |
| 执行 | V8 原生 async/await、Promise | V8 执行提前生成的续延 JS |
| 源码 | 同一游戏/通用程序 | 同一游戏/通用程序 |
| 实例状态 | 直传函数可共享闭包/模块状态；原生构建产物按实例重建模块工厂 | 共享 Program 下，各实例 Context 独立 |
| 普通 IO | 同一 Node 进程内回调 | 声明端口与受控调度器 |
| 保存/fork | 不提供这两项能力 | 在完整等待点和正常结束点提供 |
| 普通任务 | 完整对局后提交；中断可重跑未提交的局 | 可以逐步保存，恢复未完程序 |

直接传入 NativeCoreLoader 的 ProgramModule 是受信任的本地 JS，可以直接调用宿主或共享闭包；它只接受公共端口和 schema 的边界检查，不接受 IO-only 或 fork/restore 保证。经过原生构建的入口额外落实源码准入、模块重建和可插桩预算，但保留原始 async/await/Promise，因此同样不承诺 IO-only。只有编译受控入口提供这项保证。原生运行可作为 V8 语义对照，不能代替受控路径验收。

原生实验有构建产物时使用该产物；没有时使用游戏提供的可信 `ProgramModule` 直传。受控实验必须提供受控产物。原生登记及其结果不能当成 IO-only 验收。

受控构建使用 Rollup、Babel 和 EffectfulJS core v2。构建时把跨 await 存活的控制流、局部变量和闭包转成显式现场，并提前生成函数工厂。运行时不读取 TypeScript 源码，不运行 Babel，也不逐条解释作者 AST。

采用 core v2 是因为最初的 es-persist 路线在嵌套 async 闭包恢复中出现反例。vendor/effectful 保留 MIT 许可、上游版本和必要补丁说明。项目裁剪了调试 UI，并替换运行时动态函数构造。

## 4. 编译准入、数据隔离与预算

受控构建先做 TypeScript 语义检查，再解析闭合依赖图。作者源码使用明确的语法和全局能力名单。网络、Node 宿主 API、动态导入、eval、Function、真实时间/熵、原生未决 Promise 等不能成为受控规则能力。依赖不能任意按包名加载；目前批准的第三方游戏依赖是固定版本的 Zod。直接传入的可信原生函数不经过这些源码检查。

登记默认计算计数预算为 100,000,000，进程 RSS 软预算为 4096 MiB。RSS 在启动/决策边界检查，并行局共用同一个进程限额；它不能中断单次大分配，也不是堆内存硬隔离。预算超限记为截断，不生成胜负或奖励。

循环和生成的控制流程有预算检查；原生构建也在函数和循环处插入计数。预算异常即使被作者 catch，执行层仍保持故障状态。schema 内的编译代码同样执行预算检查，校验耗尽预算不能退化成普通非法回复或正常终局。经过构建的原生路径同样阻止被捕获的隐式熵变成成功结果。实验把 budget_exceeded 或决策上限归类为截断，不判输赢。

跨界值经过复制和 schema 检查。普通对象/数组及允许的原始值不能夹带函数、访问器、隐藏字段或资源。检查拒绝会改变输入值的边界 schema；Zod 不承担隔离的全部责任。

这不是运行任意恶意 JS 的通用安全产品。没有独立进程级堆内存硬隔离；受控路径在共享 Program 装载时创建一个 V8 Realm，Instance、fork 和 restore 不新建 Realm，也不使用 Worker 或独立进程承载实例；AST 检查或步数预算不是恶意代码沙箱。没有硬超时，无法插桩的原生调用等待返回。原生内建调用的最坏资源消耗也不等于插入计数器就已受控。

Map/Set、数组、字符串、类型化数组及 RegExp matchAll 的受控游标，以及同步/异步生成器已有可保存状态实现；原生游标内部槽不直接写入 Context。未经适配的原生游标不能交付给作者状态。具体支持与排除条件以 controlled-program-spec.md 为准，整体值域验收状态见 plan.md 顶部。

## 5. 保存、恢复和分支究竟保存什么

快照只编码独立 Context 并关联程序身份及记录前缀。Context 包含跨外部 call 所需的控制状态、局部值、闭包捕获环境、模块可变数据、对象引用关系、SDK 状态和预算；共享代码及静态元数据不进入快照。run 绑定和 schema 实例值仍属于 Context，闭包代码通过标识引用共享注册表。导出命名空间只有被源码实际使用时才保留；入口使用 this 时保留接收对象，别名不变。未使用的导出不作为额外根，自定义校验捕获的状态也不丢失。

恢复关联已加载的同一产物并读回 Context，不重新执行模块初始化；新进程先装载匹配产物并完成 schema 准入，随后直接读回 Context；准入用的临时 Context 不作为恢复源，也不运行游戏入口或历史输入。恢复和 fork 使用新的实例身份，保留当前 CallId 和历史前缀，清空外侧回调绑定。重新绑定策略后才继续。

fork 复制完整当前现场，不更改真实父局。STS 搜索适配直接接收当前 Context，通过原规则与独立概率/排序内核展开未揭示未来；评分器只消费原公开观察。当前已确定的敌人意图及关联状态按背板授权复用，包括 Runic Dome；不能借真实未来 RNG、牌序或奖励评分，也不能重新执行旧 choose 或历史前缀。

提供了内存和文件快照提供者。文件提供者先写临时文件、同步、重命名，再同步目录。故障中的半执行现场不能保存成有效检查点。

## 7. 策略、会话和轨迹

策略提供 FirstLegal、LastLegal、RandomLegal 和 Forge Rule。前三者按游戏提供的稳定动作顺序选择；随机策略使用显式、独立的随机游标，记录实际行为概率。规则策略根据合法观察评估出牌、攻击、致命伤害和交换，不读取隐藏现场。

PolicyRouter 暂存候选动作、记忆变化和事件。只提交 run 返回的实际获胜候选。错误、过期和竞争失败的回复不推进已提交记忆或随机游标。每局、每席位隔离，记忆提交使用任务和逻辑步身份去重。

轨迹保留实际请求、实际接受动作、行为/编码版本、概率和玩家可见事件。终局奖励按席位记录；故障/截断没有伪造的胜负奖励。没有动作的席位仍保留独立终局奖励字段。

VirtualSession 记录显式到达时间和稳定序号，比较当前请求凭证与游戏声明的期限。相同时间使用 timeoutFirst。它只选择输入，由游戏解释 timeout/clock；游戏报告接受后才推进会话时钟和消费输入。普通训练实验没有游戏期限输入时，不强行创建会话时钟。driveSession 通过公开 bind/bindControl/run 接线，不直接修改规则世界。

## 8. 实验登记与文件提交

没有数据库。一个实验目录保存：

- 不可变登记：规则、策略组合、构筑干预、种子块、预算和分析参数。
- 生产代码/依赖身份和冻结的构建产物。
- 每个任务的逐次尝试记录、完整终态文件和用于查询的摘要。
- 受控任务的检查点文件，以及提供者保存的完整快照。
- 从已提交结果计算的分析结果。

任务身份固定，不用每次尝试的 UUID 计样本。原生任务中断时重跑尚未提交的完整对局；受控任务可通过 checkpointEvery=N 每 N 个决策保存；默认 0 仅提交完整局，有检查点时从最近的已提交检查点继续，否则重跑未提交的完整局。任务文件通过临时文件和原子重命名提交，提交前不会出现在证据查询中。提交后回执丢失时，重启读取同一任务文件，不重复计样本。

检查点同时保存快照引用、策略记忆、已提交轨迹、接受回执和逻辑步。ExperimentFiles.receipt(taskId, logicalStep) 从检查点或最终任务文件查询已提交回执，重试不重新推进策略。新快照先持久保存，再提交引用它的检查点。进程在两者之间退出时，旧检查点仍是有效进度。

同一个目录只允许一个活跃调度器写入进程。内部任务按有界批次并发，每局独立；快照回收只在没有活跃保存的批次边界执行。崩溃留下的锁会在确认原进程已退出后恢复。摘要是可重建的查询辅助数据；完整任务文件是依据。大量轨迹不一次性传到浏览器。

快照的活引用就是已提交检查点。替换检查点后释放旧快照；独占调度器在重启和任务完成时回收无引用内容，包括保存成功但引用未提交的孤儿。每次尝试另有持久记录；进程突然退出而没有保存成本的尝试明确标为成本未知，不补成零成本。

目前没有跨机器调度、云存储或多调度器并发写入。恢复不自动迁移旧程序或格式。

## 9. 什么实验、怎样判断关系

示例 baseline.json 登记 128 个发现种子块和另 128 个独立确认种子块，交换两座次，冻结四类策略及对手。首个干预把指定火花槽替换成爆裂；第二项把指定守卫槽替换成修复。两个干预形成完整 2×2 条件。示例共 2 阶段 × 128 种子 × 4 策略 × 4 对手 × 2 座次 × 4 条件 = 32,768 局；这是可调整的示例规模，不是系统启动或验收的必跑数量。

条件对局关系比较胜率与 0.5；替换关系使用同种子/座次的替换差；交互关系使用四条件的差中差。先合并同一独立种子块的座次，再按种子块 bootstrap。故障或缺失导致配对不完整时，该块不冒充零分，缺失数量另报。实际任务记录根任务身份；分析拒绝重复任务、重复配对格和分支结果，不能把重试或 fork 当独立对局。

默认最少 64 个完整块、最小有意义差异 0.05、bootstrap 2000 次。发现集先选择候选，再读确认集；确认使用按候选数分配的尾部概率和足够的重采样次数。区间是有限样本近似，不宣称严格覆盖保证。

状态包括支持正向、支持负向、落入预设等价区间、未知、缺失和不适用。没有显著差异不能写成等价。携带、抽到、可用和使用分别统计，稳定事件键去重；当前机会计数对应登记中的评测席位。

256 局 demo 只用每阶段两个种子块，因此应显示未知。它验证链路，不代替完整统计实验，也不预先手工指定最终关系边。

## 10. 展示与命令

界面使用 React、Vite 和 Cytoscape。Node HTTP 服务仅绑定 127.0.0.1，提供只读查询：进度、条件关系、任务和分页证据。可以筛选策略/对手，在图或表中定位对局，分别查看玩家 0、玩家 1 和明确标注的分析审计数据。

```sh
npm ci --ignore-scripts
npm run check
npm run build:games
npm run build:viewer
npm run demo -- --output ./data/demo
npm run serve -- --output ./data/demo
```

正常实验和恢复（预算也会冻结）：

```sh
npm run experiment -- --config examples/forge-duel/experiments/baseline.json --output ./data/baseline --concurrency 1 --memory-mb 4096 --compute-steps 100000000
npm run experiment -- --resume --output ./data/baseline
npm run analyze -- --output ./data/baseline
```

登记配置可指定 engine 为 native 或 controlled，默认 native。受控运行需要 build:games 产物与打包的 runtime；根 build:games 会先 build:runtime，build 则同时构建游戏/runtime/查看界面。运行部署只需准备好的产物/runtime，不在 Loader 内编译。demo 会先构建游戏；使用空输出目录，已有实验用 resume。

审核重点是源码和正式测试；docs/plan.md 仍是唯一进度清单。未验收的要求不能因为这里介绍了模块就标完成。项目已验证本机神经训练的执行闭环，但不宣称模型收敛或达到竞技强度；没有通用完备性证明，也没有跑完全部默认统计任务便得出的平衡结论。

## 13. 验证、成本和审核限制

正式检查在各包 tests/ 中，根命令汇总。受控差分包含闭包/递归、控制流、异常、排序、图遍历、背包、矩阵、显式随机、Unicode/JSON、小型解释器、特殊数值和实际 Zod；比较完整调用轨迹和结果，并在各等待点保存恢复；另跑无外部 IO 的算法变体。图距离、背包和矩阵还有独立算法 oracle。两种完整游戏对照原生结果与事实；独立子进程只载入产物/runtime 来恢复。双潮焚契验证真实分支、私密取牌、来源离场、故障和旧凭证。文件实验测试真实进程退出，不只是抛异常模拟重启。关闭实例清除执行器与 schema 的持有引用；宿主原型不挂接实例序列化注册表，已释放实例可以回收。

这组测试验证列出的准入案例；它不是对所有 TypeScript 程序的证明。规范中更广的算法举例可以继续补充，新增语法、第三方库或后端能力必须补入正式差分。

当前性能测量与完成状态统一见 [实施计划](plan.md)。捕获投影复用后，Forge Duel 同一首个 IO 现场的快照为 866,686 字节，较优化前减少 10.4%；直接 Context fork 约 10 ms，保存/恢复约 15–19 ms，不含磁盘，也不是任意游戏的耗时上界。

独立进程中同一组 16 局的两次重复测量：原生端到端约 6.12 秒，受控约 61.1 秒；执行阶段峰值 RSS 分别约 350 MB 和 1.49 GB，均在登记预算内且全部正常结束。受控执行有明显额外成本，不承诺与原生同速或适合高吞吐搜索。完整计时口径、范围及限制见计划，不能将编译堆、装载、创建、写盘混称为普通游戏函数成本。

通用引擎 benchmark 分别输出计算和创建/保存/恢复/fork 耗时，不设置依赖机器的速度断言。算法差分日常运行小/中数据量，大数据量使用 `npm run test:benchmarks:extended -w @bear-forge/runtime-controlled`。

构建产物在 build/，演示输出由 --output 指定；这些是业务产物，不提交到 Git。主分支保存源码、锁定依赖、规格和正式测试。
