# 目标与边界

此文件定义有效需求。完整交付按 C01–C07 连续推进；具体实施选择见 [implementation-spec.md](implementation-spec.md)。C01 为协议、斗地主作者包及原生消费者；C02/C03 为生产运行底座。当前代码目录和范围说明见 project-overview.md；完成状态只以 docs/plan.md 和实际验收为准。

## R01 产品目标

通过脚本、搜索或模型探索卡牌游戏中的构筑与打法，以带条件、不确定性、覆盖和证据的关系图识别替代、协同、克制与未知区域。规则正确性是前提；通过规则测试不代表设计好坏。不得用单一胜率或总分代替关系分析。

## R02 首版范围

系统闭环目标包括一个明确版本的游戏；RandomLegal、FirstLegal、LastLegal 和至少一个有规则依据的策略；多局独立运行；固定策略/构筑条件的对局比较；至少一种明确的卡牌替换干预；关系图和样本证据。完整斗地主游戏包验证接口，规则配置见 doudizhu.md；系统闭环按 C04–C07 交付，可构筑干预游戏采用 implementation-spec.md 中 forge-duel-v1 的实施默认，需先落实独立规则文档/schema 和测试。

先脚本，后模型。神经训练、自动脚本演化、受限搜索、完整商业游戏复刻及正式多人运营界面均为后续范围，不阻塞首版。不以三种基础脚本足以评价平衡为前提。

## R03 执行边界

下述独立 Context、IO-only、保存和分支保证适用于编译受控入口。直接装载 `ProgramModule` 是明确受信任的原生游戏代码入口：它仍按公共端口协议交互，但其闭包和宿主访问不受编译准入约束，也不提供保存或分支。不能用原生运行结果证明受控保证。

Core 提供通用受控执行机制；Instance 是一个程序的完整运行态，只有声明端口调用、返回、结束与执行故障，没有游戏语义。BaseGame 位于 Instance 上层，落实游戏交互约定并提供跨游戏可训练接口。项目提供配合外侧功能的内侧 game-sdk lib 与共享端口契约；具体游戏提供领域类型、规则、循环、组合后的 SDK、端口声明和适配处理器。BaseGame 不复制规则状态，不另写结算。外部调用参数及返回由声明 schema 校验；编译受控入口禁止绕过端口取得宿主状态。Instance.bind/run 负责通用端口回调和单步控制；BaseGame.bind/run 提供逐请求玩家回调及单步结果。玩家动作从 onRequest 返回，可选会话输入从 bindControl 的回调返回。直接运行不依赖存档、训练或搜索。

Instance 是唯一完整运行态。内侧 GameSDK 和具体游戏规则在其中执行，外侧 BaseGame 通过共享 GameContract 绑定该 Instance。保存和恢复只使用 InstanceSnapshot；分支返回同类型 Instance/BaseGame。所有影响继续执行的 SDK/服务状态在 Instance 内；策略记忆、会话及搜索树属于调用方。Core 不认识随机或时间的含义。

执行代码与实例上下文必须分离：同一编译产物在提供者中加载为共享 Program（内部实现概念，不新增公共类型），Instance 持有独立 Context，runtime 带着该 Context 和端口返回调用共享代码。程序对外是黑箱，Core 只识别端口边界、正常结束和故障，不解释游戏规则。

环境一步接受一个动作或会话控制后，交付其事件并到达下一个请求或终局；下一请求可属于其他玩家。run 返回具体接受结果。

## R04 状态与副作用

本节的源码准入、IO-only 与可复制现场要求针对编译受控入口；可信原生直传不由源码检查器审查闭包或宿主访问。公共端口值、schema 和驱动租约仍由对应执行器检查。

作者方向为 TS+toolkit、成熟语言实现与依赖白名单，检查必须覆盖传递依赖。纯计算用语言能力，不另造语言。linter 不作为安全隔离证明。随机、时间、外部输入必须显式受控；游戏规则状态不得藏在宿主绑定中。宿主绑定不得藏有游戏继续执行所需的内部状态；受控伪随机流可以在内侧计算，真实外部不确定性必须作为显式输入。

作者程序及其全部传递依赖只接受严格语义的 ES Module；TS 仅去类型并按 ESM 执行。Script 全局声明环境、非严格语义、CommonJS 输入、运行时生成代码及动态模块加载不属于首版准入。准入范围内的原始 ESM 以固定目标 V8 的行为为差分基准；范围外程序明确拒绝，不能改写后冒充等价执行。

准入采用白名单及其内部排除规则；未知构造拒绝，具体语义与 Core/SDK 分层义务见[受控程序规范](controlled-program-spec.md)。合法性与作者来源无关；通过类型检查或原生对局测试不能代替该准入。

快照支持完整外部输入等待边界及结束边界，Instance 保存继续执行需要的全部运行状态、待决调用和记录游标；内侧 SDK/服务状态一并纳入 Instance；公共协议不暴露内部表示。恢复不依赖重放完整游戏前缀；分支相互隔离。当前优化要求 COW 快速分支：fork 不遍历完整状态，首次推进不能补做完整复制；不要求任意指令处可恢复抢占。快照与程序、规则及保存格式版本绑定。运行内部方案按 implementation-spec.md 的选型关卡验证，以 architecture.md 的公共协议为约束。

Context 是可独立复制/编码的数据根，包含跨 call 继续执行所需的控制位置、局部值、调用帧、闭包捕获环境、模块可变数据、对象引用关系及 SDK 状态。这些由编译器显式化；普通同步计算仍直接用 V8，不要求作者手写状态机。闭包代码引用共享 Program 的稳定标识，捕获的可变数据属于 Context。并非只保存游戏场面 JSON，也不保存原生 JS 栈或活动函数对象。

fork 在内存中复制 Context，复用已加载 Program；save 编码 Context 并关联程序身份；restore 解码 Context 后关联对应 Program。已加载同一产物时不得重新执行程序/依赖初始化或重建静态调试元数据。新进程可以加载一次匹配产物。用户未绝对禁止重放，但不得依赖完整历史增长的重放开销，也不能重新执行历史外部副作用；本轮采用 COW，不以重放替代分支状态隔离。静态代码、模块导出容器和整套依赖对象不得作为通用快照根。schema 的静态逻辑可复用；自定义检查捕获的可变状态仍须进入 Context。把对象图命名为 Context 并不能满足此边界。

记录前缀仍按固定协议保留，由记录能力管理；可以共享不可变前缀，不强制塞进执行堆或每次深复制全部历史。内存 fork 不必经过持久化字符串和文件存储。fork 创建共享状态根，后续成本对应实际修改的数据和索引路径，不能每次包含加载整份程序或完整复制实例数据的成本。

执行预算中止在协议中为 fault/budget_exceeded，在实验中归类为 truncated，不自动判输赢；中断半执行现场不能当有效快照。语言表达能力和实际实现正确性分别举证，不宣称对任意游戏穷尽验证。

## R05 实例与策略

ExperimentInstance 调度规则×构筑×策略×座次×种子×预算，不要求穷举笛卡尔积。每局 BaseGame 独立；PolicyBinding 保存席位的固定策略版本及独立记忆。共享冻结代码/权重，隔离游戏状态、记忆、随机流、请求与日志。模型可以跨局合批。

真人、脚本、模型按 player 独立绑定同一决策协议。游戏请求直接指定 player；GameContract 投影各玩家状态和事件。行动主体属于请求的领域数据。策略只拿合法观察/历史，不能拿真实隐藏现场、种子或审计日志。过期/重复/非法提交不能改变状态或推进策略记忆。游戏通过 exact 完整列表或 construct 自定义 JSON 描述提供输入选项；Game 上层调用方负责解释构造约定，通用层不解释输入空间。

## R06 数据与训练

BaseGame 能力管交互；训练适配管编码、行为概率、奖励与轨迹；分析适配管领域事实、机会与关系语义。记录实际发给策略的观察及实际行为版本。按 player 与请求身份连接轨迹，具体行动主体由领域数据解释，保留中间可见事件，奖励不漏不重；终局、截断和错误分开。

训练、评测与推理共用规则及决策路径。评测冻结版本；学习器产出新版本后显式切换。脚本数据用于模仿训练；PPO 数据记录真实采样策略。自回归完整动作概率按条件概率组合。编码与动作分布由训练适配定义。

## R07 实验与证据

严格区分固定策略冲击、固定构筑战术适应、构筑/打法生态适应；首版只实现第一类。观察关联不标作因果。机会定义明确区分携带、抽到、可用、使用；未知、不适用、未充分探索不作零值。以正确抽样单位估计不确定性，分支和同局决策不当独立对局。

保留历史威胁与独立挑战，不只留平均胜率最高者；循环克制可存在。独立确认集不能用于适应后仍称独立。冷区覆盖不能证明不存在模型/脚本偏向，有限预算也不能保证发现所有设计问题。

## R08 时间、前端与搜索

游戏限时使用独立可选会话控制；动作仅包含动作。实战真实时钟与训练虚拟时钟均转成控制输入，超时处理由游戏规定。计算超时与游戏期限不同。动画纯前端，不等待动画来推进规则，也不作为环境时间。

后续玩家搜索从合法信息构造假设世界，复用原游戏规则；游戏提供构造器。只有独立授权的分析实验可分叉真实全状态。快照能力不等于安全搜索能力。

## R09 成本与不承诺项

已有 RTX 4070，本地优先；增量计算与 Agent API 合计上限 $500，人工不包含其中。C01 验收完整斗地主源码；生产执行/会话与系统闭环按后续关卡交付。现成实现按固定协议评估复用，后端在 C01 选型项确定。完整交付验收见 implementation-spec.md；成本以实际实验记录核算。
