# 目标与边界

此文件定义有效需求。状态：已有协议和斗地主游戏源码，系统运行底座未实现。

## R01 产品目标

通过脚本、搜索或模型探索卡牌游戏中的构筑与打法，以带条件、不确定性、覆盖和证据的关系图识别替代、协同、克制与未知区域。规则正确性是前提；通过规则测试不代表设计好坏。不得用单一胜率或总分代替关系分析。

## R02 首版范围

系统闭环目标包括一个明确版本的游戏；RandomLegal、FirstLegal、LastLegal 和至少一个有规则依据的策略；多局独立运行；固定策略/构筑条件的对局比较；至少一种明确的卡牌替换干预；关系图和样本证据。当前用户单独授权完整斗地主游戏包验证接口，规则配置见 doudizhu.md；不在本轮实施系统闭环。后续仍须确认干预游戏范围，不能把斗地主接口样例冒充设计分析系统完成。

先脚本，后模型。神经训练、自动脚本演化、受限搜索、完整商业游戏复刻及正式多人运营界面均为后续范围，不阻塞首版。不以三种基础脚本足以评价平衡为前提。

## R03 执行边界

Core 提供通用受控执行机制；Instance 是一个程序的完整运行态，只有声明端口调用、返回、结束与执行故障，没有游戏语义。BaseGame 位于 Instance 上层，落实游戏交互约定并提供跨游戏可训练接口。具体游戏提供领域类型、规则、循环、SDK、端口声明和适配处理器。BaseGame 不复制规则状态，不另写结算。外部调用参数及返回由声明 schema 校验，禁止绕过端口取得宿主状态。Instance.bind/run 负责通用回调和控制，BaseGame.bind/run 提供游戏语义回调及边界控制；手动回复与回调驱动共用唯一执行路径。直接运行不依赖存档、训练或搜索。

Instance 是唯一完整运行态。内侧 GameSDK 和具体游戏规则在其中执行，外侧 BaseGame 通过共享 GameContract 绑定该 Instance。保存和恢复只使用 InstanceSnapshot；分支返回同类型 Instance/BaseGame。所有影响继续执行的 SDK/服务状态在 Instance 内；策略记忆、会话及搜索树属于调用方。Core 不认识随机或时间的含义。

环境一步是一个完整真实决策提交后，推进到下一个真实决策或终局；下一决策可属于其他玩家，不要求整张牌结算完。模型生成参数的 token 不是环境步。

## R04 状态与副作用

作者方向为 TS+toolkit、成熟语言实现与依赖白名单，检查必须覆盖传递依赖。纯计算用语言能力，不另造语言。linter 不作为安全隔离证明。随机、时间、外部输入必须显式受控；游戏规则状态不得藏在宿主绑定中。宿主绑定不得藏有游戏继续执行所需的内部状态；受控伪随机流可以在内侧计算，真实外部不确定性必须作为显式输入。

准入采用白名单及其内部排除规则；未知构造拒绝，具体语义与 Core/SDK 分层义务见[受控程序规范](controlled-program-spec.md)。合法性与作者来源无关；通过类型检查或原生对局测试不能代替该准入。

快照支持完整外部输入等待边界及结束边界，Instance 保存继续执行需要的全部运行状态、待决调用和记录游标；内侧 SDK/服务状态一并纳入 Instance；公共协议不暴露内部表示。恢复不依赖重放完整游戏前缀；分支相互隔离。不要求 COW、O(1) fork 或任意指令处可恢复抢占。快照与程序、规则及保存格式版本绑定。运行内部实现暂缓选择，以 architecture.md 的公共协议为约束。

执行预算中止归为 fault/truncation，不自动判输赢；中断半执行现场不能当有效快照。语言表达能力和实际实现正确性分别举证，不宣称对任意游戏穷尽验证。

## R05 实例与策略

ExperimentInstance 调度规则×构筑×策略×座次×种子×预算，不要求穷举笛卡尔积。每局 BaseGame 独立；PolicyBinding 保存席位的固定策略版本及独立记忆。共享冻结代码/权重，隔离游戏状态、记忆、随机流、请求与日志。模型可以跨局合批。

真人、脚本、模型共用决策协议。策略只拿合法观察/历史，不能拿真实隐藏现场、种子或审计日志。过期/重复/非法提交不能改变状态或推进策略记忆。游戏通过 exact 完整列表或 construct 自定义 JSON 描述提供输入选项；Game 上层调用方负责解释构造约定，通用层不解释输入空间。

## R06 数据与训练

BaseGame 能力管交互；训练适配管编码、行为概率、奖励与轨迹；分析适配管领域事实、机会与关系语义。记录实际发给策略的观察及实际行为版本。按 actor 连接轨迹，保留中间可见事件，奖励不漏不重；终局、截断和错误分开。

训练、评测与推理共用规则及决策路径。评测冻结版本；学习器产出新版本后显式切换。脚本数据可作模仿数据，不冒充 PPO 原策略采样。自回归完整动作概率按条件概率组合。框架复用不等于无需自定义编码与分布。

## R07 实验与证据

严格区分固定策略冲击、固定构筑战术适应、构筑/打法生态适应；首版只实现第一类。观察关联不标作因果。机会定义明确区分携带、抽到、可用、使用；未知、不适用、未充分探索不作零值。以正确抽样单位估计不确定性，分支和同局决策不当独立对局。

保留历史威胁与独立挑战，不只留平均胜率最高者；循环克制可存在。独立确认集不能用于适应后仍称独立。冷区覆盖不能证明不存在模型/脚本偏向，有限预算也不能保证发现所有设计问题。

## R08 时间、前端与搜索

游戏限时是显式会话协议；实战真实时钟与训练虚拟时钟均转成可记录输入，超时处理由游戏规定。计算超时与游戏期限不同。动画纯前端，不等待动画来推进规则，也不作为环境时间。

后续玩家搜索从合法信息构造假设世界，复用原游戏规则；游戏提供构造器。只有独立授权的分析实验可分叉真实全状态。快照能力不等于安全搜索能力。

## R09 成本与不承诺项

已有 RTX 4070，本地优先；增量计算与 Agent API 合计上限 $500，人工不包含其中。无吞吐实测、无学习效果保证、完整斗地主源码已有测试，生产执行/会话与系统闭环尚未完成。现成实现按固定协议评估复用；后端未选定。本轮不编写 bench。不得以历史估算当当前验收指标。
