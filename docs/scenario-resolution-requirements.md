# 双潮焚契：结算、分支与恢复案例

## 初始局面

| 对象 | 状态 |
| --- | --- |
| 甲 | 生命 10，法力 3，手牌仅有「双潮焚契」 |
| 乙 | 生命 10，法力 0，手牌仅有「旧符」 |
| 甲的「余烬见证者」W | 耐久 2 |
| 乙的「灰狼」L | 耐久 2 |
| 乙的「石卫」G | 耐久 3 |
| 甲的牌库 | 从顶到底为「泉」P、「刃」B、「种」S、「月」M、「山」N |

手牌、牌库顺序对对手隐藏。对象以实例 ID 区分；离场再进入产生新 ID。

## 卡牌与时机

### 双潮焚契

支付 3 点法力施放。双方依次放弃响应后开始结算。

依次执行两波：

1. 甲选择一个当前在场的生物，包含自己的生物。没有生物则跳过本波。
2. 目标控制者可弃一张手牌，防止本波全部伤害；没有手牌则自动不防止。
3. 未防止则造成 2 点伤害。耐久降至 0 或以下的生物立即死亡。
4. 将本波实际伤害加入本次法术的累计伤害。

两波完成后，累计伤害至少为 2 时，甲查看牌库顶至多三张，选一张加入手牌，其余按原相对顺序放到牌库底。没有牌则跳过，只有一张则自动取走。

最后法术进入甲的弃牌区。

### 余烬见证者

另一个生物死亡时，若 W 当时在场，生成触发，记录 W 的实例 ID 和当时的控制者。

法术结束后，触发按生成顺序进入游戏堆叠，后进入的先结算。双方放弃响应后，触发的控制者选择一位玩家，使其获得 1 点生命。W 后来离场或易主，不改变已生成触发的控制者。

### 决策规则

- 游戏堆叠存放待结算法术和触发。
- 法术结算期间的选项不开放施法响应窗口。
- 每次只接受当前请求的授权玩家提交一次完整动作。
- 唯一选项自动执行；非法动作不推进游戏。
- 一个请求由「对局 ID、分支 ID、请求 ID」共同定位。

## 主路径与恢复点

甲施放法术，法力变为 0，手牌为空。法术实例记为 F。双方放弃响应。

| 等待点 | 决策 | 主路径选择 | 接受后发生的事 |
| --- | --- | --- | --- |
| Q1 | 甲选第一波目标 | L | 打开乙的防止选择 Q2 |
| Q2 | 乙是否弃「旧符」 | 不弃 | L 受 2 点伤害并死亡；累计伤害 2；生成 T1；打开 Q3 |
| Q3 | 甲选第二波目标 | G | 打开乙的防止选择 Q4 |
| Q4 | 乙是否弃「旧符」 | 弃掉 | G 不受伤；累计仍为 2；甲看到 P/B/S；打开 Q5 |
| Q5 | 甲从 P/B/S 中取一张 | B | B 入甲手牌；牌库变为 M/N/P/S；F 入弃牌区；T1 入堆叠 |
| 响应窗口 | 双方响应或放弃 | 均放弃 | T1 开始结算，打开 Q6 |
| Q6 | 甲选择获得生命者 | 甲 | 甲生命 11；T1 完成 |

恢复点定义为请求已经生成、回复尚未接受时：

| 恢复点 | 必须接续的情况 |
| --- | --- |
| K2 = Q2 | 第一波目标已固定为 L，尚未造成伤害 |
| K3 = Q3 | 第一波已经结束，L 已死亡，T1 已生成，第二波目标未选 |
| K4 = Q4 | 第二波目标已固定为 G，乙尚未弃牌，累计伤害 2 |
| K5 = Q5 | 乙已弃牌，第二波已结束，甲已看见 P/B/S，尚未取牌 |
| K6 = Q6 | F 已结束，T1 正在结算，尚未增加生命 |

主路径最终状态：甲生命 11、法力 0、手牌 B；乙生命 10、手牌空；W 耐久 2、G 耐久 3；L、旧符、F 分别进入其所有者的弃牌区；牌库 M/N/P/S；T1 已完成。

## Case 1：同一个防止选择分成两个世界

起点 K4，复制为分支 A、B。

- A：乙弃旧符；甲在 Q5 取 B；Q6 选甲。
- B：乙不弃；甲在 Q5 取 B；Q6 选甲。

| 结果 | 分支 A | 分支 B |
| --- | --- | --- |
| G 耐久 | 3 | 1 |
| 乙手牌 | 空 | 旧符 |
| 累计伤害 | 2 | 4 |
| 生成的触发 | 只有 T1 | 只有 T1 |
| 甲最终生命 | 11 | 11 |
| 甲手牌/牌库 | B / M,N,P,S | B / M,N,P,S |

执行 A 时，B 和原始 K4 保持不变。A 的弃牌事件不得出现在 B 的记录中。两个分支都只能记录一次第一波死亡，不能把共同前缀算成两次实际死亡。

## Case 2：第二波摧毁触发来源

起点 K3。甲将第二波目标选为自己的 W。

甲此时没有手牌，自动不防止，不产生等待请求。W 受 2 点伤害并死亡；累计伤害变为 4。W 不为自己的死亡产生触发。

甲完成取牌后，T1 仍进入堆叠，仍由甲在 Q6 选择受益者。选甲后生命为 11。不能因为 W 已不在场而删除 T1，也不能重新查询场上 W 来确定谁作选择。

## Case 3：从每个恢复点继续同一条路径

分别保存 K2、K3、K4、K5、K6，销毁原运行实例；各自恢复后输入主路径剩余选择。

| 起点 | 不能重复执行的部分 |
| --- | --- |
| K2 | 支付法力、施放 F、选择第一波目标 |
| K3 | 第一波伤害、L 死亡、生成 T1 |
| K4 | 上述内容及选择第二波目标 G |
| K5 | 弃旧符、第二波结算、打开本次私密看牌 |
| K6 | 取 B、调整牌库、F 入弃牌区、T1 入堆叠 |

所有恢复运行最终得到主路径状态。恢复后的当前选择者、合法选项、可见历史与保存时一致。已提交事件不再次发布为新事件。

## Case 4：恢复后再次分支

保存 K3，销毁实例，恢复为 R，再从 R 分出 A/B。

- A：第二波选 G，乙弃牌，之后按主路径。
- B：第二波选 W，自动不防止，之后按主路径。

A 中 W 存活、G 耐久 3、乙手牌空；B 中 W 死亡、G 耐久 3、乙仍持旧符。两支都保留第一波的 T1，最终甲生命均为 11。

R 仍停在 Q3，W/G 均可选，乙仍持旧符。恢复不应让分支共享可变目标列表、待处理触发或牌库数组。

## Case 5：私密选择点分支

起点 K5，甲已经看到 P/B/S。

- A：选 B，甲手牌 B，牌库 M/N/P/S。
- B：选 P，甲手牌 P，牌库 M/N/B/S。

两支随后完成 T1。乙在两支中都只看到甲获得一张牌、法术结束，不能通过选项列表、事件负载或错误信息知道甲拿了哪张。

保存并恢复 K5 后，甲仍看见同一组 P/B/S；不得再次抽样、改顺序或重新触发看牌事件。

## Case 6：上一波的目标已经死了

起点 K3，甲提交目标 L。

拒绝：L 已不在场。仍停留在 Q3，合法候选为 W/G；累计伤害保持 2，T1 仍只有一项，无第二波伤害。

随后甲提交 G，应能正常进入 Q4。第一次非法提交不能消耗第二波，也不能偷偷改成随机目标。

## Case 7：错误玩家与错误动作类型

起点 K4：

1. 甲替乙提交“弃旧符”：拒绝。
2. 乙提交“施放另一张法术”：拒绝；当前不是响应窗口。
3. 乙提交“弃甲的手牌”：拒绝。
4. 乙提交“弃两张牌”：拒绝；协议只允许不弃或弃自己的一张手牌。
5. 乙提交合法“不弃”：接受，G 耐久降为 1，进入 Q5。

前四次请求不扣资源、不产生领域事件、不改变累计伤害，不消耗当前合法选择机会。

## Case 8：重复回复与跨请求回复

起点 K4，乙合法提交弃牌，已进入 Q5。

- 网络重发完全相同的 Q4 回复：返回已处理结果或明确拒绝重复；不能再次弃牌。
- 乙将 Q4 的“不弃”作为另一条回复发送：拒绝；不能撤销已提交的弃牌。
- 将 Q4 的回复标作 Q5：拒绝；Q5 的授权者和动作类型都不同。
- 甲合法选择 B：正常继续；非法输入没有提前结束 Q5。

## Case 9：分支回复混入另一分支

从 K4 创建 A/B，两支各生成自己的有效请求凭证。

乙对 A 提交弃牌。随后把携带 A 凭证的回复发送给 B。

B 拒绝，仍保持 G 耐久 3、乙持旧符，等待自己的 Q4。A 的凭证不能因为两支起源于同一快照而在 B 生效。

恢复到新会话时，旧会话凭证失效；游戏选择内容保持一致，新会话生成新的有效凭证。

## Case 10：对象离场后以相同卡名返回

另设一条响应路径：甲施放 F 后、法术开始结算前，乙用已准备好的效果令 L 离场，再将同名灰狼放回场上，新实例为 L2。双方随后放弃响应。

Q1 候选包含 L2，不包含 L。甲提交旧实例 L 被拒绝；提交 L2 合法。不能用卡名相同或复用数组位置让旧引用命中新对象。

此响应发生在法术开始结算前；不能插入 Q2/Q4 的防止选择期间。

## Case 11：相同场面，不同的未完流程

构造两个合法等待状态：

- X：从初始局面施放 F，尚未处理第一波，停在 Q1。W/L/G 均在场，甲法力 0、手牌空，乙持旧符。
- Y：使用一张同样支付 3 点法力的变体法术 F2，其第一波只记录一次“空过”，不改变对象；现在等待第二波目标。其余状态与 X 相同。

两者世界对象的生命、手牌、耐久和牌库可以完全一致，但 X 还剩两波，Y 只剩一波。

各自选 L、乙不防止后：X 还应询问下一波目标；Y 应进入法术尾部奖励。仅凭场面数据不能确定应该去哪一个等待点。

## Case 12：处理输入中故障

起点 K4，乙提交弃牌；执行过程中已在工作副本移走旧符，但尚未生成 Q5 时发生错误。

本次推进不能作为成功提交向客户端发布。不得出现“乙已弃牌、系统仍让乙回答原 Q4”的有效局面。

选择从 K4 重试时，重新执行这一次回复，最终只弃一张牌、只生成一组第二波记录。选择丢弃本局时，结果是执行故障，不是乙输、平局或正常终局。

## Case 13：恢复到正在等待受益者的触发

起点 K6。分别选择甲、乙。

- A 选甲：甲 11、乙 10。
- B 选乙：甲 10、乙 11。

两支的手牌、牌库、法术弃牌状态完全相同；不能重新执行法术奖励，也不能再开放一次 T1 结算前的响应窗口。

## Case 14：法术被反制，内部选择根本不发生

在初始局面的变体中，乙持有一个可用的免费反制效果。在 F 进入游戏堆叠后，乙响应将其反制。

F 进入甲弃牌区，已付的 3 点法力不退。W/L/G 耐久不变；不生成 Q1–Q6、不查看牌库、不产生 T1。

不能因为施放入口预先创建了两波任务，就在 F 被反制后继续执行这些任务。

## Case 15：有条件的尾部被跳过

初始局面变体：乙手牌为旧符 U1、旧符 U2。两波目标都选择 G，乙分别弃 U1/U2 防止伤害。

累计伤害为 0，G 耐久仍为 3，W/L 均存活。不生成取牌请求 Q5、不查看牌库、不生成 T1；F 直接结束并进入弃牌区。甲手牌仍为空，牌库仍为 P/B/S/M/N。

## 逐点核对

| 位置 | 当前还欠游戏什么 |
| --- | --- |
| K2 | 对 L 完成本波防止/伤害，再执行第二波及尾部 |
| K3 | 选择第二波目标，随后完成防止/伤害及尾部；保留 T1 |
| K4 | 接受乙对 G 的防止选择，再完成尾部；保留累计 2 和 T1 |
| K5 | 完成已公开给甲的这次取牌，再结束 F 并处理 T1 |
| K6 | 只完成 T1 的受益者选择，然后返回游戏主流程 |

每个恢复点都同时核对：谁正在选择、哪些事实已发生、哪些事件已发布、哪些步骤尚未执行、哪些信息分别对甲乙可见。
