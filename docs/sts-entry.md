# STS 逐步交互入口

正式评审在主对话完成入口验收后按用户授权恢复，运行进度以本次评审manifest为准。入口验收与固定输入夹具不计入计划中的 104 局；首决策或单步检查通过，不代表完整 A20 碎心流程已通过验收。工程验收与评审进度以 docs/plan.md 为准。

此入口使用生产 Card Core 和 BaseGame。它不选择动作、不调用策略，也不自动开下一局。每次启动只创建一个干净会话；操作者逐次提交当前观察允许的动作。只支持 A20。

## 启动

在仓库根目录运行：

```sh
npm run sts -- play --character volibear --ascension 20 --seed 130 --output data/sts-review/volibear-001 --interface jsonl
npm run sts -- play --character ironclad --ascension 20 --seed 130 --output data/sts-review/ironclad-001 --interface terminal
```

`--output` 必须是不存在或空的目录，已有记录不会覆盖或续写。角色支持 `volibear`、`ironclad`；种子为十进制无符号 64 位整数。`--interface` 支持 `jsonl` 和 `terminal`。重复参数、缺值和未知参数均拒绝。旧 `--out`、`--mode` 分别是 `--output`、`--interface` 的别名，不能与对应正式参数重复使用。

评审模式默认开启，动作必须有非空理由。普通手动游玩可加 `--review false`，此时可以省略理由。生产详细事件始终记录。

需要纯 JSONL 标准输出时，使用 `npm run --silent sts -- play ...`，或直接运行 `node --experimental-strip-types packages/cli/src/sts.ts play ...`；普通 `npm run` 会先打印 npm 自己的命令提示。

## JSONL 协议

每行一个 JSON 对象。启动后返回 `kind: "decision"`，包含 `sessionId`、`decision`、玩家可见 `observation` 和 `presentation`。后者给出当前合法动作的 `id`、标签、说明与可见牌面规则。动作编号从 **0** 开始，每个决策重新编号。

```json
{"op":"observe"}
{"op":"act","sessionId":"从当前decision复制的ID","decision":0,"action":1,"reason":"根据当前牌组选择该项"}
{"op":"quit"}
```

`observe` 只读取当前决策，绝不推进。`act.action` 是当前 `presentation.actions[].id`，不是底层 `bits`。`sessionId` 与 `decision` 必须同时匹配；旧决策、其他会话、越界编号及缺少必需理由返回 `rejected`，保留当前状态。非法 JSON 和未知命令也拒绝，不自动改成其他动作。

标准输出中的 `observation.history` 只包含自上次输出以来的增量；`historyTotal` 为累计长度。审计文件保留完整原始观察。玩家输出只来自公开观察；不会额外暴露私有随机状态、未来奖励或隐藏抽牌顺序。

## 终端交互

终端显示当前幕、楼层、生命、金币、公开状态、规则说明和合法动作编号。输入：

```text
1 选择这一项的理由
observe
quit
```

评审模式必须输入“编号 空格 理由”；`--review false` 时可以只输入编号。终端接口与 JSONL 接口使用同一生产会话和动作校验。

## 审计文件

| 文件 | 内容 |
| --- | --- |
| `run.json` | 会话、角色、种子、A20、引擎、开始时间、Git 来源及终态 |
| `source.patch` | 指定源码范围内的已修改文件差异与未忽略新增源码的精确补丁；不采集运行数据目录 |
| `decisions.jsonl` | 完整原始观察、展示、收到的输入以及接受或拒绝结果和理由 |
| `events.jsonl` | 生产事件；`seq` 从 0 递增，附会话与当时决策编号 |
| `maps.json` | 已生成各幕的完整公开地图及连接；尚未生成的幕没有地图 |
| `summary.json` | 终态、终止原因、接受动作数、实际路线、牌组/遗物/药水变化、战斗事件索引及最后观察 |

战斗索引依据生产 `battle-start` 和 `battle-end` 事件的 battle ID 与 `seq` 构建，不通过观察差异推断战斗开始或结束。中止时正在进行的战斗可以只有开始索引。逐回合及伤害、出牌、敌人行动等原始事实以 `events.jsonl` 为准。

源码补丁覆盖 STS 源码、公共包、vendor 与根配置中的本地差异和新增 TS/JSON 源码。结合 `run.json` 中的提交及安装环境可追溯本次执行来源；它不是依赖安装包或完整仓库备份。

## 状态与故障恢复

| `summary.status` | 含义 |
| --- | --- |
| `heart-victory` | 终局且 `heartDefeated=true`，成功碎心 |
| `act3-clear` | 游戏返回胜利但未击败心脏，不计碎心成功 |
| `death` | 正常规则结算死亡 |
| `aborted` | EOF、`quit`、SIGINT 或 SIGTERM 中止，不计死亡 |
| `fault` | 装配、程序、展示、来源归档或清理故障，不计正常终局 |

程序故障会输出 `fault`，保存诊断、最后观察与已写入的输入/事件，并以非零退出状态结束；清理失败会保留原始故障信息。非空输出目录等启动参数错误直接拒绝启动。操作系统强制终止（例如 SIGKILL）无法保证最终汇总写完，应保留现有文件检查。

此入口没有恢复旧进度或重放后改选功能。评审发现疑似程序 bug 时，立即停止所有玩家，保留本次目录并报告主对话；当前未完成局丢弃，不计死亡或完成局。主对话修复并完成必要验收后，以**新输出目录重新创建干净会话**；不要向旧目录追加记录。正式玩家是否恢复由主对话统一通知。

## 当前验收边界

尼奥代价按当前资源显示精确损失及前后数值。现有生命代价先将当前生命除10取整再乘7，例如68→42；最大生命代价也按现有浮点与取整结果显示，避免用近似百分比代替实际支付。

多笔金币奖励各自提供一个带索引动作，领取后移除该笔奖励。工程参考构建除Curiosity外，也显式修正上游金币动作遗漏索引的问题；保持原生/受控/C++的有序合法动作全量比较，未用比较器去重掩盖差异。

正式详细观察中的选牌数量、是否可空选与是否可选任意张均来自当前实际选择请求，并按合法动作集合校验。历史参考形状中的旧显示计数不作为操作约束。

当前基础内容仍有源能力限制：Orrery不发卡牌奖励、Dollys Mirror不复制牌、Old Coin不发金币、Wing Boots不能跨路线、Toy Ornithopter不因药水治疗、Prismatic Shard不扩展奖励颜色池。Darkstone Periapt仅在蠕动肉块植入且无御守时加最大生命。入口如实展示这些行为；本轮修正说明没有补齐这些原版功能，最终角色评审须单列该环境限制。

验收覆盖两角色首决策、只读观察、固定单步选择、非法/过期动作拒绝、理由要求、终端数字选择、EOF/退出/信号中止、非空目录拒绝、来源故障归档，以及修正后的三条正常A20碎心动作带。完整JSONL命令另经一条正常碎心轨迹验证动作、事件序号、四幕地图和战斗索引归档。检查数字及当前完成状态只在 docs/plan.md 维护。

## 牌面说明的依据

内容说明描述固定参考与生产代码当前实际规则，不把原版游戏的惯常效果替代实现。已核对并显式注明的源行为包括：Blood Potion在战斗内外的比例不同、Impatience无攻击牌前提限制、Dark Shackles给敌人增加力量。它们不是本次入口新增效果；后续评审应把共享内容的源行为与新角色设计问题区分。角色自定义能力、领域、卡牌成长、一次性加伤/减费、重复效果及选牌候选均从生产查询公开，不由CLI猜测。
