# STS 玩家入口

新玩家使用完整 [STS TUI](sts-simulator.md)：`npm run sts:tui`。支持自动保存、保存退出、直接恢复。下文是保留的旧 JSONL/数字终端评审接口；其新局和退出限制仅约束旧入口，不适用于 TUI。搜索评审保持封存。

# STS 逐步交互入口

正式评审在主对话完成入口验收后按用户授权恢复，运行进度以本次评审manifest为准。入口验收与固定输入夹具不计入计划中的 104 局；首决策或单步检查通过，不代表完整 A20 碎心流程已通过验收。工程验收与评审进度以 docs/plan.md 为准。

此入口仅使用受控生产 Card Core 和 BaseGame。它不选择动作、不调用策略，也不自动开下一局。每次启动只创建一个干净会话；操作者逐次提交当前观察允许的动作。只支持 A20。

## 启动

在仓库根目录运行：

```sh
npm run sts -- play --character volibear --ascension 20 --seed 130 --output data/sts-review/volibear-001 --interface jsonl
npm run sts -- play --character ironclad --ascension 20 --seed 130 --output data/sts-review/ironclad-001 --interface terminal
```

`--output` 必须是不存在或空的目录，已有记录不会覆盖或续写。角色支持 `volibear`、`ironclad`；种子为十进制无符号 64 位整数。`--interface` 支持 `jsonl` 和 `terminal`。重复参数、缺值和未知参数均拒绝。旧 `--out`、`--mode` 分别是 `--output`、`--interface` 的别名，不能与对应正式参数重复使用。

评审模式默认开启，动作必须有非空理由。普通手动游玩可加 `--review false`，此时可以省略理由。生产详细事件始终记录。

需要纯 JSONL 标准输出时，使用 `npm run --silent sts -- play ...`，或直接运行 `node --experimental-strip-types examples/sts/src/cli/sts.ts play ...`，也可在示例包内运行 `npm run sts -w @bear-forge/sts -- play ...`；普通 `npm run` 会先打印 npm 自己的命令提示。

## JSONL 协议

每行一个 JSON 对象。启动后返回 `kind: "decision"`，包含 `sessionId`、`decision`、玩家可见 `observation` 和 `presentation`。后者给出当前合法动作的 `id`、标签、说明与可见牌面规则。动作编号从 **0** 开始，每个决策重新编号。

```json
{"op":"observe"}
{"op":"act","sessionId":"从当前decision复制的ID","decision":0,"action":1,"reason":"根据当前牌组选择该项"}
{"op":"quit"}
```

`observe` 只读取当前决策，绝不推进。`act.action` 是当前 `presentation.actions[].id`，不是底层 `bits`。`sessionId` 与 `decision` 必须同时匹配；旧决策、其他会话、越界编号及缺少必需理由返回 `rejected`，保留当前状态。非法 JSON 和未知命令也拒绝，不自动改成其他动作。

标准输出中的 `observation.history` 只包含自上次输出以来的增量；`historyTotal` 为累计长度。审计文件保留完整原始观察。玩家输出只来自公开观察；不会额外暴露私有随机状态、未来奖励或隐藏抽牌顺序。

## 公开规则与动作核对

- 地图的 `EVENT` 是“?”未知房间，不保证进入事件页面；实际解析可能是普通战斗、商店、宝箱或事件，遗物还可能修正结果。进入商店本身不是房间类型错误。
- 进入下一幕时，按缺失生命的75%计算治疗量（当前实现为单精度运算后四舍五入），再经过正常治疗修正。例如没有治疗修正时，29/72恢复32点到61/72。实时说明与计算来自同一幕间恢复实现，不是额外奖励。
- 敌人的状态与已排定行动不同：Lagavulin受伤唤醒会清除睡眠状态，但当前睡眠／苏醒过渡行动仍不攻击，只安排后续攻击。不要仅从状态消失推断本次会攻击；以当前公开意图为准。
- 每次提交前重新列出完整 `presentation.actions`，逐项核对 **id、动词、名称、目标索引与名称、费用**。喝药水不等于结束回合，手牌索引不等于动作id，敌人顺序也不能凭上一决策记忆。不得从底层事件选项编号猜动作id。
- Masked Bandits旧版曾把付款与战斗说明反写。修复后的文字与实际选项组合共同生成；发现旧冻结会话的文字与行为不符时继续保留现场，不重新提交动作、不覆盖旧记录。

## 终端交互

终端显示当前幕、楼层、生命、金币、公开状态、规则说明和合法动作编号。输入：

```text
1 选择这一项的理由
observe
quit
```

评审模式必须输入“编号 空格 理由”；`--review false` 时可以只输入编号。终端接口与 JSONL 接口使用同一生产会话和动作校验。

## 审计文件

| 文件 | 内容 |
| --- | --- |
| `run.json` | 会话、角色、种子、A20、引擎、开始时间、Git 来源及终态 |
| `source.patch` | 指定源码范围内的已修改文件差异与未忽略新增源码的精确补丁；不采集运行数据目录 |
| `decisions.jsonl` | 完整原始观察、展示、收到的输入以及接受或拒绝结果和理由 |
| `events.jsonl` | 生产事件；`seq` 从 0 递增，附会话与当时决策编号 |
| `maps.json` | 已生成各幕的完整公开地图及连接；尚未生成的幕没有地图 |
| `summary.json` | 终态、终止原因、接受动作数、实际路线、牌组/遗物/药水变化、战斗事件索引及最后观察 |

战斗索引依据生产 `battle-start` 和 `battle-end` 事件的 battle ID 与 `seq` 构建，不通过观察差异推断战斗开始或结束。中止时正在进行的战斗可以只有开始索引。逐回合及伤害、出牌、敌人行动等原始事实以 `events.jsonl` 为准。

源码补丁覆盖 STS 源码、公共包、vendor 与根配置中的本地差异和新增 TS/JSON 源码；游戏模块自身 `examples/sts/package.json` 与 `tsconfig.json` 也在采集范围内。补丁首部另记录本次执行所用交互入口源码路径及对应提交 blob（CLI 入口、游戏导出、交互会话、会话类型、展示层），入口源码无法取证时按来源故障归档。结合 `run.json` 中的提交及安装环境可追溯本次执行来源；它不是依赖安装包或完整仓库备份。

## 状态与故障恢复

| `summary.status` | 含义 |
| --- | --- |
| `heart-victory` | 终局且 `heartDefeated=true`，成功碎心 |
| `act3-clear` | 游戏返回胜利但未击败心脏，不计碎心成功 |
| `death` | 正常规则结算死亡 |
| `aborted` | EOF、`quit`、SIGINT 或 SIGTERM 中止，不计死亡 |
| `fault` | 装配、程序、展示、来源归档或清理故障，不计正常终局 |

程序故障会输出 `fault`，保存诊断、最后观察与已写入的输入/事件，并以非零退出状态结束；清理失败会保留原始故障信息。非空输出目录等启动参数错误直接拒绝启动。操作系统强制终止（例如 SIGKILL）无法保证最终汇总写完，应保留现有文件检查。

此入口没有恢复旧进度或重放后改选功能。评审发现疑似程序 bug 时，立即停止所有玩家，保留本次目录并报告主对话；当前未完成局丢弃，不计死亡或完成局。主对话修复并完成必要验收后，以**新输出目录重新创建干净会话**；不要向旧目录追加记录。正式玩家是否恢复由主对话统一通知。

## 当前验收边界

尼奥代价按当前资源显示精确损失及前后数值。现有生命代价先将当前生命除10取整再乘7，例如68→42；最大生命代价也按现有浮点与取整结果显示，避免用近似百分比代替实际支付。

多笔金币奖励各自提供一个带索引动作，领取后移除该笔奖励。工程参考构建除Curiosity外，也显式修正上游金币动作遗漏索引的问题；有序合法动作全量比较仅用于显式受控TS/C++差分，不用比较器去重掩盖差异。

正式详细观察中的选牌数量、是否可空选与是否可选任意张均来自当前实际选择请求，并按合法动作集合校验。历史参考形状中的旧显示计数不作为操作约束。

遗物补齐范围为星系仪的5组手动卡牌奖励、多利之镜复制选牌、古钱币300金币、羽翼之靴3次跨线、玩具扑翼飞机药水治疗、黑石护符获得诅咒加最大生命。实际验收状态见plan.md。棱镜碎片正常生成、购买和获取，仅跨色奖励效果明确禁用。对局测评保持停止。

当前入口检查保留两角色首决策、只读观察、非法/过期动作拒绝、理由要求、展示候选、终端、退出/信号、目录与来源故障等局部场景。旧完整碎心动作带、CLI整局重放和历史诊断前缀均已从执行路径移除；历史通过数字不代表清理后的版本已验收。

## 工程检查入口

在仓库根目录使用：

```sh
npm test -w @bear-forge/sts
npm run test:run -w @bear-forge/sts
STS_COMPARE_CPP=1 STS_REFERENCE_SOURCE=/absolute/path/to/sts_lightspeed npm run test:run -w @bear-forge/sts
STS_REFERENCE_SOURCE=/absolute/path/to/sts_lightspeed STS_DIFF_SEED=130 STS_DIFF_MISMATCH='填写已观察到的具体结果差异' npm run test:differential -w @bear-forge/sts
```

这些命令的当前执行结果见plan.md；显式差分仅在普通终局比较出现具体不一致后启用。默认test顺序执行受控局部规则检查与唯一整局终局检查，不需要C++源码或编译器。STS_COMPARE_CPP只接受0或1，默认关闭；设为1才运行TS/C++终局比较。仅提供源码路径不会开启C++比较；显式差分另含定向跨语言场景，必须填写种子与已观察差异，不进入默认 test/check。整局检查及可选比较共用既有测试工具，复用正式BaseGame；启用比较时两端从干净新局持续推进，当次动作各执行一次，禁止动作带、前缀或记录重放。C++只从STS_REFERENCE_SOURCE指定的本地修正版目录构建，仍校验固定提交和源码干净；路径缺失或构建失败直接报错，不静默退回TS单跑。

常规整局关闭capture与指令记录，不保存中间观察、事件或检查点；可选C++比较的中间推进只返回确认，终局才读取结果。普通死亡或胜利终局一致不等于成功碎心，决策上限不能当成完成。显式差分才检查当前边界的公开和私有状态，诊断快照立即释放，不用于重新执行。保存/恢复能力由局部Context测试覆盖。

人工入口仍按评审要求记录真实对局；它不绑定自动选牌策略、不自动开下一局。通用card:run/card:replay对STS直接拒绝，旧reference:play/reference:replay和STS性能重复整局命令已删除。玩家评测继续停止。

## 牌面说明的依据

内容说明与生产行为均须服从已确认的游戏规则。2026-10-22对照sts-re规则书发现并修复旧固定参考的错误：Blood Potion战斗内外均治疗20%（树皮40%）、Impatience仅手牌没有攻击时抽牌、Dark Shackles临时降低力量且被人工制品抵消。完整差异见[规则差异清单](sts-rule-gaps.md)。角色自定义能力、领域、卡牌成长、一次性加伤/减费、重复效果及选牌候选均从生产查询公开，不由CLI猜测。
