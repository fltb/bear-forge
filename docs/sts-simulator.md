# STS 玩家模拟器与 TUI

本轮验收对象：玩家能启动、完整游玩、保存退出并继续的 TUI。唯一原规则、共享 Program、独立 Context；不恢复已封存搜索，不替玩家决定。现有角色 ironclad / volibear，现有难度 A20。首批不实现 Web 或 Transformer 训练。

## 启动与操作

仓库根目录安装依赖后，用仓库固定的 Node 24（最低22.18）在交互终端运行：

```sh
npm install
npm run sts:tui
# 直接新开沃利贝尔局，或继续最近一局
npm run sts:tui -- --new --character volibear
npm run sts:tui -- --resume latest
# 不进入游戏，只查看存档
npm run sts:tui -- --list
# 指定新局目录与角色；目录必须不存在或为空
npm run sts:tui -- --save data/sts-saves/my-run --character ironclad
# 沃利贝尔新局（使用另一个空目录）
npm run sts:tui -- --save data/sts-saves/my-volibear-run --character volibear
# 保存退出后继续，直接装载原 Context
npm run sts:tui -- --resume data/sts-saves/my-run
```

默认进入启动菜单，列出固定用户目录 `~/.bear-forge/sts/saves` 下每局的角色、楼层、生命、决策编号、保存时间和可恢复状态；也可用 `BEAR_FORGE_STS_SAVES` 指定绝对位置。默认路径不随当前工作目录改变。菜单可继续、查看终局或新开任一角色；中断、不兼容、损坏、正在使用的存档明确显示且不能选入。`--resume latest` 只选最近可继续的未结束局，没有候选就报错。指定的 `--save` / `--resume` 路径保持原语义，继续时不能混用新局角色或种子，不自动开新局。默认种子来自系统随机源，可用 `--seed` 指定十进制 uint64。本地存档只用于可信目录，不从网上加载不可信存档。

- ↑/↓：在完整合法动作中选择；标签明确动词、目标、费用及多选组合。Enter 执行。药水「喝下」执行效果；「丢弃（不生效）」只移除药水，详情明确提示且需再次确认。
- 结束回合、丢弃药水、离开与跳过奖励再次 Enter 确认；Esc 取消确认。
- m：多选窗口切到勾选模式，↑/↓ 移动、Space 勾选、Enter 提交；只匹配原宿主已给出的合法组合，不构造新动作。Esc 返回动作列表。
- /：按名称、目标或组合筛选动作；Enter 完成输入，Esc 清空。输入期间字母不会执行动作。
- ←/→：场面、卡组与牌堆、地图、结算记录、规则说明、当前动作详情；Tab 在动作选择和内容滚动间切换。
- PgUp/PgDn：滚动内容；Home/End：当前焦点的首尾。? 查看帮助。
- s：保存；q 或 Ctrl-C：成功保存后退出。SIGTERM、SIGHUP、输入关闭和终端流错误也进入同一保存队列；当前动作或手动保存进行中时先等待完成。保存失败留在当前交互现场，可重试，不宣称成功。确需放弃当前进程时，连续两次大写 X 明确中止；未提交进展不可恢复。

至少需要 60 列 × 16 行；更小窗口显示调整提示并禁用动作。支持缩放、中文换行；内容可滚动。场面、卡组和规则页读取原展示文案。抽牌堆只显示数量，持 Frozen Eye 时沿原公开契约显示顺序。未知地图节点不是保证事件。

2026-10-28 信息布局：主屏顶部固定生命、能量、格挡和回合；左侧只列敌人生命、公开意图、非零状态、领域、全部手牌的序号、费用、牌名与可用状态，以及牌堆数量。右侧每个合法动作占一行，选中行高亮；80×24及以上的战斗主屏改用下文全宽牌效布局，其他页面保留侧栏预览，移动选择时预览位置不跳动。费用与意图数值仍来自原公开规则结果，不在界面另算。攻击意图数值为格挡与伤害减免前；隐藏意图仍显示隐藏。

主屏使用紧凑手牌列表，不铺开牌面全文、遗物全文和结算日志。普通状态零值省略，负力量等非零状态仍保留；沃利贝尔雷势保留零值便于观察积累。「牌堆」提供全部可见卡牌的原文、类型、升级、费用和标记；「规则」提供当前状态全文、遗物记录与药水槽位；「记录」保留完整已收集结算。

「详情」提供当前选项全文、界面消息、全部合法选项、商店／奖励的全部公开物品、价格、金币不足与售罄标记。长操作列表以省略号提示截断，预览放不下时明确提示进入详情页；完整正文可通过 PgUp/PgDn 或 Tab 后方向键滚动，Home/End 到首尾。多选模式下预览跟随当前候选；不会因商品买不起而隐藏其说明。地图页显示完整公开路线及本幕 Boss。

## 会话与策略边界

`examples/sts/src/simulator.ts` 提供 `createSimulator({store, setup})` 和 `resume:true`。每进程共享加载后的 Program，每局独立 Context。`observe / act / save / close` 串行；`decide(policy, signal)` 在串行队列外等待建议，再按原 revision 提交。HumanPolicy 只等待 UI 选择，返回现有 Policy Proposal，不调用执行器。未来模型可以直接替换策略。

普通对局不维护旧搜索的隐藏牌序概率分布，真实洗牌、抽牌、塞牌和触发结算仍由原内核执行。普通 Context 直接交给旧概率搜索时，如果后继需要未知牌序，明确报告概率不可用，不读取真实隐藏未来作为替代。后续 Transformer 通过公开观察与合法动作接入，不需要这份分布；旧搜索仍处于封存状态。

动作命令包含 `id / sessionId / revision / action`。外部入口验证当前请求和合法候选；原游戏宿主仍负责接受和执行。一次执行到下一请求或真实终局，包括效果中的选牌。已接受 Policy 的 nextMemory/nextRandom 随 Context 提交并在恢复后续接；未接受建议不改变它们。最后一次命令及结果记录随存档提交：相同命令重试返回已有结果，旧 revision 拒绝，相同 id 不同内容拒绝。界面不把非法输入转换成其他动作。终局分 death / act3-clear / heart-victory；用户保存退出不算死亡或通关，执行故障和未提交中断也不算终局。

## 存档与中断

每个保存目录：`current.sts` 是一个原子提交的完整 Context 和会话包，`pending.json` 是执行前持久化的目标 revision，`owner.lock` 保证本机单会话使用；崩溃锁回收留下 `.retired-*` 代次标记，避免并发恢复误删新锁。临时文件先写入并同步，原子替换后同步目录。不要将同一目录放在多主机共享文件系统并发使用。

每次真实动作前先同步 pending，再执行原规则，抵达下一稳定边界后同步当前 Context、请求、最近命令结果、事件批次和游标。仅提交成功后显示已保存；失败时停止新动作，但保留内存当前现场供重试保存。成功重试不再执行动作。自动存档覆盖的是本会话自己的当前状态，新会话拒绝非空目录。

进程在动作执行中或提交前消失，pending 高于已提交 revision：恢复报告 interrupted，拒绝旧存档补跑。成功提交后即使 pending 文件仍在，其 revision 不高于存档，允许直接恢复。进程死在稳定且已提交边界可继续；无历史动作重放。锁的旧 PID 不存在时才尝试回收；无法识别的锁如实报错，不擅自覆盖。

故障或明确中止后，退出提示只给出现场目录，不承诺该局可继续。已保存的死亡/胜利终局可以用兼容的最新版 `--resume` 查看，合法动作为空，不能复活或重新执行。即使修复了故障，也不会因此允许旧 pending 未提交的局从检查点补跑。终端断开后若保存失败，进程以失败状态结束并输出现场路径，不宣称成功；SIGKILL、断电不能执行退出处理，仍以最后成功提交及 pending 标记判断是否可以继续。

存档可能包含私有游戏未来，因此只能由可信宿主持有，不作为前端或模型输入。公开视图、原规则事件只通过会话接口输出。

## 存档兼容与迁移（2026-10-29起）

新存档外壳 `format:2` 记录 `contextVersion`、创建时间和最近保存时间。源码 program SHA-256继续用于日志追溯，不作为新版恢复的逐字节门槛；Node主版本也不再作为单独拒绝条件，底层V8仍必须能解码该文件，推荐固定Node24。所有恢复直接装载完整Context，沿最新版唯一生产执行器继续。

`simulator-save.ts` 是现场兼容与迁移的唯一入口。当前现场版本1是本次重置后的起点。界面、文案以及保持组件、实体、程序块、局部变量布局和语义不变的平衡数值调整可保持版本；任何影响这些位置或含义的变更必须提升版本，并在此入口添加显式Context转换及跨进程恢复回归。不能靠保持版本号不变把任意改动宣称为兼容，也不能仅移动公开血量/卡组来替代完整现场迁移。未知现场版本明确拒绝、保留文件；没有自动回退或重开。

旧外壳 `format:1` 仅在源码身份完全一致时可无损迁移到新外壳，并在接受新动作前原子提交；其他历史版本不猜测转换。本轮用户决定作废现有旧局，原存档整体移到仓库 `data/sts-saves-retired-2026-10-29`，不进入新默认列表，也不恢复执行；新局从最新规则开始。新格式的兼容需要后续结构变更维护对应迁移，不能承诺尚未编写的任意未来迁移。

## 公开事件与未来 Web

每个批次含 `fromRevision / revision / actionId / cursor / events / identities / state`。事件携带单调 sequence 和动作归属；实体在首次公开时分配不含原分配位置的稳定展示 id，卡牌公开 uniqueId 和敌人公开槽位用于定位；映射随 Context 存档续接。规则事件补充关联信息不改变结算。

Web 可从上个展示状态顺序播放当前批次，再采用最终 `state`。伤害事件用于表现，资源变化和最终状态用于状态同步，不可重复扣血。跳过动画直接采用最终状态。断线后调用 observe 获取最新状态与最新批次，用 sessionId/revision/cursor 去重；更早批次不在内存无限积累，过期客户端直接同步最终状态。展示记录只读，绝不驱动内核重执行。

退出时打印动作推进、存档和绘制的样本数量、中位数及最大耗时。启动/恢复计时包含加载与持久化相关工作；动作计时不含玩家思考和存档，绘制计时含构造文本和写入终端流，不等同终端像素呈现延迟。执行不等待动画，不设自动对局一分钟上限。

2026-10-26 性能修复：已从普通执行中移除反复塞牌/消耗时急剧膨胀的概率语言维护。修复后新建压力夹具 1264 次动作最大约 178 ms；没有重放原 64 秒慢动作，该样本也不构成所有操作的响应上界。出现“正在执行或保存”时不要连续输入或另开同一存档。两个角色此前的完整人工实玩均到达第三幕死亡，完整结果、具体失误、版本和测量范围保留在 `plan.md`。界面文字完整但部分卡牌/敌人仍用英文名称或标识，复杂规则说明较长，需要翻页查看。


## 运行 JSONL trace（2026-10-26）

TUI 默认在存档目录创建新的 `trace-<时间>.jsonl`，`--trace /绝对路径/new.jsonl` 指定新文件，`--trace off` 关闭。文件使用独占创建（已存在就报告失败，不覆盖），权限0600；观察器不改 `current.sts` 或 `pending.json` 及写入顺序。继续同局时创建新日志段，通过 sessionId/revision/cursor 关联，不重新输出旧批次或执行历史。存档兼容遵守上方现场版本与迁移规则；日志不参与迁移，也不重放真实存档。

SDK 可传 `createSimulator({store,setup,trace})`；`openJsonlTrace(path)` 提供文件 sink。SDK 缺省无日志。`session.traceStatus()` 返回启用/错误/成功记录数/累计观测耗时。`traceText(record)` 将同一 JSONL 记录转成可读缩进文本；不需要加载游戏。

每行含单调 traceSequence、recordedAt；原事件另保留连续 sequence、actionId、稳定实体 id、battle 关联：

- header：格式、源码 program SHA-256、Node 版本、sessionId、新局 setup（含 seed/character）及字段可用性说明。旧存档恢复时 setup=null，不能拿默认seed冒充原局seed；须与原日志header关联。
- command：动作bits及纯展示解释、目标/卡牌/选牌、动作前完整公开状态及合法候选（手牌uniqueId/升级/本回合费用/实际支付预览、能量/HP/block、敌人意图、牌堆数量及公开弃牌/消耗牌、力量等状态、蓄雷/领域/成长）。观察中的重复动作历史前缀省略，已由逐条command表达。
- event：原展示事件逐条落盘，覆盖抽/弃/消耗、出牌、资源变化、伤害requested/blocked/blockSpent/unblocked/lost、敌人行动及回合/战斗边界。所有数值来自原事件，不重新结算。
- boundary：动作后公开状态、下一选择或真实终局、实体映射、cursor。动作内的选牌同样是独立决策边界。
- commit：原自动存档成功后记录revision/cursor、已有Context字节数和SHA-256；不额外save或解码RNG。fault/save-error分别表示原执行故障或原存档失败；日志绝不把未提交动作当已提交。

日志只能保存原来可观察的事实。隐藏抽牌顺序/RNG不公开；Context摘要用于确认同一保存字节，不等于公开RNG值。伤害source/target和actionId是确定关联；原block-gain事件没有能力来源，嵌套能力精确因果链、领域本可阻止但未发生的效果/伤害量均明确不可得，不能从邻接事件猜成事实。领域收益可分析实际状态、清除/补抽和前后差异，不提供编造的反事实收益。旧日志缺失部分无法追补。

观察器只消费既有batch/command及原persist已产生的Context字节；不调用游戏query、getters、RNG、advance或额外save。所有给sink的数据先复制，sink无法修改游戏状态。写入/序列化/关闭异常被隔离，首次失败停写；TUI提示缺口且继续原游戏/存档。文件每条await追加，正常关闭fsync；没有每事件fsync。崩溃可丢尾部/留下半行，读者丢弃不完整末行并检测sequence/commit缺口，不回放修补。磁盘延迟会增加墙钟耗时，traceStatus单列观测耗时；无异步无限队列、不把积压留在内存。坏盘/挂起I/O仍可能延迟UI，不承诺无墙钟开销。

验收用全新临时目录的成对局，从相同seed执行相同明确动作，每个边界比较完整已保存Context（只归一化独立宿主call UUID），包含RNG、隐藏牌序与继续执行状态，并比较公开事件和真实终局。另验证失败隔离、sink修改隔离、去重、日志连续性、旧终局直接恢复、文件拒绝覆盖。真实用户存档不参加执行测试。
